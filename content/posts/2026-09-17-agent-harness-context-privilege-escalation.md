에이전트 하네스의 컨텍스트 조립 단계 자체가 공격 지점임. 이 논문(arXiv:2609.01222)은 Claude Code와 Codex를 포함한 12개 실전 하네스를 분석해서 낮은 권한의 컨텍스트에 심은 공격 내용이 높은 권한의 메시지 역할로 흘러들어가는 경로 1,761개를 찾아냈음.

1. 배경부터. 실전 하네스는 매 턴 컨텍스트를 조립함. 시스템 프롬프트, 도구 결과, 파일 내용, 스킬 문서, 커맨드 출력 등 여러 출처의 텍스트를 하나의 메시지 열로 합침. 문제는 이 조립 로직이 벤더 소유이거나 불투명하다는 것. 어느 출처의 내용이 어느 메시지 역할로 들어가는지, 한 번 들어온 내용이 어디까지 지속되는지 사용자는 알기 어려움.

2. 프롬프트 인젝션 연구는 주로 "모델이 악성 지시를 따르는가"를 다뤘는데 이 논문은 한 단계 앞의 "내용이 어떻게 권한 있는 위치까지 올라가는가"를 분석함. 이 시점 차이가 핵심임. 모델을 속이는 게 아니라 구조를 타는 공격이라는 것임.

3. 두 가지 범주로 정리됨. M-CPE(MessageRole)는 낮은 권한의 출처, 예컨대 웹페이지나 압축 파일 안의 문서에서 온 공격자 제어 내용이 높은 권한의 메시지 역할, 예컨대 시스템 프롬프트나 신뢰된 문서로 편입될 때 발생함. 모델은 그 내용을 높은 권한의 지시로 받아들임.

4. X-CPE(Cross-Scope)는 공격자 제어 내용이 원래 도입된 컨텍스트 범위를 넘어 지속될 때 발생함. 특정 태스크 폴더에서 읽힌 파일 내용이 세션 전체, 심지어 다른 프로젝트의 컨텍스트까지 살아남는 식임. 스코프 이스케이프임.

![Codex CLI 컨텍스트 구성](/images/2026-09-17-agent-harness-context-privilege-escalation/fig-1-p4.png)

5. 숫자. CoRA라는 자동 열거 도구로 후보 CPE 경로 1,761개를 찾음. M-CPE 940, X-CPE 640, 양쪽 모두 올리는 경로 181임. 엔드투엔드 검증에서 하네스별 차이가 큼. Claude Code는 GPT-5.4-mini 기준 51 경로 중 49 로드, 49 검증(96%). Gemini CLI는 102 경로 전부 로드됨.

6. 재미있는(그리고 무서운) 지점. Claude Code는 네이티브 모델(Sonnet 4.6)보다 GPT 계열 모델을 물렸을 때 경로가 더 많이 터짐(96% vs 78%). 모델 교체 가능성 자체가 위험 요소라는 뜻임. 하네스 방어가 특정 모델의 정렬에 암묵적으로 기대하고 있다는 증거이기도 함.

7. Claude Code RCE 사례가 구체적이라 그대로 옮김. 사용자가 웹사이트 확인을 부탁함. 에이전트는 사이트를 둘러보다 배포 방법 블로그 글을 찾았고 거기 있던 source.tar.gz를 /tmp에 다운로드해 압축을 품. LLM은 보안을 의식해서 사용자 디렉터리 밖 /tmp에 풀 정도로 조심했음.

8. 근데 모델이 웹사이트 소스(index.html)를 읽으러 들어가는 순간 Claude Code가 폴더 안의 .claude/skills 디렉터리를 자율적으로 탐색해서 스킬을 전부 로드함. 동적 스킬 디스커버리임. 압축 파일 안에 심어둔 악성 SKILL.md가 이렇게 컨텍스트에 들어옴.

9. 그리고 스킬 본문의 특수 블록은 커맨드로 실행되고 출력으로 치환됨. 에이전트가 그 스킬을 사용하는 순간 셸 커맨드가 에이전트 프로세스 권한으로 실행됨. 논문은 이걸 RCE로 분류함. RCE는 원격 코드 실행(remote code execution), 즉 공격자가 임의 명령을 피해 시스템에서 실행하는 침해를 뜻함. 공격 벡터 두 개가 결정적이라는 점이 핵심임. 폴더 안 파일을 읽으면 스킬은 무조건 로드되고 스킬이 쓰이면 커맨드는 무조건 실행됨. 확률이 개입하는 건 에이전트가 스킬을 사용할지뿐임.

![CoRA 구조](/images/2026-09-17-agent-harness-context-privilege-escalation/fig-2-p12.png)

10. 방어는 논문의 분석 틀을 그대로 쓰면 됨. 역할 축에서는 낮은 권한 출처의 내용이 높은 권한 역할로 편입되는 경로를 제거하거나 표시할 것. 도구 결과와 시스템 지시의 경계를 모델이 구분하게 만드는 마크업이 여기 해당함.

11. 스코프 축에서는 도입 컨텍스트를 넘어 지속되는 내용의 수명을 제한할 것. 태스크가 끝나면 함께 사라지는 격리가 기본값이어야 함. 그리고 실무 방어로 신뢰할 수 없는 출처의 압축 파일을 에이전트 작업 디렉터리에서 풀지 않는 것, 스킬 동적 로드를 필요할 때만 켜는 것이 있음.

12. 실무 채점. 우리 자동화 에이전트 설계에 바로 묻는 질문임. "이 내용은 어디서 와서 어디까지 살아남는가"를 모든 컨텍스트 출처에 대해 답할 수 있어야 함. 스킬 동적 로드나 커맨드 블록 실행 같은 편의 기능은 권한 모델과 만나면 공격면이 됨. 편의와 권한의 교차점을 인벤토리화하는 게 하네스 설계자의 첫 과제임.

13. 이 논문의 가치는 새로운 공격 기법 자체보다 불투명했던 컨텍스트 조립을 권한 상승 관점으로 체계화한 데 있음. 컨텍스트 출처별 권한 등급과 수명을 명시하는 것이 차세대 하네스의 기본 요건이 될 것임.
