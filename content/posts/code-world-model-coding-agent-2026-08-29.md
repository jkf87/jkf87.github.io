세상에 상호작용하는 게임 월드를 통째로 생성하는 모델들이 쏟아지는데 다들 비슷한 벽에 부딪힘. 화면은 그럴듯한데 세계의 규칙이 안 지켜진다는 것. [Code World Model](https://arxiv.org/abs/2608.25927)은 이 문제에 색다른 답을 냄. 세계의 진화는 코딩 에이전트가 코드로 관리하고 화면 구현은 비디오 모델이 맡는 것. 논문은 이 코딩 에이전트를 "월드 브레인"이라 부름. 규칙과 렌더링의 분리라는 관점이 에이전트 설계 일반에도 적용돼서 정리함.

1. 배경. 비디오 월드 모델은 화면만 보고 배우니까 결과는 알지만 규칙을 모름. 플레이어가 도시 통치자를 암살하면 질서와 파벌 동맹과 NPC 행동이 모두 바뀌어야 하는데 이런 건 화면 데이터에 제대로 남지 않음. 심지어 플레이어가 없는 화면 밖에서 벌어지는 일은 시각 기록 자체가 없음. 상태가 코드에 있으면 이 둘이 다 해결됨. 규칙은 코드가 직접 다루고 화면 밖 상태도 전파됨.

![파이프라인](/images/code-world-model-coding-agent-2026-08-29/fig2-pipeline.png)

2. 역할 분리가 설계의 핵심임. 코딩 에이전트는 드물지만 복잡한 결정만 함. 새 사건 해석, 장기 결과 추론, 세계 작동 방식 수정 같은 것. 반복적인 실행(위치, 속성, 쿨다운, 충돌)은 코드에 맡김. 비디오 모델은 오직 외관과 미세 동작만 책임짐. 앞서 정리한 NOOA의 원칙, 정확한 계산은 결정적 코드로, 의미 판단은 모델로, 그리고 ORCH의 병렬은 놓두고 순서만 계층으로, 같은 철학의 또 다른 등장임. 판단과 실행을 분리하면 둘 다 단순해진다는 것.

3. 프록시라는 인터페이스가 재치있음. 갱신된 상태를 비디오 모델에 텍스트로 전달하면 안 되더라고 하는 것. 아무리 긴 텍스트와 전용 카메라 조건을 줘도 카메라 궤적과 개체 움직임이 정밀하게 제어되지 않았음. 그래서 프레임 단위 공간·시간 제약을 아예 이미지 좌표로 직접 표현하는 조건을 만듦. "텍스트 프롬프트의 시각적 대응물"이라는 표현이 정확하고, 해상도가 타깃의 1/4이라 토큰 부담도 1/16 수준임. 자연어가 안 되는 제어는 제어에 맞는 표현으로 바꾸라는 교훈임.

4. 데이터 구성도 실용적임. 게임 데이터는 런타임 주석을 코드가 읽어서 픽셀 단위 프록시 주석을 자동 생성함. 실영상은 캘리브레이션된 3D 재구성으로 오프라인 컴파일하는데 액션 라벨이 필요 없어서 주석 비용이 확 줄어듦. 그 결과가 인상적인데 GTA V 게임플레이 5시간만으로 MiniMax-H3를 파인튜닝했는데도 전혀 다른 캐릭터, 환경, 모션, 카메라 궤적으로 강하게 일반화됨. 60초마다 스타일이 바뀌는 장기 생성도 세계 상태가 코드로 유지되니 가능해짐. 명시적 3D 생성 루트의 에셋 커버리지 천장과 달리 비디오 모델의 사전지식이 커질수록 같이 스케일업되는 구조라는 게 저자들의 주장임.

![쌍 데이터 구성](/images/code-world-model-coding-agent-2026-08-29/fig3-paired-data.png)

5. 내 해석과 한계. 평가가 정성 중심이라는 건 기억해야 하고 코딩 에이전트가 임의의 복잡한 세계를 처음부터 구축하는 건 논문 스스로 "기대"라고 쓴 부분임. 오픈엔디드 세계는 아직 데모 단계임. 그래도 가져갈 원칙은 명확함. 규칙과 표현을 분리할 것, 텍스트로 안 되는 제어는 좌표 기반 표현으로 바꿀 것, 자동 주석 파이프라인을 먼저 설계할 것. 내 업무 자동화에서도 "상태를 코드로 유지하고 렌더링은 맨 마지막에"라는 구조는 그대로 적용되는 패턴임.
