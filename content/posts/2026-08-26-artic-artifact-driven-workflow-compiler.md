도메인 전문가가 절차를 자연어로 쓰면 에이전트가 실행하는 구조가 확산 중인데, 소프트웨어가 기대하는 두 속성이 성립 안 함. 환경 간 재사용 가능한 예측 가능성과 프로그램 지시에 대한 정확한 이행. Purdue의 [Artic](https://arxiv.org/abs/2608.21341)은 자연어 워크플로를 컴파일해서 이걸 해결했고 원문 텍스트 대비 평균 28%p 해결률 향상을 냈음. 자연어 지시서를 그대로 돌리는 내 자동화와 직결된 문제라 정리함.

1. 원인 진단이 정확함. 첫째, 암묵적 데이터 의존성. 각 스텝이 과거 컨텍스트의 모든 중간 결과에 접근 가능한데, 이건 중간 결과를 전역 변수에 저장하는 프로그램과 같음. 실행 에이전트는 매 스텝 관련 결과를 식별해야 하고 노이즈가 있으면 오류가 남. 둘째, 이행 부담 증가. 컨트롤 플로우가 복잡하고 중간 결과가 많으면 스텝 누락, 잘못된 제어 이전, 컨텍스트 컴팩션(길어진 히스토리를 요약·축약하는 처리) 중 정보 유실이 발생함. 실제 실패 사례로 환자 리퍼럴 워크플로에서 필요한 이용 이력 대신 만성질환 리퍼럴 메시지를 근거로 삼은 경우와 "high risk OR recent acute utilization" 조건을 AND로 해석한 경우가 나옴. 내가 겪는 지시서 이행 실패와 같은 패턴임.

![실패 모드 예시](/images/2026-08-26-artic-artifact-driven-workflow-compiler/fig-1-p3.png)

2. 해법은 자연어 워크플로를 아티팩트 중심 워크플로로 변환하는 컴파일러임. 각 스텝이 읽기/쓰기 아티팩트, 산출 아티팩트에 대한 제약, 명시적 제어 이전 조건을 선언함. 스텝 내부의 로컬 동작은 자연어 지시로 유지되어 에이전트가 수행함. 즉 데이터 의존성과 제어 이전만 명시적·검사 가능해지고 사람이 쓰는 부분은 그대로 남는 것. 이 표현은 부담을 분석 가능하게 만들어서 다수 아티팩트에 의존하는 스텝은 컨텍스트 압박 지표로, 중첩 분기는 제어 복잡도 지표로 식별됨.

3. 컴파일 파이프라인은 두 단계임. 제약 최적화에서 LLM이 초안을 작성하고 프로그램 분석이 문제 구간을 보고함. 충실성 검증에서 정적 검증, 전역 충실성 주장을 지역 의무로 분해하는 귀납 검증, 원본과 컴파일본의 실행 트레이스를 비교하는 드라이런 시뮬레이션을 돌리고 실패 시 진단을 최적화 단계로 환류함. 검증 없는 컴파일러 변형은 전체 시스템 대비 16%p 저하됨. 컴파일도 게이트가 필요하다는 것. 앞서 본 원칙의 재등장임.

![컴파일 구조](/images/2026-08-26-artic-artifact-driven-workflow-compiler/fig-3-p4.png)

4. 결과. SOP-Bench 기반 11개 실제 도메인 워크플로, 488개 문제 인스턴스에서 원문 텍스트 직접 실행 대비 평균 28%p 향상. 모든 실행기 모델에서 최고 평균을 냄. 일관성 개선이 더 인상적인데 실행기 모델 교차 일관성 +32%p, 반복 실행 일관성 +56%p. k=10 반복에서 텍스트는 16%p 하락하는데 컴파일본은 유지됨. 환경 교란(일시 오류, 컨텍스트 컴팩션) 하에서도 컴파일본은 100% 유지, 텍스트는 80%. 그리고 에이전트당 입력 토큰 63%, 출력 토큰 50% 감소. 명시적 의존성이 검색 부담을 없애서 비용까지 줄어드는 것.

5. 비용 구조가 좋음. 컴파일은 워크플로당 1회 오프라인 비용. 중위 컴파일 시간 5분 미만, 평균 비용 $3 미만. 매 실행마다 불안정성을 감수하는 것과 한 번 컴파일하고 안정적으로 도는 것의 트레이드오프가 명확함. 어블레이션에서는 드라이런 피드백, 귀납 검증, 최적화가 각각 8~32%p 기여했고 부담 스텝 식별·분해인 최적화 기여가 최대였음.

6. 논의도 정직함. KYB(기업 신원 확인, Know Your Business) 도메인의 오타/조작 판별처럼 모델 판단력에 의존하는 문제는 워크플로 강제로 해결되지 않는다고 명시함. 워크플로 컴파일은 절차 이행의 문제를 풀지 판단력의 문제를 풀지 않는다는 것. 경계가 명확해서 오히려 신뢰가 감.

7. 내 적용은 이렇게임. 자연어로 쓴 자동화 지시서를 그대로 두지 말고 각 스텝의 입력 아티팩트, 출력 아티팩트, 다음 스텝으로 넘어갈 조건을 명시한 형태로 한 번 컴파일하는 것. 사람이 읽는 지시서와 에이전트가 실행하는 지시서를 분리하는 것. LLM으로 초안을 만들고 원본과 컴파일본의 실행 결과를 비교하는 드라이런까지 돌리면 검증도 붙음. 5분, 3달러짜리 작업으로 실행기가 바뀌어도 흔들리지 않는 지시서가 생긴다는 게 이 논문의 실무적 매력임.
