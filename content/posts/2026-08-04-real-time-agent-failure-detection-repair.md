에이전트는 실행 중간에 망가짐. 도구 오류가 연쇄되고 같은 행동을 반복하다 루프에 빠지고 목표에서 이탈함. 표준 해법인 "매 스텝 두 번째 LLM으로 판단"은 감시 비용이 본체보다 큼. 원문은 [arXiv:2608.02464](https://arxiv.org/abs/2608.02464).

1. 제안은 정상 실행 데이터만으로 학습한 스텝당 200마이크로초짜리 감시기임.

![](/images/2026-08-04-real-time-agent-failure-detection-repair/gifs/smoke-detector.gif) 2,823개 실제 에피소드로 검증했고 모델은 qwen2.5 7b/3b, llama3.1 8b, gemini-2.5-flash 다섯 종, 프레임워크도 bespoke·LangGraph·AutoGen 세 개를 씀.

![정상 궤적 대비 이상 감지 개요](/images/2026-08-04-real-time-agent-failure-detection-repair/fig-1-p6.png)

2. 숫자부터. 행동 모니터(ESN-CUSUM. ESN인 에코 스테이트 네트워크는 고정된 랜덤 순환망을 통과한 상태 특징만으로 출력을 학습하는 저비용 순환 신경망이고, CUSUM은 관측값의 작은 이상 징후를 누적해서 임계를 넘으면 알람 주는 고전 통계 기법임)가 실패의 71%를 오탐 5% 예산에서 탐지함(AUROC 0.872. AUROC는 정상과 실패 케이스를 점수로 분리하는 능력을 재는 지표로 0.5는 무작위, 1은 완벽함). 결정론적 검증은 실패의 60%를 오탐 0%로 잡음. 수리(롤백+재실행)는 실패한 실행의 45%를 회수해서 작업 성공률을 52%에서 73%로 올림. 추가 모델 호출 약 1회 비용임.

![](/images/2026-08-04-real-time-agent-failure-detection-repair/gifs/vhs-rewind.gif)

3. 감시기 입력은 세 관측 신호임. 의미 임베딩(char-3-gram 해시라 모델 다운로드 불필요), 토큰 불확실성(logprob 기반), 액션 메타데이터(도구 타입·지연·에러 여부). 이걸 echo-state network에 먹이는데 고정 랜덤 순환 맵 + 폐형 최소제곱이라 학습이 1.7초면 끝남. 같은 데이터로 GRU(게이트를 써서 장기 의존을 다루는 표준 순환 신경망)를 학습하면 68초임.

![감시기 입력 구성](/images/2026-08-04-real-time-agent-failure-detection-repair/fig-3-p7.png)

4. 작은 변화 누적은 CUSUM이라는 고전 기법으로 잡음. 채널별로 따로 누적하고 가장 반응이 큰 채널 알람을 쓰는 구조임. 재밌는 건 핵심 기여가 ESN이 아니라 "채널별 max 융합 래퍼"라는 것임. 같은 래퍼를 GRU에 씌워도 탐지율 0.76까지 감. ESN을 쓰는 이유는 오탐이 더 낮고(0.069 vs 0.113) 학습이 100배 빠라서임.

5. 오탐 0인 계층이 따로 있음. 결정론적 검증임. 에이전트가 "총 42달러"라고 했으면 도구 결과에서 실제 숫자를 찾아 더해보고, 필수 도구 호출 누락을 확인하고, 도구 결과가 해당 도구가 반환할 수 있는 형태인지 검사함. 정상 에피소드 1,825개 중 단 하나도 오탐 없이, 모델족을 바꿔도 재보정 없이 작동함.

![오탐 0 계층적 감시](/images/2026-08-04-real-time-agent-failure-detection-repair/fig-4-p8.png)

6. 수리 방식의 발견이 실무적으로 제일 좋음. 실패 판정 시 롤백해서 다시 돌리는데, 정답을 직접 알려주는 것보다 "어느 검증이 실패했는지" 이름만 알려주는 게 더 효과적이었음(회수율 45% vs 36%). 정답을 주지 말고 스스로 다시 계산하게 두는 게 잘 작동한다는 것임. 내 재시도 프롬프트 설계에서 "정답 힌트"를 빼고 "실패한 검증 항목"만 명시하는 식으로 바꿨음.

![수리 방식 비교](/images/2026-08-04-real-time-agent-failure-detection-repair/fig-5-p10.png)

7. 솔직한 한계 보고가 가치 있음. 콘텐츠 오염(결과 텍스트가 안 바뀌는 경우)에서는 탐지율이 0%에 가깝고, 주입이 아닌 자발적 환각에는 거의 무작위 수준(AUROC 0.31-0.42)임. 다른 모델로 옮기면 재보정 없이는 50/50임. 그래서 결정론적 검증 계층이 필요한 것임.

8. 내 배포 구조에 그대로 적용함. 첫째, 비용 거의 0이고 오탐 없는 결정론적 검증(숫자 합계 검산, 필수 도구 호출 체크, 결과 형식 검사)을 기본으로 깔음. 둘째, 그 위에 가벼운 행동 모니터를 얹음. 셋째, 제일 비싼 LLM 판단자는 앞 두 계층이 못 잡는 것만 에스컬레이션함. 감시 LLM을 전 단계에 두는 구조는 비용 구조부터 틀렸다는 게 이 논문의 결론이자 내 체감임.

9. 문제제기. ESN 재보정 문제는 남아있고, 환각 탐지는 사실상 못 한다고 봐야 함. 그리고 결정론적 검증은 "검증 규칙을 미리 쓸 수 있는 도메인"에서만 강함. 규칙을 못 쓰는 창의적 작업에는 그대로 안 옮겨짐.

10. 결론. 감시는 계층으로 쌓고 비싼 판단은 최상위에만 둬야 함. 코드와 2,823개 트레이스, 데모 영상이 전부 공개돼 있어서([GitHub](https://github.com/sunnydubey1111/agent-trajectory-sentinel)) 바로 벤치마크해볼 수 있음.
