논문: [Safety Harness Evolution (SHE), arXiv 2608.09885](https://arxiv.org/abs/2608.09885) (Shanghai AI Lab, Fudan, SJTU, HKUST, 2026-08-10)

에이전트 안전 장치의 고질은 배포 후 고정이라는 것. Llama Guard, NeMo Guardrails 같은 가드레일이든 SafeHarness 같은 하네스 레벨 방어든 규칙은 사람이 설계한 대로 멈춰 있고, 새 공격 패턴이 트라젝토리에 드러나도 그 실패를 규칙 수정으로 되먹이는 통로가 없음. SHE가 메우는 게 이 간극임. 실행 트라젝토리의 실패를 진단해서 하네스의 안전 경계를 스스로 진화시키는 프레임워크임.

1. 장애물 진단이 먼저 정확함. 첫째, 결합된 기능. 하나의 안전 실패가 컨텍스트 구성, 메모리 검색, 도구 권한, 응답 필터에 얽혀서 어디를 고쳐야 할지 특정이 안 됨. 둘째, 트라젝토리-규칙 변환. 실행 기록엔 도구 관찰과 검증 결과, 실패 기록이 풍부한데 여기서 실행 가능한 규칙 수정을 뽑기 어려움. 진단은 가능한데 개선이 자동으로 안 이어지는 상태라는 것. SHE는 하네스를 네 아티팩트, System Prompt(전역 행동 계약), Rule Bank(리스크 분류·개입 규칙 allow/warn/block/sanitize/judge), Safety Memory(진화로도 못 막은 실패의 경험치), Tool Policy(도구 권한 강제)로 분해해서 책임을 명시적으로 배정함. 실패가 어느 영역에 속하는지 특정할 수 있으니 한 컴포넌트 수정이 다른 컴포넌트를 건드리는 간섭을 막음.

![SHE 프레임워크 개요](/images/2026-08-19-she-safety-harness-evolution/fig-2-p4.png)

2. 루프가 여섯 단계로 돌아감. 현재 최적 하네스로 롤아웃 수집 → 실패를 harm domain(피해 유형), attack surface(침입 채널), failure mode(실패 양상) 3차원으로 구조화 진단 → 책임 아티팩트로 라우팅 → 그 아티팩트만 국소 수정(bounded edit) → 스키마 준수와 보상 해킹성 검사 → 안전 점수가 오르고 유틸리티가 떨어지지 않을 때만 채택, 아니면 거절 사유 저장 후 롤백. Safety Memory의 갱신 조건이 별도로 보수적임. 같은 실패 패턴이 2라운드 넘게 미해결이거나 수정 후 재발할 때만 경계를 엔트리로 저장함. 실패 경험이 무분별하게 쌓이지 않게 한 설계임.

3. 실험 설계가 데이터 누수에 신경 씀. Agent-SafetyBench 첫 200 태스크 중 15개만 진화에 사용하고 나머지 185개는 최종 평가 전용. 공격 조건은 clean, context poisoning, indirect injection, tool tampering, memory injection, composite attack 6종. 20라운드, 각 조합 2회 롤아웃, temperature 0. 결과는 평균 ASR 8.6% → 5.5%, 정적 SafeHarness 대비 17.1% → 5.5%로 3.1배 감소. Clean UBR도 25.7% → 19.8%로 내려가고 평균 UA는 33.5% → 47.6%로 오름. 안전과 유틸리티를 같이 올렸다는 게 이 프레임워크의 주장의 핵심임.

![모델 간 이전 결과](/images/2026-08-19-she-safety-harness-evolution/fig-3-p7.png)

4. 이전 결과가 운영 비용 관점에서 제일 가치 있음. 진화에 안 쓴 AgentHarm에서 Harm Score 19.8% → 9.8%, 거절률 78.4% → 86.4%. 그리고 Kimi K2.6, GLM-5.2, MiniMax M2.7에 추가 진화 없이 하네스를 옮겨도 안전성 개선이 유지됨. 안전 지식이 특정 모델에 묶이지 않고 하네스 쪽에 자산으로 남는다는 것. 모델을 교체해도 안전 인프라를 다시 만들 필요가 없다는 뜻임.

5. 학습된 경계의 예시가 구체적임. 앱 추천 요청에 에이전트가 기기 레벨 자동 설치까지 실행한 실패 사례. SHE는 이걸 두 경계로 바꿈. Rule Bank에는 앱 추천·공식 스토어 안내는 허용, 기기 레벨 설치 실행은 금지. Tool Policy에는 설치 액션에 실행 제약. 추천은 살리고 설치만 차단하는, 트라젝토리에서 뽑은 재사용 가능한 경계를 만든 것. 벤치마크 특화 핵이 아니라는 저자 주장에 설득력을 주는 부분임.

![학습된 안전 경계 사례](/images/2026-08-19-she-safety-harness-evolution/fig-5-p9.png)

6. 내 해석은 두 가지를 짚음. 첫 번째, 진화 품질이 GPT-5.5 진단에 의존함. 진화 모델을 바꾼 절제 실험에서 DeepSeek-V3.2는 이른 수렴 후 안전을 공격적으로 올리고 GPT-5.5는 유틸리티 보존이 강하고 GLM-5.2는 중간이었음. 진화 모델 선택이 곧 안전-유틸리티 트레이드오프 선택이라는 것. 두 번째, 20라운드 중 수용은 R00, R03-R05, R17 다섯 곳뿐. R05-R16은 플래토라서 후보가 계속 거절됨. 동시 개선 조건이 보수적이라 살아남는 수정이 적다는 건 장점이자 비용. 안전 개선 루프가 빠르게 수렴한다고 착각하면 안 된다는 뜻임.

7. 실무 이식 결론. System Prompt, 규칙, 도구 권한을 아티팩트로 분리하고, 실패 로그 기반으로 국소 수정한 뒤 유틸리티 회귀 테스트를 거쳐 채택하는 루프. 이 구조는 논문 구현을 그대로 안 써도 프롬프트·가드레일 운영에 바로 벤치마킹 가능함. 진화 모델을 뭘로 쓸지, 수용 조건을 얼마나 보수적으로 둘지가 실제 결과를 좌우하는 하이퍼파라미터임. 코드는 [github.com/RainbowQTT/SHE](https://github.com/RainbowQTT/SHE)에 공개돼 있음.
