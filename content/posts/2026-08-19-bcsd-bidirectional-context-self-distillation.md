에이전트에 스킬 라이브러리를 달아줘도 정작 스킬을 잘 못 쓰는 문제가 있음. [BCSD](https://arxiv.org/abs/2608.09555)(컨텍스트를 늘린 뷰와 줄인 뷰 양방향에서 자기증류 신호를 만드는 스킬 활용 학습 프레임)는 이걸 "스킬을 더 잘 쓰도록 정책을 학습시키는 것"으로 접근함. 컨텍스트를 늘린 뷰와 줄인 뷰 두 방향에서 자기증류(같은 모델이 자기 출력을 비교해 스스로에게 학습시키는 방식) 신호를 만들어 GRPO(같은 문제의 여러 답을 서로 비교해 학습하는 강화학습 알고리즘) 어드밴티지(그룹 내 상대 점수, 학습 신호의 원천)를 리스케일하는 방식이 핵심임. 좋은 스킬을 제공해도 그걸 효과적으로 쓰는 건 별개의 능력이라는 문제의식이 앞선 Regression Tax와 이어져서 정리함.

1. 배경. 스킬 기반 에이전트 연구는 두 갈래였음. 스킬 품질을 개선하는 접근(SkillBank류 생성·감사·수정)은 좋은 스킬을 줘도 활용을 못 한다는 한계가 있고, 스킬을 파라미터로 증류하는 내재화 접근은 명시성·편집성·전이성을 잃음. 태스크 성공 리워드만으로는 어떤 결정이 스킬에 근거했는지 알 수 없다는 게 크레딧 할당 문제의 출발점임.

![세 가지 패러다임 비교](/images/2026-08-19-bcsd-bidirectional-context-self-distillation/figure1-paradigms.png)

2. 방법의 뼈대는 두 개의 컨텍스트 뷰임. 첫째, 증강 뷰. 롤아웃에서 성공/실패 궤적을 대조해서 "이 스킬을 어떻게 써야 하는가"에 대한 상위 가이던스(Meta-Skill)를 추출해서 컨텍스트에 추가함. 현재 정책의 행동에 의존하는 텍스트라서 학습이 진행될 때마다 검증 윈도우마다 갱신되고 추론 시에는 학생 컨텍스트에 포함되지 않음. 둘째, 축소 뷰. 일반 스킬에서 군더더기를 잘라내서 태스크 스킬 사용 여부에 집중된 참조를 만듦. 방해가 되는 일반 지침만 제거하는 것.

3. 갭-가중 어드밴티지 리스케일이 핵심 메커니즘임. 각 토큰에 대해 두 컨텍스트에서의 로그확률 갭을 계산하고(증강 뷰 가중치 0.9) 이 갭으로 원래 GRPO 어드밴티지의 크기만 조절함. 업데이트 방향은 리워드가 정하고 크기만 컨텍스트 신호가 조절한다는 설계임. 그리고 리스케일 계수는 0.1에서 선형 감쇠해서 초반에는 밀도 높은 가이던스를 주고 후반에는 환경 리워드에 반환함. 가이던스는 지속이 아니라 이행 수단이라는 판단임.

![BCSD 프레임워크](/images/2026-08-19-bcsd-bidirectional-context-self-distillation/figure2-overview.png)

4. 결과. ALFWorld(텍스트 가상 집안에서 일상 과제를 수행하는 벤치마크)와 WebShop(가상 쇼핑몰에서 주문 조건에 맞는 상품 찾기를 수행하는 벤치마크)에서 Qwen2.5-3B/7B, Qwen3-1.7B로 평가해서 Qwen2.5-7B ALFWorld 평균 83.6%(최고 baseline 대비 +3.1pt), WebShop SR 78.1%로 최고, 3B에서는 WebShop +9.4pt. 학습 곡선 차이가 뚜렷해서 WebShop 스텝 60에서 BCSD는 약 45%에 도달할 때 다른 메서드는 20% 미만이었음. 최종 약 66%로 최강 baseline 대비 약 9%p 우위.

5. ablation이 구성의 타당성을 보여줌. Meta-Skill 뷰를 제거하면 ALFWorld 82.0→71.1, WebShop 66.4→50.0으로 가장 크게 하락함. Pruned 뷰 제거는 82.0→75.0. 그리고 λ 감초를 없애고 고정하면 76.6/52.3으로 떨어짐. 초반 가이던스는 유지하되 후반엔 리워드 학습으로 반환해야 한다는 것. 단일 신호에 의존하지 않고 늘리기/줄이기 양방향 교차 검증이 안정적 크레딧 할당으로 이어진다는 게 저자의 해석이고 동의함.

6. 진짜 스킬을 쓰는지 검증도 깔끔함. 태스크 스킬을 추론 시 제거하면 BCSD는 ALFWorld −2.3pt, WebShop −7.8pt 하락함. 파라미터에 지식을 외운 게 아니라 외부 스킬을 실제로 읽어서 쓰고 있다는 증거임. 스킬 사용법만 내재화하고 지식은 외부에 편집 가능한 형태로 남겨둔 것. 지식이 스킬 파일에 있으니 나중에 스킬을 고치면 정책을 다시 학습할 필요 없이 행동이 바뀜. 이게 내재화 접근 대비 이 구조의 실용적 장점임.

7. 내 해석 두 가지. 첫째, 스킬 뱅크를 운영 중이라면 스킬 문서를 더 다듬는 것보다 정책이 스킬을 활용하도록 학습시키는 편이 성능 차이가 큼. 파인튜닝을 안 하는 나 같은 경우의 번역은 이것임. 스킬을 잘 쓰게 만드는 프롬프트 장치(스킬 선택 시점, 진입 경고, 사용 사례 대조)를 스킬 문서 안에 두는 것. 둘째, 단일 특권 컨텍스트에 의존하는 증류는 불안정하니 정보를 넣은 뷰와 뺀 뷰를 비교하는 양방향 검증 구조가 안정적이라는 원칙. 검증 파이프라인 설계에도 적용됨.

8. 한계. ALFWorld/WebShop은 텍스트 기반 벤치마크라 실무 툴 사용 에이전트로의 확장은 추가 검증이 필요하고 코드 릴리스가 예고된 상태임. 그래도 "스킬 품질과 스킬 활용력은 다른 축이고 후자를 키우는 게 더 크다"는 방향 자체는 벤치마크 밖에서도 유효해 보임.
