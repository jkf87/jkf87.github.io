RAG 검색 방식 논쟁에 통제된 답이 나옴. [USTC와 Metastone의 스케일링 실험](https://arxiv.org/abs/2607.26497)이 51만 개 문서, 6억 토큰 코퍼스에서 28개 중첩 단계를 만들고 네 가지 RAG 패러다임(어휘 검색, 밀도 검색, 그래프 RAG, 에이전트 검색)을 같은 조건에서 돌림. 밀도 검색은 문서와 질의를 벡터로 바꿔 의미 유사도로 찾는 방식이고, 그래프 RAG는 문서 속 개체와 관계를 그래프로 추출해 검색에 활용하는 방식임. 결론이 충격적임. 코퍼스가 커질수록 가장 단순한 BM25가 가장 정교한 에이전트 검색과 그래프 RAG를 이김. BM25는 질의와 문서에 공통으로 들어간 단어의 빈도와 희귀도를 점수화해 문서 순위를 매기는 대표적인 키워드 기반 어휘 검색 알고리즘임. 교차점은 약 1,000만 토큰. 에이전트로 검색을 시키는 사람이 꼭 알아야 할 그래프라 정리함.

1. 기존 연구가 왜 엇갈렸는지부터. 전부 코퍼스 크기를 고정하고 비교했음. 수천 개 문서에서 낸 결론을 수십만 개 문서에 확장 못 함. 이 실험은 다르게 설계함. 골드 문서 722개와 함정 문서 326개, 루어 99개를 최소 단계(1,144개 문서, 170만 토큰)에 고정하고, 그 위를 포함하면서 1.25배씩 28단계로 51만 개 문서, 6억 토큰까지 약 450배 확장함. 질문 500개, 리더 모델, 판정 모델 전부 동일. 함정을 최소 단계에 고정해놔서 "의미적으로 비슷하지만 사실이 틀린 문서를 걸러내는가"도 모든 규모에서 일관되게 측정됨.

![스케일링 교차점 개요](/images/2026-08-01-bm25-wins-rag-scaling-agent-vs-lexical/fig-1-p2.png)

2. 비교 대상 중 File-System Agent가 핵심임. 인덱스 없이 `ls`, `grep`, `cat` 같은 파일 도구로 원시 파일 트리를 탐색하는 방식. 질문당 80회 LLM 호출 예산을 줌. 지금 코딩 에이전트가 실제로 작동하는 방식과 같음. 즉 이 실험은 "에이전트가 직접 코퍼스를 뒤지는 게 좋은가, 인덱스 검색이 좋은가"를 규모별로 묻는 것.

3. 결과의 교차점. 소규모(170만 토큰)에서는 File-System Agent가 77.4로 BM25 74.7을 소폭 앞섬. 신뢰구간이 겹치는 수준. 근데 약 1,000만 토큰에서 곡선이 교차하고, 풀 스케일(6억 토큰)에서는 BM25가 50.5, 에이전트가 30.7로 20점 격차로 역전됨. 원인은 명확함. BM25는 인덱스에 전역 랭킹을 이미 계산해뒀기 때문에 코퍼스가 커져도 질의당 5.8K 토큰으로 일정한데, 에이전트의 순차적 탐색은 코퍼스가 커질수록 관련 브랜치에 아예 도달하지 못하는 후보 발견 실패가 남. 골드 문서 적중률이 에이전트는 39.0%로 추락하는데 BM25는 71.6%를 유지함.

![공식 성적표](/images/2026-08-01-bm25-wins-rag-scaling-agent-vs-lexical/table-1-p6.png)

4. 가장 중요한 통제 실험이 이걸 확정함. 에이전트의 검색 도구만 원시 파일 탐색에서 BM25로 바꿈. 모델, 하네스, 예산은 그대로. 결과가 Agent+BM25 조합은 풀 스케일에서 69.4점으로 원시 파일 에이전트보다 32.52점 높고 순수 BM25보다도 14.56점 높음. 결론은 한 문장임. **에이전트는 전역 랭킹 이후에 도움이 되고, 반복적 로컬 탐색은 전역 랭킹의 대체재가 아님.** 발견은 인덱스가 하고 정밀 분석은 에이전트가 하는 분업이 정답임.

5. 그래프 RAG는 더 극적임. 구축 비용의 벽에 부딪힘. MS-GraphRAG는 8,750개 문서에서 중단, 풀 스케일 추정 79억 생성 토큰, 약 50일. LightRAG는 2,826개 문서에서 완료 불가에 풀 스케일 추정 1,020억 토큰, 약 4년. HippoRAG 2는 그나마 3일 추정인데 1억 5,500만 토큰 코퍼스에서 7억 2,400만 토큰을 쓰고도 41.0점으로 BM25보다 15점 낮음. 그리고 LLM 추출 없이 NER + 임베딩만으로 그래프를 만든 LinearRAG가. NER은 개체명 인식으로, 문장에서 사람·장소·사물 같은 개체 이름을 뽑아내는 기술임. MS-GraphRAG·LightRAG와 1.8점 이내였음. LLM 기반 추출이 비용 대비 노이즈를 더 빨리 만들어낸다는 뜻임.

![비용 스케일링](/images/2026-08-01-bm25-wins-rag-scaling-agent-vs-lexical/fig-4-p7.png)

6. 비용 효율도 압도적임. BM25는 500질문에 290만 토큰, 인덱스 구축 비용 제로. File-System Agent는 500질문에 1억 1,280만 토큰. 질문당 39~60배 차이임. BM25는 상환 기간 10에서 10,000질문까지 파레토 프론티어 위에 있음. 에이전트 탐색이 40배 비싸고 규모가 커지면 점수도 낮으면 쓸 이유가 없는 것.

7. 근데 에이전트가 아직 이기는 영역도 있음. 완결성 질문(여러 문서를 종합해야 하는)에서는 56 대 27로 압승이고, 문서 내 질문, 프로젝트 관련 질문, 충돌 정보 비교 질문에서도 우세함. 반면 조회형, 교차 출처, 집계형은 BM25가 최고. 그래서 실전 정답이 Agent+BM25 하이브리드임. 전역 어휘 랭킹으로 후보를 발견하게 하고, 좁혀진 후보에 대해 에이전트가 정밀 분석하는 것. 각자 잘하는 단계를 분리해서 붙이는 것.

![질문 유형별 성적](/images/2026-08-01-bm25-wins-rag-scaling-agent-vs-lexical/fig-5-p8.png)

8. 그래프 RAG 실패 원인 세 가지도 정리돼 있음. 추출 노이즈(32K 추출 엔티티 중 상당수가 malformed fragment), 의미적 유사 함정(그래프 검색이 의미적으로 가깝지만 사실이 틀린 이웃을 반환), 확장 비용(LightRAG는 초선형 증가). 그래프 RAG는 관계형 질문이 압도적으로 많고, 구축이 준선형이고, 코퍼스가 10만 문서 이하일 때만 정당화된다는 게 연구진의 결론.

9. 실무 가이드로 번역함. 첫째, 기본값은 BM25임. 엔터프라이즈 코퍼스에서 가장 강력하고 가장 쌈. 둘째, 집계·종합 질문이 많으면 Agent+BM25 하이브리드로 가라. 셋째, 코퍼스가 자랄 것을 고려하라. 오늘 1만 문서에서 에이전트가 이겨도 내일 50만 문서가 되면 역전당함. 나도 이 원칙을 내 위키와 메모리 검색에 그대로 적용할 계획임. grep질 대신 인덱스 검색 먼저, 에이전트는 후보 정리 단계로 보내는 것.
