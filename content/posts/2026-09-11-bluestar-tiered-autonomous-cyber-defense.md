공격은 기계 속도로 움직임 — 평균 브레이크아웃 시간 29분, 최단 27초. 방어 자동화는 탐지와 실행까지만 되고 "어떤 경보가 진짜인지 판단하는" 단계는 사람 몫이었음. [BlueSTAR](https://arxiv.org/abs/2609.11852)가 이 판단 단계를 라이브 사이버 레인지 2곳에서 검증함. 고처리량 데이터에 LLM을 붙이는 구조 문제라 정리함.

1. 실험 1이 출발점임. Security Onion(오픈소스 보안 모니터링 플랫폼)이 초당 23.4만 토큰을 쏟아내는데 1M 컨텍스트 Opus 4.7조차 초당 6.3만 토큰만 처리 — 3.7배 모자람. 컨텍스트를 늘려도 처리량 자체는 안 늘어남. 원본 로그 직접 입력 구성의 연간 비용은 Opus 기준 $37M.

2. 정확도 실패가 더 인상적임. gpt-4o-mini가 내린 469개 행동 중 313개가 방어자 자기 머신 격리였고 5개는 인증 기관 계정 삭제 — 실행됐다면 방어 시스템이 스스로 무력화됐을 것. 20배 비싼 Sonnet으로 바꿔도 20개 윈도우 전부에서 잘못된 호스트 격리. 논문의 결론 — 이 격차의 뿌리가 표현(representation)에 있어서 모델 능력이 올라가도 안 닫힌다는 것.

3. 조치는 4단계 계층. Signal Extraction(원본 텔레메트리를 행위자별 집계 IOC로 변환) → Tier 1 결정론적 응답기(고정 규칙, 메인 루프에서 동기) → Tier 2 LLM 추론(백그라운드, 최소 1사이클 오프셋) → Rolling Memory(열린 위협과 행동 이력 유지).

4. Tier 1이 동기로 도는 게 설계의 핵심임. 물리적 결과가 있는 행동이 LLM 호출 대기열 뒤로 밀리면 안 되니까 안전 크리티컬 응답 지연을 상한으로 보장. API 타임아웃이 나도 Tier 1은 계속 돔. 탐지기도 두 종류 — 정밀 탐지기는 Tier 1으로 직결, 문맥 보강 탐지기(SED)는 자연어 출력을 Tier 2만 소비. 고정 규칙에 물으면 오탐률이 감당 안 되는 애매한 신호를 LLM 계층에서 소화하는 것.

5. 숫자. 신호 추출 계층을 앞세우니 연간 비용 $2K(Opus) / $60(mini) — 18,000배 절감. 같은 mini 모델로 정밀도 3.8% → 100%. 자기 격리 313회 → 0회.

6. 규칙 기반의 두 구멍을 LLM이 막음. 첫째, 탐지 커버리지 갭 — DCSync(도메인 컨트롤러에서 자격증명을 동기화해 탈취하는 공격 기법)는 정상 DC 동기화와 로그가 같아서 Tier 1이 0행동, 6분 만에 기밀 파일 5개가 유출(Res-AUC 0.146, 무방비와 동일). LLM은 행동 IOC를 읽고 자격증명 탈취로 추론해 횡적 이동 탐지 전에 선제 조치, 파일 전부 보존. 둘째, 사이클 간 추론 갭 — 재침투 공격자 앞에서 Tier 1은 매번 같은 세션 종료를 반복. Tier 2는 Rolling Memory에서 재침투 신호를 보고 대응을 끌어올림.

7. 7개 공격 체인의 패턴이 명확함. 신호가 명확한 체인은 Tier 1로 충분하고 Tier 2를 더해도 성적이 안 떨어짐. 문맥 추론이 필요한 순간에만 Tier 2가 격차를 벌림. Concurrent 시나리오가 승부처 — 시끄러운 유인이 방어를 포화시키는 동안 조용한 유출이 일어나는데, Tier 1만 있으면 무방비와 구분 안 되고(0.014) BlueSTAR는 유인을 Tier 1이 흡수하는 동안 Tier 2가 두 위협을 독립 추적해 유출 에이전트가 도달하기 2-18초 전에 선제 격리.

8. 여기서 문제제기. 이건 보안 도메인만의 얘기가 아님. LLM 에이전트를 고처리량 원본 데이터에 붙일 때 입력을 의사결정 단위로 집계하는 계층이 모델 선택보다 앞선 전제 조건이라는 것. 센서 스트림 감시, 긴 컨텍스트 코드베이스 에이전트도 같은 구조 문제를 가짐. 내 자동화도 원본 로그를 그대로 넣는 지점이 있는지 점검할 것.

9. 적용 원칙 세 개. (1) LLM에게 원본이 아니라 집계된 의사결정 단위를 줄 것 — 집계 계층 설계가 모델 선택보다 먼저. (2) 물리적 결과가 있는 행동은 결정론적 계층에 두고 LLM은 백그라운드로 — LLM 장애가 크리티컬 경로를 막지 않게. (3) LLM 행동을 타깃이 명시된 행동 어휘로 제한할 것 — 무제한 행동의 자기 격리 313회가 정확도 문제 이전의 안전 문제임을 보여줌.

10. "이미 시도했고 실패한 행동의 이력"을 읽고 행동 종류를 바꾸는 순간이 Tier 2의 인상적 장면 전부라는 점도 기억할 것. 상태 없는 사이클 호출에서는 나올 수 없는 능력 — 메모리 설계가 대응 가능한 위협 클래스를 결정한다는 것.

11. 한계. 적응적 공격자는 범위 밖. 자격증명 교체 같은 일부 대응은 운영자 보고로 끝남. 평가 환경 2곳 모두 논문 팀이 구축한 레인지라 실제 프로덕션 검증은 아님.

12. 결론. 실패의 3종(처리량, 비용, 정확도)이 전부 같은 원인 — 패킷 볼륨 입력 vs 행위자 단위 의사결정의 표현 불일치였음. 모델을 바꿔도 안 닫히는 격차는 구조로만 닫힘. 근데 그 구조의 핵심이 "LLM 이전의 집계 계층"이라는 것 — 결국 LLM 이전 단계에서 얼마나 잘 요약하느냐가 모든 걸 결정한다는 결론임.
