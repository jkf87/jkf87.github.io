멀티에이전트 LLM 시스템에 GRPO(그룹 단위로 여러 응답을 뽑아 그룹 평균과 비교해 상대 보상을 매기는 강화학습 알고리즘)를 그대로 걸면 학습이 불안정해지는 이유를 수학적으로 짚은 논문이 있음. 모든 에이전트에게 하나의 전역 평균/표준편차로 어드밴티지를 정규화하면 역할마다 reward 분포가 다른데 그 차이가 그래디언트 노름 폭주로 이어진다는 것. Dr. MAS(arXiv 2602.08847, NTU Bo An 그룹)가 이걸 해법 한 줄로 품. 각 에이전트가 자기 데이터의 평균 μk와 표준편차 σk로 자기 어드밴티지를 정규화하는 것. 결과가 큼. 수학 +5.6%, 멀턴 검색 +15.2%(avg@16, 16회 실행 평균 성능), 그래디언트 스파이크 대부분 제거.

1. 문제 진단이 인과로 정리돼 있음. GRPO는 그룹 단위 rollout(태스크를 한 번 실행해 모은 궤적)에서 그룹 평균을 baseline으로 쓰는데 단일 에이전트에선 잘 작동함. 근데 멀티에이전트로 오면 상황이 달라짐. 에이전트마다 호출 빈도가 다르고 역할이 다르니 reward 분포 자체가 다름. 그런데 전역 baseline 하나로 모든 에이전트의 어드밴티지(각 결과가 평균보다 얼마나 나은지 나타내는 학습 신호)를 정규화하면 실제 분포와 baseline이 어긋난 에이전트의 그래디언트가 비정상적으로 커짐. 논문은 이 어긋남이 그래디언트 이차 모먼트(그래디언트 크기의 제곱 평균)를 키워서 노름 폭발로 이어진다고 수학적으로 보여주고 실측으로 확인함. vanilla GRPO에서 search agent의 그래디언트 노름이 80을 넘긴 뒤 NaN(숫자가 아니라는 값, 수치가 발산해 계산이 무너진 상태)으로 죽는 사례가 재현됨.

![](/images/2026-09-11-dr-mas-stable-multi-agent-llm-rl/fig-4-p9.png)

2. 해법이 어드밴티지 정규화 한 줄이라 도입 비용이 거의 없음. 경험을 에이전트별로 그룹핑하고 각 에이전트 k는 자기 그룹의 μk, σk로 정규화. 다른 학습 절차는 그대로임. ablation이 어떤 통계를 바꿔야 하는지 알려줌. 전역 28.0 → 평균만 에이전트별 39.1 → 표준편차만 42.9 → 둘 다 43.8(avg@16). 표준편차 쪽 기여가 더 큼. 에이전트 간에 평균 차이보다 퍼짐 차이가 더 크다는 뜻임.

3. 실험이 두 축으로 돌아감. 수학은 solver/verifier 2에이전트 루프로 Qwen3-4B/8B. 검색은 verifier/search/answer 3에이전트로 Qwen2.5-3B/7B. 검색 쪽 실패가 극명함. Qwen2.5-7B 비공유에서 vanilla GRPO는 그래디언트 노름이 커지면서 검색 호출 자체를 회피하도록 학습돼 28.0/40.5로 추락. Dr. MAS는 같은 설정을 43.8/58.3로 복원함. 이건 단일 에이전트 baseline과 공유 설정보다도 높은 수치임. 학습 불안정이 단순히 죽는 게 아니라 회피 행동으로 변질된다는 게 실무적으로 무서운 부분임.

![](/images/2026-09-11-dr-mas-stable-multi-agent-llm-rl/table-2-p8.png)

4. 수학 쪽에서 비공유 설정의 개선이 더 큼. Qwen3-8B AIME'24(수학 경시 문제로 구성된 수학 추론 벤치마크)가 42.7/66.7 → 54.8/80.0. 파라미터가 독립일수록 행동 분포가 더 벌어져서 에이전트별 보정이 더 중요해진다는 해석. 공유 설정이라도 도움은 되지만 격차가 작음. 자기 팀이 어떤 설정인지에 따라 기대 효과가 달라진다는 것.

![](/images/2026-09-11-dr-mas-stable-multi-agent-llm-rl/table-1-p7.png)

5. 내가 제일 와닿은 결과는 이질 모델 배치임. verifier에만 Qwen2.5-7B를 두고 search/answer에 Llama-3.2-3B를 쓰는 구성을 전체 7B 동질 구성과 비교했더니 성능은 거의 동일한데 API 비용 41.8% 절감, 지연 31.6% 절감. 계층형 멀티에이전트에서는 최상위 판단자만 강하면 전체 품질이 유지되고 하위 실행 에이전트는 작은 모델로 바꿔도 된다는 결론. 배포 설계에 바로 쓸 수 있는 가이드라인임. "전 에이전트를 프롼트리어 모델로"가 아니라 "판단 지점만 프론티어로"가 비용 정답이라는 것.

![](/images/2026-09-11-dr-mas-stable-multi-agent-llm-rl/fig-5-p9.png)

6. 프레임워크 기여도 있음. 논리 에이전트 K개를 물리적 LLM 워커 그룹으로 매핑하고 에이전트별 학습 설정을 따로 두며 액터 백엔드 자원을 공유 스케줄링함. 기존 veTRL/ROLL/AReaL류 대규모 RL 프레임워크가 단일 액터 최적화 중심이라 이런 멀티에이전트 오케스트레이션이 자연스럽지 않았다는 지적도 참고할 만함.

7. 어디까지 믿을지 정리. 원문이 명확히 보여준 건 전역 정규화에서 그래디언트 불안정으로의 인과(이론+실측), (μk,σk) 정규화의 일관된 개선, NaN 재현. 주의 포인트는 실험이 role-specialized 오케스트레이션 2종으로 한정된다는 것. 자유로운 대화형 멀티에이전트나 코드 에이전트 같은 위상에 그대로 일반화하긴 이르고 보상도 binary 기준이라 연속 보상이 섞이면 분포 차이가 다른 양상을 보일 수 있음. 그래도 수정 비용이 거의 0이라 멀티에이전트 RL을 돌리고 있다면 가장 먼저 시도해볼 후보임. 단일 에이전트 GRPO에서는 그룹 내 분포가 하나라 전역 정규화가 이미 자기 통계와 같아서 안 써도 됨.
