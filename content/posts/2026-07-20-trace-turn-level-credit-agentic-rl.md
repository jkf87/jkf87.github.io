에이전트 RL에서 제일 골치 아픈 게 크레딧 할당임. 수십 번의 도구 호출 중 정확히 어느 것이 정답 도달에 기여했는지 결과 보상은 말을 안 해줌. TRACE는 동결된 참조 모델을 탐침으로 써서 턴 단위 보상을 계산해냈음. 추가 크리틱, 과정 라벨, 판단 모델 다 없이 작동함.

1. 문제 구조부터. 실패한 롤아웃에도 유용한 검색이 섞여 있고 성공한 롤아웃에도 쓸데없는 행동이 섞여 있음. 근데 결과 보상은 궤적 전체에 하나의 부호만 줌. 그래서 유용한 탐색이 벌점 받고 불필요한 행동이 보상 받는 왜곡이 생김. 호라이즌이 길수록 그래디언트 분산도 커짐.

2. 기존 대안인 과정 감독은 단계별 라벨이나 강력한 판단 LLM이 필요함. 비용이 크고 보상 모델 드리프트 문제도 있음. TRACE는 이 쪽 길을 안 감.

3. 핵심 직관은 단순함. 정답이 이미 알려진 훈련 시점에서, 각 도구 호출 뒤에 정답이 더 예측 가능해졌는지를 측정하는 것임. 동결된 참조 모델(학습 초기화 복사본)이 판단자가 아니라 안정적인 탐침 역할을 함.

![도구 호출 경계의 크레딧 할당](/images/2026-07-20-trace-turn-level-credit-agentic-rl/fig-1-p2.png)

4. 계산은 3단계임. 첫째, 각 궤적 프리픽스에서 정답의 평균 로그 확률을 참조 모델로 계산. 둘째, 원시 점수 대신 초기 갭 대비 얼마나 닫았는지 로그 비율 가치로 변환. 셋째, 인접 프리픽스 간 가치 차이인 TD 차이를 턴 보상으로 사용. 양수면 도움, 0이면 무의미, 음수면 정답에서 멀어진 것임.

5. 로그 비율을 쓰는 이유가 있음. 같은 절대 증가라도 정답에서 멀 때는 미미하고 가까울 때는 큼. 상대적 갭 폐쇄가 절대적 가능도 변화보다 더 좋은 크레딧 신호라는 게 실험으로도 확인됨. 로그 비율 TD가 35.5, 원시 델타가 32.4, 결과 전용 GRPO가 30.0임.

6. 그리고 1단계 TD 크레딧은 망원경 특성이 있어서 중간의 중복 턴들이 신호를 부풀리지 못함. 긴 궤적에서 노이즈가 누적되는 걸 수학적으로 차단하는 구조임.

![TRACE 보상 구성](/images/2026-07-20-trace-turn-level-credit-agentic-rl/fig-2-p4.png)

7. 결과. Qwen3-4B는 BrowseComp-Plus 7.2→35.6, 네 벤치마크 평균 13.4→34.0. Qwen3-30B-A3B는 평균 16.7→38.1. GRPO 대비 +4.5~+5.6임. 콜드스타트 SFT, 미드트레이닝, 라이브 웹 데이터 없이 순수 RL만으로 달성했음.

8. 통제가 잘 된 비교라는 점이 설득력임. 같은 백본, 같은 브라우저 인터페이스, 같은 데이터, 같은 평가 프로토콜에서 최적화 신호 구성만 바꿈. 30B에서 TRACE 160스텝 체크포인트가 결과 보상 200스텝을 이미 앞질렀음.

![학습 곡선](/images/2026-07-20-trace-turn-level-credit-agentic-rl/fig-3-p9.png)

9. 왜 빨리 배우는가. 결과 보상만 쓰면 초반의 긴 궤적은 대부분 실패라 긴 상호작용 시도 자체가 벌점임. TRACE는 각 상호작용이 정답 예측 가능성을 높였는지 즉각 보상하니까 에이전트가 "유의미한 탐색"을 일찍 배움. 이득이 더 긴 추론이 아니라 정보 흐름 관리에서 온다는 게 논문의 해석임.

10. 하이퍼파라미터 감각도 실무에 유용함. 턴 보상 계수는 0.2~3이 최적이고 너무 크면 로컬 준비도가 최종 정확도를 압도함. TD look-ahead는 K=3이 최적, 안 쓰면 결과 전용과 거의 같아짐. 참조 체크포인트는 초기화든 step 200이든 비슷해서 강한 교사 모델이 따로 필요 없음.

11. 전이도 확인됨. 폐쇄 코퍼스에서 훈련했는데 개방형 웹 검색(GAIA 34.1→52.0)과 중국어 벤치마크(xbench-DeepSearch 20.0→45.0)까지 전이됨. 언어를 넘는 검색 전략 학습이라는 뜻임.

12. 실무 채점. 이 원리는 훈련 말고도 쓸 데가 있음. 에이전트 실행 로그를 디버깅할 때 "각 턴 뒤 정답 가능성이 어떻게 움직였는지"를 참조 모델 점수로 그려보는 것. 어떤 도구 호출이 실제로 정보를 끌어왔는지 육안 리뷰보다 싸게 판별 가능함. 실패 궤적에서 잘한 턴을 찾아내는 평가 루프에도 바로 붙일 수 있음.

13. 한계는 명확함. 짧고 검증 가능한 정답에 최적화돼서, 정답이 길거나 구조화된 작업(코드 패치, 개방형 어시스턴트)에서 적용성이 미확인임. 검증 환경도 검색 작업 중심임.

14. 그래도 메시지는 남음. 크레딧 할당 문제를 외부 크리틱 없이 "정답을 아는 상태에서의 참조 모델"로 푸는 발상. 에이전트 학습 파이프라인에 추가 학습 비용 없이 밀집 신호를 얹는 방법임.
