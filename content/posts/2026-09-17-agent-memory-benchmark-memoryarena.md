기존 메모리 벤치마크에서 준최고 점수를 내던 에이전트들이 [MemoryArena](https://arxiv.org/abs/2602.16313)에서는 평균 태스크 성공률 0.12~0.17에 그침. 그룹 여행 계획 환경에서는 모든 방법의 성공률이 0.00이었음. 핵심은 이것임. 기억을 불러오는 것과 기억을 다음 행동에 쓰는 것은 다른 능력인데 기존 벤치마크는 앞쪽만 측정했다는 것. ICML 2026 정규 논문이고 Stanfold·UCSD 등이 참여함. 나처럼 메모리 시스템을 붙여서 쓰는 사람에게 도입 결정의 기준이 바뀌는 결과라 정리함.

1. 기존 벤치마크의 구조적 한계가 명확함. LoCoMo, LongMemEval, MemoryAgentBench 같은 회상 중심 벤치마크는 과거 대화를 읽고 단일 질문에 답하는 형태라 에이전트가 환경과 상호작용하며 메모리를 능동적으로 쓰는 과정이 없음. WebArena류 행동 벤치마크는 액션은 있는데 단일 세션이라 장기 메모리가 필요 없음. 실제 환경은 둘이 묶여 있음. 초반 상호작용에서 호환성 조건이나 중간 추론 결과 같은 잠재 제약이 생기고 환경은 이걸 다시 말해주지 않으니 에이전트가 스스로 보관했다가 뒤의 결정에 적용해야 하는 것.

![MemoryArena 개요](/images/2026-09-17-agent-memory-benchmark-memoryarena/fig-1-p1.png)

2. 구성이 실전에 가까움. 네 가지 환경이 각각 다른 의존 구조를 담당함. 번들 쇼핑은 나중 구매가 이전 아이템 속성 회수에 의존하고 교차 호환성 같은 전역 제약이 걸림. 그룹 여행 계획은 첫 일정에 참가자가 점점 붙어서 선임 참가자의 활동과 선호를 정확히 기억해야 새 제약과 기존 계획의 충돌을 풀 수 있고 의존 체인이 깊이 4까지 감. 점진적 웹 검색은 조건이 단계마다 하나씩 추가돼서 최종 답이 전체 조건을 만족해야 함. 형식 추론은 연구 수준 수학·물리 논문의 정리 증명을 나눠서 앞 서브태스크의 정의와 보조정리를 뒤에서 재사용해야 함. 태스크당 평균 57 액션 스텝, 추론 트레이스 40k+ 토큰. 가볍지 않은 설정임.

![네 가지 환경](/images/2026-09-17-agent-memory-benchmark-memoryarena/fig-2-p4.png)

3. 결과가 뼈아픔. GPT-5.1-mini 롱컨텍스트 평균 SR 0.16, GPT-4.1-mini 0.12, Gemini-3-Flash 0.17. 그룹 여행 계획은 전 방법 SR·PS 0.00이라 논문이 별도 soft Progress Score를 도입할 정도였음. 눈에 띄는 패턴은 SR과 PS의 격차. 대부분 방법에서 서브태스크 단위 진척 점수는 성공률보다 훨씬 높음. 개별 서브태스크는 어느 정도 풀지만 이걸 전역적으로 일관된 해답으로 통합하는 데 실패한다는 뜻임. 회상 벤치마크에서 준포화 점수를 내던 에이전트가 이 설정에서 무너진다는 게 핵심 관찰임.

4. 외부 메모리와 RAG가 도움이 되는 조건이 갈린다는 것도 실무적으로 중요함. 점진적 웹 검색과 형식 추론에서는 Letta, Mem0, ReasoningBank 같은 외부 메모리가 일관된 향상을 냄. 트레이스가 120k+ 토큰으로 길거나 도메인 추론이 무거워서 롱컨텍스트가 주의 포화와 오류 누적에 취약한 구간이니 외부 메모리의 선별·증류가 이를 완화하는 것. 반대로 앞서 얻은 정보의 정확한 재사용이 필요한 작업(형식 추론의 중간 결과 회수, 여행 계획의 정확한 활동·시간대 참조)에서는 검색 기반이 더 강했음. 무거운 추상화·통합을 하는 외부 메모리보다 RAG의 감쇠가 완만했다는 것. 앞서 정리한 BM25 스케일링 연구와 같은 방향, 즉 정확한 회수가 병목이면 검색이 이김.

![SR@k 감쇠](/images/2026-09-17-agent-memory-benchmark-memoryarena/fig-3-p6.png)

5. 그리고 깊이에 따른 감쇠가 전 방법에 있었음. 서브태스크 깊이 k가 깊어질수록 모든 방법의 성공률이 감쇠하고 평평하게 유지되는 방법은 없었다는 것. 롱컨텍스트도 외부 메모리도 깊은 상호의존 태스크를 안정적으로 지탱하지 못한다는 결론. 레이턴시 트레이드오프도 있어서 외부 메모리 에이전트의 지연이 가장 크고 롱컨텍스트가 가장 낮았다는 것.

6. 실무 교훈 세 개. 첫째, 메모리 시스템 도입 결정을 벤치마크 회상 점수만으로 하지 말 것. 실제 워크플로와 비슷한 다중 세션 태스크에서 측정하고 도입할 것. 둘째, 정확한 재사용이 중요한 도메인(코드, 수학, 예약)에서는 복잡한 메모리 파이프라인보다 검색 기반이 나을 수 있음. 셋째, 메모리 평가를 설계할 때 성공률 하나만 보지 말고 진척 점수와의 격차를 볼 것. 부분 해결은 되는데 통합에 실패하는 실패 모드가 숨어 있음. 나도 내 메모리 시스템의 효과를 "기억해냈나"로 검증해왔는데 "그 기억으로 다음 행동이 바뀌었나"로 검증 기준을 바꿔야 함.
