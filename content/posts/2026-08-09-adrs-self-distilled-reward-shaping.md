에이전트 RL의 함정은 환경이 궤적 끝의 성공/실패만 준다는 것. 50스텝 궤적에서 어떤 액션이 기여했는지 알 방법이 없음. ADRS는 이걸 훈련 전용 특권 컨텍스트(정답·해설처럼 훈련 때만 보여주는 추가 정보)로 품. 크레딧 할당 시리즈의 한 축이라 정리함.

1. 배경. GRPO(같은 문제의 여러 롤아웃을 그룹으로 묶어 상대 비교로 정책을 갱신하는 RL 알고리즘)든 GiGPO(궤적과 스텝을 이중으로 그룹 묶어 어떤 스텝이 성공에 기여했는지까지 비교하는 에이전트 RL 알고리즘)든 궤적 끝 보상 하나를 전체에 뿌림. 잘한 액션과 망친 액션이 같은 크레딧을 받는다는 건 이전에 본 TCPO, TurnSight와 같은 문제임. ADRS는 같은 문제를 "특권 정보로 자기 증류"라는 다른 각도로 품.

2. [ADRS](https://arxiv.org/abs/2608.03223)의 조치. 행동 정책이 스킬 없이 롤아웃을 만들고, 그 토큰들을 고정한 뒤 같은 정책이 특권 컨텍스트 하에서 재평가함. 이 교사 점수를 스텝별로 센터링·정규화하고, TVA 게이트로 교사 자신감이 실제 보상과 상관있는지 확인한 뒤 RL 보상에 직접 더함. 보조 손실이 아니라 RL 경로 안에 넣는 것.

3. TVA(Teacher Value Advantage) 게이트가 맹신 방지 장치임. 교사가 자신한다고 무조건 믿지 않고 그룹 안에서 교사 신뢰도 높은 쪽/낮은 쪽의 평균 보상을 비교해서 게이트 값을 만듦. 끄면 성능이 87.5% → 89.8%로 2.3pp 차이 나고 last-3 안정성이 91.9% → 94.3%로 올라감. 파이널 체크포인트 신뢰도에 더 큰 기여를 함.

4. 숫자. Qwen2.5-3B 기준 ALFWorld(텍스트 가상 집에서 일상 과제를 푸는 에이전트 벤치마크) 75.0% → 94.5%(+19.5pp), WebShop(모의 쇼핑몰에서 조건에 맞는 상품 검색·구매 벤치마크) 63.3% → 76.6%, Search QA 36.4% → 45.0%. 300스텝 피크는 97.7%. 모델을 바꿔도(Qwen2.5-7B +7.8pp, Qwen3-1.7B +8.6pp) 일관됨.

5. 데이터 효율이 눈에 띔. ALFWorld 훈련 데이터 60%만 써도 78.1%로 풀데이터 GRPO(75.0%)를 넘김. 토큰 단위 크레딧이 있으니 적은 데이터로도 배우는 것. 비싼 롤아웃을 줄일 수 있다는 실무적 의미.

6. 교사 신호가 어디에 집중하는지 분석한 게 제일 흥미로움. 액션 토큰, 오브젝트 토큰, 스타일 토큰을 분리해서 교사-학생 갭을 측정했더니 초기에 액션/스타일 비율이 1.6이던 게 step 150엔 95.3까지 감. 교사 신호가 실행 액션과 객체 선택에만 집중되고 문체 토큰엔 신경을 안 씀. 긴 호라이즌에서 잘 되는 이유가 여기 있음.

7. 여기서 문제제기. 이건 훈련 기법이라 프롬프트로 직접 복제는 안 됨. 근데 교사 신호의 집중 패턴은 분석 관행으로 베낄 수 있음. 궤적에서 무엇이 중요했는지 평가할 때 액션 선택과 객체 지정을 보는 것 — 문체나 서술은 건너뛰는 것. 로그 리뷰의 초점을 어디에 둘지 정해주는 데이터임.

8. 그리고 TVA의 발상은 평가자 검증에 그대로 이식됨. 내가 쓰는 LLM 판정자가 이 케이스들에서 실제로 잘 맞히는지 확인한 뒤에만 가중치를 주는 것. 판정자 신뢰도와 실제 정확도의 상관을 그룹 비교로 검증하는 습관 — 이거 없으면 판정자가 그냥 또 하나의 의견임.

9. 특권 정보는 훈련에만 쓰고 추론에선 없다는 점도 설계 포인트임. 정답을 알 때의 자기 평가로 학습 신호를 만들되 배포 시엔 그 혜택이 가중치 안으로 녹아들게 하는 것. 지도 교사-학생 패러다임과 같은 구조인데 RL 크레딧에 적용된 케이스임.

10. 한계. 특권 컨텍스트를 만들 수 있는 태스크 설정이 전제임. 벤치마크 3종 중심 검증이라 실무 워크로드 일반화는 미확인. 그리고 교사와 학생이 같은 모델이라 모델 자체의 한계가 교사 한계가 되는 지점은 남아 있음.

11. 결론. 성공/실패 신호를 토큰 단위 크레딧으로 바꾸는 기술이 계속 진화하고 있음 — hindsight 실행 결과(TurnSight), 참조 비교(TCPO), 특권 자기 증류(ADRS). 공통분모는 "전체 궤적에 같은 보상을 뿌리지 않는다"임. 근데 어떤 액션에 크레딧을 줄지 정하는 일은 결국 사람이 설계하는 영역이라는 것까지가 결론임.
