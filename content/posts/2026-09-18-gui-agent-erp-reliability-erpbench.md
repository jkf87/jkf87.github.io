GUI 에이전트의 화면 성공과 데이터베이스 실제 반영이 어긋난다는 걸 정량화한 벤치마크가 나옴. 엔터프라이즈 도입 검토에 직결되는 숫자라 정리함. 원문은 [arXiv:2609.17885](https://arxiv.org/abs/2609.17885).

1. 설계가 실무적임. 컴퓨터 사용 에이전트를 셀프호스팅한 오픈소스 ERP(ERPNext)에 스크린샷 1280×720만 보고 조작하게 하고, 채점은 화면이 아니라 최종 DB 필드 값을 Frappe REST API로 검증함. 재현 불가능한 독점 플랫폼 벤치마크와 달리 전부 공개 구성이라는 것도 장점임.

2. 핵심 문제는 조용한 실패임. ERP는 화면에서 성공 확인이 떴는데 DB에 값이 안 들어가거나 예전 값이 남을 수 있음. 이 오류는 화면 어디에도 안 나타나고 downstream 재무·재고 프로세스로 그대로 전파됨. 검증을 화면 대신 DB에서 하면 된다는 게 접근의 전부임.

3. 결과의 낙차가 큼. Claude Sonnet 4.6은 T1 94%, T2/T3 100%로 인간 기준선(전문가 99~100%, 첫 사용자 87~96%)에 근접. 반면 오픈 모델 최고도 T1 34%에 T2/T3는 0~3%. 그리고 첫 사용자조차 모든 오픈 모델을 크게 앞섬 — 도메인 지식 부족 탓이 아니라 실행 능력의 문제라는 것.

4. UI-TARS-7B가 극단적 사례임. 목표 레코드 도달 95%, 저장 발동 68%인데 DB 정답률 9%. 저장을 눌렀는데 거의 다 잘못된 값이 들어간 것. T2에서는 커밋 85%에 DB 정답 3%. 스테이지별 채점(Navigation → Interaction → Commit → Database)으로 실패 지점을 쪼개니 이 간극이 보인다는 게 이 벤치마크의 방법론적 기여임.

5. 실패 분류 다섯 가지 중 Save-step(값은 맞게 넣었는데 save를 안 누름)과 Perception(save는 했는데 DB에 잘못된 값 기록)이 DB 레벨 채점이 필요한 이유임. Qwen3-VL-32B는 Grounding 실패가 59%로 주된 반면 UI-TARS-7B는 Perception 59% — 모델마다 무너지는 지점이 다르다는 것도 진단 가치임.

![실패 유형 분류](/images/2026-09-18-gui-agent-erp-reliability-erpbench/fig3-failure-taxonomy.png)

6. 하네스 설계도 같이 공개함. 각 턴마다 에이전트가 액션과 리스크 등급(safe/commit/irreversible)을 제안하면 배포 모드에서는 사람이 승인해야 실행되고 commit/irreversible은 항상 명시적 확인이 필요함. 평가 모드에서만 자동 승인으로 무인 돌림. 앞서 정리한 IssueTrojanBench의 프레임워크 방어 0건 결과와 연결하면 — 모델이 허용한 행위를 막는 건 결국 이런 하네스 게이팅뿐이라는 결론이 재확인됨.

![리스크 게이팅 하네스 UI](/images/2026-09-18-gui-agent-erp-reliability-erpbench/fig2-harness-ui.png)

7. 비용도 짚을 만함. Claude는 T3에서 런당 입력 토큰이 약 2.0M까지 늘어남(T1 231K). 오픈 모델의 낮은 토큰 사용은 효율이 아니라 조기 루프 탈출 때문 — OpenCUA-7B는 T1에서 평균 1.6 액션으로 사실상 포기하는 그림임. 토큰 사용량 지표는 방향을 함께 봐야 한다는 교훈임.

8. 필자 적용 포인트. CUA 도입 검토 시 스크린샷·트레이스 기반 QA로는 부족하다는 직접 증거임. 검증은 시스템 상태(이 경우 DB, 필자의 경우 파일 내용·HTTP 응답)에서 해야 하고, 하네스 리스크 게이팅은 필수임. 그리고 "에이전트에게 시작 URL까지 주는가"가 실제 성능 변수 — 블랭크 스타트에서 체인 완성도가 22%→9%로 떨어짐. 작업 지시에 진입점을 명시하는 게 성능에 영향을 준다는 건 지금 바로 적용할 설계 변수임.

9. 문제제기. 30과제 5회 반복이라 규모가 작고, ERPNext 단일 시스템이라 다른 엔터프라이즈 소프트웨어 일반화는 열려있음. Claude의 인간급 성적도 2.0M 토큰 비용이 전제라 도입 판단엔 TCO 계산이 필요함.

10. 남는 결론. 화면 조작 능력은 엔터프라이즈 신뢰성을 보장하지 않음. 검증을 결과 상태에서 하고 위험 액션을 게이팅하는 하네스 없이는 CUA를 업무 시스템에 붙이면 안 된다는 게 이 벤치마크의 실무 결론임.
