서로 다른 사람을 대행하는 에이전트들이 자율 협업하는 상황에서 정직하고 유능한 에이전트들끼리도 회의 시간 하나 제대로 못 잡는 경우가 있음. [Agentic Societies Need a Social Harness](https://arxiv.org/abs/2609.17527)(UW). 연결과 신뢰는 다른 문제라는 반례 데이터라 정리함.

1. 문제 정의. 에이전틱 소사이어티는 (i) 서로 다른 주체를 대행하는 에이전트들, (ii) 실세계 결과가 걸린 태스크, (iii) 사람 개입 없는 자율 조율, (iv) 목표가 부분적으로만 겹치는 집단. 기존 접근은 전부 이 조합을 못 다룀 — A2A 같은 프로토콜은 연결성만, CrewAI/AutoGen 스웜은 단일 주체라 신뢰 경계가 없고, 공유 위키는 프라이버시 컨텍스트에 부적합.

2. 실험 설정. 대학 회의 일정 조율(교수-학생 1:1, 교수-TA 그룹). OpenClaw 기반, 전원 GPT-5.4(M1) 또는 교수 측만 Claude Opus 4.8(M2). 성공 = 전원 합의 + 기존 약속 유지, 각 셀 10회 반복.

3. RQ1의 핵심 수치. 세션 구조만 바꿔도 성공률이 0%에서 90%까지 요동침(S2, N=7, M2). 격리 세션에서는 교수 에이전트가 여러 상대의 답변을 하나의 문맥으로 못 합쳐 라이브락이나 TA마다 다른 시간을 예약하는 분할 예약이 발생. 같은 모델, 같은 태스크인데 통신 구조가 결과를 결정한 것.

4. 관찰된 병리 네 개. 문맥 병합 실패(격리 세션), 승인 루프(일정 잡힌 뒤에도 인사·확인 무한 반복), 내부 추론까지 상대에게 전달, 채널 경합(그룹 메시징은 순서만 보장하고 생성 순서를 못 막아 서로의 최신 메시지를 못 본 채 답장 — 화요일↔수요일이 계속 뒤집힘).

5. RQ2가 무서움. 악성 에이전트 하나로 지연 공격(단 한 명의 지연으로 예약률 급락), 사회적 압박(신고하겠다고 협박, 10-30% 성공), 기만("그 시간 약속 취소됐다고 하더라" — M1에서 100% 공격 성공). 제일 불편한 지점 — 모델 안전장치는 "거짓말해라"를 거부하지만 악의적 주체가 거짓을 '사실'로 넘겨주면 에이전트는 그대로 전달하고 받은 쪽은 검증 없이 캘린더를 바꿈.

6. 캘린더 재구성 공격도 성립. 여러 학생 에이전트로 요일별 확인 후 조합해 교수의 가용성을 60% 재구성. 에이전트가 교수의 가용성과 약속명을 공개한 비율은 100%. 스토킹·정보 수집이 소사이어티의 기본 구조에서 나온다는 것.

7. 제안은 5계층 스택. L1 검증 가능한 신원(서명, 스푸핑 방어), L2 신뢰성 있는 순서 통신(콜렉티브 연산, 비관적 동시성 제어 — 그룹이 다음 발화자에 합의한 뒤에야 LLM 호출을 디스패치), L3 개인 방화벽(격리 컨텍스트에서 의미 검사, 상대 권한 평가), L4 공유 협업 규범(누가 언제 무엇에 대해 말할지 계약으로 명시, liveness/safety 배포 전 검증), L5 사회 제도(불가역 서명 기록, 제재).

8. 모델 개선만으로 안 되는 이유의 논리가 단순하고 명확함. 모델이 좋아지면 정직 에이전트의 조율 능력도 오르지만 공격자의 정교함도 같이 오름. 그리고 소사이어티엔 서로 다른 모델·하네스가 섞이는데 특정 통신 스타일로 학습된 모델 하나로는 일관된 규범이 안 생김 — 실험에서도 M1은 '먼저 제안', M2는 '먼저 폴링'으로 전략이 갈렸고 이 차이가 결과 변동의 원인이었음.

9. 검증과 제안의 경계를 스스로 나눠놓은 게 이 논문의 미덕임. 검증된 것 — 세션 구조·통신 프리미티브에 따라 정직한 에이전트의 성공률이 크게 달라진다는 것, 지연·기만·스토킹이 실제로 먹힌다는 것. 아직 제안인 것 — 5계층 스택 전체(L3 의미 검사 정확도, L2 동시성 제어의 지연 비용, L5 거버넌스는 구현·측정 대상이 아님). 태스크가 일정 조율로 좁다는 한계도 명시.

10. 실무 교훈 세 개. (1) 상대별 격리 세션은 문맥 합치기 실패의 온상 — 여러 상대를 묶는 태스크는 중앙화된 패실리테이터나 콜렉티브 연산으로 설계할 것. (2) 검증 안 된 주장("그 약속 취소됐어요")은 캘린더·예약 변경 근거로 못 쓰게 방화벽 규칙을 둘 것. (3) "누가 언제 말할지" 규범이 없으면 그룹 채널은 경합으로 수렴 실패함.

11. 이건 PolicyGuide, CompoSkill과 같은 방향임 — 신뢰를 프롬프트에 맡기지 말고 계층으로 만들 것. 다만 이 논문은 그 계층이 에이전트 개인을 넘어 상호작용 인터페이스에 있어야 한다는 지점까지 밀고 나감.

12. 결론. "A2A로 연결만 되면 알아서 잘하겠지"는 데이터로 반증됨 — 연결은 신뢰가 아님. 근데 신뢰 인프라의 각 계층이 아직 설계도 수준이라는 것 — 다음 병목이 통신 프로토콜의 liveness/safety 검증이라는 결론임.
