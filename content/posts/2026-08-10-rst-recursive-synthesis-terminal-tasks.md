터미널 에이전트 훈련에 긴 호라이즌 작업 데이터가 필요한데 사람이 만들면 태스크당 수백~수천 달러가 든다는 게 병목임. [RST](https://arxiv.org/abs/2608.05466)는 639개 시드에서 15라운드 재귀 합성으로 37,484개 검증 태스크를 태스크당 약 $0.05에 만듦. 2~3자릿수 절감. 핵심 발상이 단숫고 재사용성이 높아서 정리함. 이전 라운드에서 만든 태스크의 참조 해답을 더 길게 확장하고, 검증기와 지시문을 다시 맞추고, 샌드박스에서 검증해서 통과한 게 다음 라운드의 시드가 되는 것.

1. 한 라운드는 네 단계임. 시드 선택(부모 다양성, 카테고리, 재작성 패밀리별 캡으로 고름), 해답 확장(참조 해답 스크립트에 설정 파일 진단, 회귀 케이스 추가, 릴리즈 노트 업데이트 같은 실행 가능한 요구사항을 추가), 검증기·지시문 정렬(검증기와 공개 지시문을 확장된 해답에 맞게 갱신, 지시문에 비공개 검증 경로가 노출되면 안 됨), 샌드박스 검증(Docker 격리에서 참조 해답을 실행해 검증기 통과 확인, 실패 시 최대 2회 피드백 수리).

![합성과 훈련의 관계](/images/2026-08-10-rst-recursive-synthesis-terminal-tasks/fig-2-p5.png)

2. 결과의 핵심은 "난이도가 실행량으로 오른다"는 것임. R1에서 R15로 가면서 중위 해답 길이는 67줄에서 374줄로 5.6배, 중위 명령어 수는 40개에서 244개로 6.1배 늘어나는데 지시문 길이는 85단어에서 122단어로 1.4배만 늘어남. 프롬프트가 길어지는 게 아니라 실제 해야 할 일이 쌓이는 것. DeepSeek-V4-Pro의 pass@4가 90%에서 2.5%로 떨어지는 걸로 난이도 상승이 확인됨. 합성 안정성도 좋아서 라운드별 합격 수가 498~572개(1,000 시드당), 검증 통과율 74.5~81.5%를 유지하고 15라운드 후에도 천장 징후가 없음.

![라운드별 패스율](/images/2026-08-10-rst-recursive-synthesis-terminal-tasks/fig-7-p9.png)

3. 재귀 합성의 고질병은 다양성 붕괴인데 여기서 안 터짐. 도메인 정규화 엔트로피가 0.821에서 0.817로 거의 변화 없고 유효 도메인 수도 11.22에서 11.09로 유지됨. 재작성 패밀리 엔트로피도 최대치 근처에서 안정적이고 R15에서 40개 중 36개 재작성 연산자가 사용됨. 다양성 캡을 시드 선택에 상시 걸어둔 효과임.

4. 실제 태스크가 어떻게 진화하는지 예시가 직관적임. JSON-diff 회귀 테스트 태스크가 시드에서 "고정 JSON 쌍에 gendiff 실행" 10줄이던 게 R1에 매트릭스 배치 실행 66줄, R5에 설정 오류 진단·수리 후 재실행 219줄, R10에 CHANGELOG에서 새 회귀 케이스 추가 264줄, R15에 설정·픽스처·기대값·테스트 일관성 수리 347줄로 자람. 핵심 목표는 그대로 두고 실행 가능한 요구사항만 누적되는 패턴. 이게 내 작업에 바로 적용되는 부분임. 내 회귀 테스트 케이스도 이렇게 키울 수 있음. 기존 케이스에 전제 조건(설정 오류 상황)과 사후 조건(일관성 검증)을 한 겹씩 입혀서 어렵게 만드는 것. 새 케이스를 외부에서 찾아오는 것보다 기존 케이스 확장이 다양성 관리도 쉬움.

5. 검증 품질 관리 기준이 배울 만함. 지시문에 없고 작업공간에서도 발견할 수 없는 요구사항을 검증기로 평가하지 않는다는 원칙. 에이전트가 풀 수 없는 태스크는 만들지 않는 것. 숫자로는 hidden-check 보호가 38.2%에서 63.5%로, 짧은 지시문 리스크가 41.6%에서 7.5%로, 비공개 테스트 경로 노출이 0.1%에서 0%로 개선됨. 요구사항 커버리지 중위값도 0.42에서 0.57로 오름. 내 테스트를 설계할 때도 "이 검증은 에이전트가 도달 가능한 정보로 판정 가능한가"를 매번 묻는 게 맞음.

6. 훈련 효과. Qwen3.5-27B에 SFT 3단계와 PPO를 돌려서 Terminal-Bench 2가 41.2%에서 49.4%, TB Hard가 22.7%에서 32.0%로 상대 향상 41%. 훈련 풀과 독립적으로 구성된 벤치마크에서도 향상이 확인돼서 오버핏이 아님.

7. 한계는 세 가지. R15 일부 태스크의 유사도 p95가 0.703까지 올라가서 중복 제거가 필요함. 프론티어 모델이 아직 다 떨어뜨리지 못해서 성능 헤드룸이 남아 있음. 합성 품질이 시드 풀의 초기 다양성에 의존함. 그래도 결론은 유효함. 좋은 시드 몇 개와 검증기, 그리고 확장 규칙이 있으면 데이터 비용 구조 자체가 바뀜. 데이터가 부족해서 못 하는 게 아니라 확장 규칙을 안 짰기 때문일 수 있다는 것.
