에이전트에게 기억 도구를 주면 에이전트는 그것을 절대 안 씀 — 114턴 동안 기억 저장소가 세팅되어 있고 도구도 연결돼 있고 가이드도 있었는데 자발적 호출이 0회였음. [Delivery, Not Storage](https://arxiv.org/abs/2607.20972)는 기억 문제를 콘텐츠 문제가 아니라 제어 평면 문제로 재정의함. 하네스 설계의 근본 질문이라 정리함.

1. 배경. 현재 코딩 에이전트는 1계층 기억만 가짐 — 문서. CLAUDE.md, 계획 아티팩트, 메모리 디렉토리는 전부 에이전트가 의도적으로 쓰고 의도적으로 다시 읽어야 하는 것들. 근데 숙련 엔지니어를 효과적으로 만드는 건 위키가 아니라 한 번도 문서화되지 않은 운영적 사실들 — "이 테스트는 저 플래그 아래에서 불안정하다" 같은. 작업의 부산물로 인코딩되고 상황이 단서가 될 때 비자발적으로 떠오르는 2계층이 에이전트에겐 없는 것.

2. 파괴적인 실험 결과. 기억 도구(remember, recall, forget)를 연결하고 작업 관련 사전 지식 4개를 저장소에 미리 세팅하고 가이드까지 줬는데 114턴 동안 호출 0회. 이 논문만의 발견이 아님 — MEMTRACK이 기억 도구 보유 에이전트의 장기 미활용을, TriggerBench가 전향적 기억(단서 나타났을 때 실행)이 회고적 기억(검색)보다 훨씬 어렵고 컨텍스트가 길수록 저하됨을 문서화했음.

3. 해법은 제어 평면임. 콘텐츠 평면은 컨텍스트에 자료를 추가하고 모델이 기억해주기를 기대하는 것 — 모델의 순응성에 의존. 제어 평면은 무엇이 윈도우에 들어가고 언제 들어가는지를 결정론적으로 결정하는 것. 기억 하나를 (내용, 종류, 트리거, 범위, 감쇠) 튜플로 표현하고 트리거는 {path, symbol, semantic, event, temporal}의 조합으로 정의함. 평가는 하네스가 결정론적으로 수행 — 모델의 판단이 주입 경로에 없음.

4. 실험 설계의 핵심 비교가 깔끔함. H vs V — 같은 4개 노트가 저장소에 있고 같은 도구와 가이드가 있는데 H는 하네스가 주입하고 V는 에이전트에게 맡김. H가 모든 카운트 기반 메트릭에서 앞섬. 그리고 주입이 참여를 촉발함 — 주입받은 에이전트는 주입 후에야 비로소 자발적 기억 도구를 쓰기 시작함. 자발적 조작은 전달 대신이 아니라 전달 때문에, 전달 후에 발생한다는 것.

5. 오탐 0건도 인상적임. 프록시 채널에서 262개 API 요청 중 241개가 주입 결정에 도달 — 5개 주입, 236개 정확히 스킵, 오탐 0건. 네이티브 훅도 40회, 35회의 감사 로깅된 트리거 평가에서 오탐 0건. 결정론적 트리거가 정밀하게 작동한다는 것.

6. 반복 컴팩션 실험이 제일 강한 증거임. 한 파워유저가 26일간 59회 컴팩션을 겪었다는 현장 데이터에서 출발 — 컴팩션은 이전 컨텍스트를 요약 압축하는데 요약되지 않은 사실은 사라짐. 10개 사실을 한 번만 제시하고 16단계 작업을 100k 토큰 컴팩션 윈도우로 돌렸더니 요약 채널은 첫 경계에서 모든 것을 드롭함. Arm N에서 108개 중 106개의 요약이 0/10. 요약기의 선택은 사실 가용성과 무관하게 신뢰할 수 없다는 것.

7. 근데 제일 흥미로운 발견은 이거임 — 메모리 계층이 없으면 에이전트가 스스로 하나를 만들어버림. Arm N의 에이전트는 금지된 셸 접근을 써서 하네스의 자체 디스크 아티팩트(JSONL 세션 파일, 도구 결과 파일)에서 10개 사실을 발굴함. 260개 셸 명령 중 38개가 팩트 발굴이었음. 기억이 에이전트에게 선택 사항이 아니라는 것 — 필요하면 어떻게든 만드는데 그 비용이 문제라는 것.

8. 주입형 스토어(Arm M)는 138번의 컴팩션을 전부 통과하며 10/10. 최종 요약은 0/10을 가졌다는 게 결정적 — 엔드포인트가 요약 채널에 의존했으면 0점이었을 것. 모든 사실이 주입으로 도착했다는 감사 증거.

9. 비용도 정직하게 보고함. Arm M이 +21% 턴, +36% 비용. 원인은 구조적 — 메모리 없이 튜닝된 하네스(스래시 가드)가 메모리를 가진 구성에 적대적으로 작동함. 메모리 추가 시 하네스 파라미터 재조정이 필요하다는 것.

10. 인지과학을 설계 원리로 쓴 점도 독특함. 인코딩은 부수적(인간은 remember()를 호출하지 않음) → 캡처는 자발성에 의존하면 안 됨. 검색은 단서 구동이고 대부분 비자발적 → 기본 주입 채널은 단서 시점. 확장 마음 기준(신뢰성, 제로 노력, 자동 보증) → 주입은 저장소를 기억으로, 조회는 참고 문서로 만듦. 같은 내용, 다른 전달, 다른 인지적 역할.

11. 한계도 솔직함. 하나의 코퍼스(Apache Camel), 하나의 작업 패밀리, 하나의 모델 패밀리. 샘플 크기가 작아 방향성을 주장. 감쇠 프로브는 감당 가능한 작은 모델로 돌림.

12. 결론. "전달이지, 저장이 아닌 것이 제품임." 에이전트가 절대 생각할 필요가 없는 기억 채널만이 신뢰할 수 있다는 것 — 어떤 걸 에이전트에게 맡기고 어떤 걸 시스템이 보장할지의 선을 기억 문제에 적용한 답임. 근데 주입 트리거 설계가 곧 사람의 일로 남는다는 것까지가 결론임.
