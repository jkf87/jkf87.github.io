에이전트로 최적화 과제를 돌릴 때마다 새 문제는 처음부터 다시 풀어야 했음. 진화 탐색으로 얻은 경험이 모델에 남지 않으니까. Evolution Fine-Tuning(EFT)은 그 궤적을 학습 데이터로 바꿔서 소형 모델 안에 경험을 박아넣는 방법임.

1. 먼저 상황 정리. GPU 커널 최적화, 조합 최적화, 수학 추측 개선 같은 과제는 정답을 계산하는 게 아니라 후보를 점수 매기고 더 나은 걸 살아남게 하는 방식으로 풀어감. AlphaEvolve 같은 시스템이 LLM을 변이 제안기로 써서 SOTA(해당 분야 최고 성능 기록)를 갱신해온 게 그 구조임.

2. 근데 여기엔 실무자 입장에서 치명적인 비용 구조가 있음. 변이 제안 품질이 떨어지면 탐색이 금방 막히는데, 그 품질을 유지하려면 보통 GPT-4급 상용 대형 모델을 계속 돌려야 했음. 과제 하나에 수백~수천 회 호출이 붙으니 예산이 터지는 지점임.

3. 그리고 경험이 재사용되지 않음. 프레임랭안에서 쌓은 "이 방향은 막혔다", "이 전략을 섞으면 뚫린다" 같은 판단이 다음 과제로 안 넘어감. 사람이라면 같은 도메인을 3년 돌리면 감이 생기는데, 에이전트는 매번 신입임.

4. EFT의 조치는 단순함. OpenEvolve 프레임랭안에 Qwen3.5-397B를 변이 연산자로 넣고 371개 최적화 과제에 탐색을 돌림. 그 과정의 "부모 해답 → 자식 해답" 전이 기록을 전부 저장해서 파인튜닝 데이터로 만듦. 172,997개 궤적에서 노이즈를 걸러 156,731개를 남겼음.

5. 이걸로 2B~9B 소형 오픈소스 모델을 미드트레이닝(사전학습과 파인튜닝 사이 규모로 대량 데이터를 추가 학습시키는 단계)하면 Finch가 됨. 핵심은 SFT가 (문제, 정답)을 외우게 하는 것과 달리, EFT는 (진화 상태, 다음 변이)를 통해 "이 상황에선 이렇게 바꿔보는 게 통했다"는 전략적 직관을 가르친다는 점임.

![EFT 개념도](/images/2026-07-02-evolution-fine-tuning-discovery-agents/fig2-eft-concept.png)

6. 결과 숫자. 과제 수를 15개에서 355개로 늘리니 학습 안 된 held-out 과제에서 평균 14.1% 향상됐음. 22개 held-out 과제에서 Finch는 베이스를 평균 10.22% 앞섬. test-time RL(추론 시점에 모델이 직접 여러 번 시도하고 반성하며 답을 다듬는 강화학습)을 얹으면 원들을 평면에 겹치지 않게 최대한 채우는 조합 최적화 문제인 원 서클 패킹 두 과제에서 SOTA와 동등해졌음.

7. 제일 흥미로운 건 전략 이동임. 경쟁 프로그래밍 문제에서 베이스 모델은 가우스-자이델(연립 방정식을 변수 하나씩 순서대로 갱신해 푸는 반복법) 한 가지를 반복하는데, Finch는 추천 시스템 도메인에서 배운 log-domain 교대 최소제곱(곱으로 얽힌 문제를 로그를 취해 덧셈 꼴로 바꾼 뒤 변수를 번갈아 고정하며 푸는 방법)이랑 수치 최적화의 Levenberg-Marquardt(경사하강과 가우스-뉴턴법 사이를 조절하며 비선형 최소제곱을 푸는 알고리즘)를 섞어 씀. 누가 조합을 가르친 적 없는데 스스로 섞음.

8. 데이터 정제 기준도 실무에 그대로 벤치마킹할 만함. 평가 결과를 못 믿는 궤적 6,321개 제외, 부모-자식 둘 다 실패한 불가복구 케이스와 좋은 부모가 깨진 파손 케이스 1,575개 제외. 점수가 오른 변이, 제자리 변이, 내려간 변이는 전부 학습에 남겼음.

![Finch Collection 구축 파이프라인](/images/2026-07-02-evolution-fine-tuning-discovery-agents/fig4-pipeline.png)

9. 회귀 변이까지 남긴 이유가 좋음. 발견 작업은 막다른 길을 탐색하고 되돌아오는 과정이 필수라서, 성공 케이스만 학습하면 모델이 되돌아오는 법을 모르게 됨. 자동화 파이프라인 실패 로그를 버리지 말고 학습 신호로 쓰라는 얘기와 같은 맥락임.

10. 내 판단으로 이걸 업무자동화에 쓰는 지점은 두 군데. 첫째, 반복적으로 돌리는 최적화·튜닝 작업(프롬프트 최적화, 파라미터 서치, 코드 최적화)의 탐색 로그를 지금처럼 버리지 말고 궤적 데이터로 축적하는 것. 둘째, 그걸로 쓰는 모델을 소형으로 내려 상용 API 비용을 끊는 것.

11. 근데 한계도 분명함. 371개 과제가 발견의 전체 폭은 아니고, teacher가 Qwen3.5-397B라 Finch의 상한선이 teacher 품질에 묶여 있음. 전략 이동이 언제 일어나는지 예측하는 것도 아직 못 함. 소형 모델로 바로 갈아타라는 결론이 아니라, 궤적 축적부터 시작하라는 결론에 가까움.

12. 그래서 실무 적용 순서는 이렇게 잡으면 됨. 지금 돌리고 있는 에이전트 탐색 작업의 transition 로그부터 구조화해서 쌓기. 쌓인 양이 수만 건 단위에 도달하면 필터링 기준(신뢰 불가 평가, 불가복구, 파손)을 적용해 정제. 그 다음에 소형 모델 파인튜닝을 검토하는 순서임.

13. 결국 이 논문이 던지는 질문은 하나임. 발견은 특권인가, 학습 가능한 능력인가. Finch의 결과는 후자임. 그리고 그 답이 바뀌면, 우리가 매번 신입 에이전트에게 처음부터 다시 가르치는 구조도 바뀌어야 함.
