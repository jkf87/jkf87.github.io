LLM 에이전트의 그래프 분석 능력을 잰 벤치마크 GABench(arXiv:2608.01684)가 나옴. 실세계 데이터셋 13개에 실행 가능한 도구 84개, 검증 가능한 정답을 가진 태스크 10,400개. 그래프 검색, 그래프 이론, 그래프 머신러닝, 그래프 개방형 QA 네 범주를 다룸. 결과는 두 가지로 압축됨. 복잡한 그래프 ML과 개방형 QA는 성공률이 대부분 40% 미만이었다는 것. 그리고 같은 모델인데 하네스에 따라 성공률이 크게 갈렸다는 것.

1. 측정 방식이 실행 기반임. 에이전트가 84개 도구를 조합해 그래프 데이터를 조회하고 노드 분류, 링크 예측, 그래프 분류 같은 ML 워크플로를 구성하고 개방형 질문에는 근거 기반 응답을 생성함. 평가 지표는 두 개. 최종 결과가 정답과 일치하는 SR과 각 단계에서 올바른 도구를 골랐는지 TSA. 답변 생성 중심의 기존 그래프 벤치마크와 다르게 계획, 도구 사용, 종단 간 성공률을 함께 잼.

![GABench 개요](/images/2026-09-02-gabench-graph-analysis-agents/fig-1-p3.png)

2. 제일 충격적인 결과가 크로스 하네스 평가임. GLM-5-turbo 하나를 도구 스키마와 시스템 프롬프트를 일관되게 유지한 채 세 하네스에 배치했더니 그래프 ML 평균 성공률이 Claude Code 87.80%, Hermes 60.22%, OpenClaw 34.94%로 갈렸음. 같은 모델에서 약 2.5배 차이. 논문은 Claude Code가 반복적인 코드·도구 실행을 지원하는 특성 때문에 다단계 워크플로가 필요한 그래프 태스크에서 유리하다고 분석함. 이 차이는 모델이 아니라 스캐폴드가 모델 행동에 미치는 영향임. 도구를 도입 검토할 때 모델 선택만으로는 불충분하고 하네스 비교가 평가 항목에 들어가야 한다는 근거가 됨.

![하네스별 성공률](/images/2026-09-02-gabench-graph-analysis-agents/table-7-p8.png)

3. 토큰 소비도 같은 방향임. Claude Code가 평균 입력 15,793토큰으로 가장 적게 쓰고 가장 높은 성공률. Hermes 29,795, OpenClaw 61,431. 가장 비싼 하네스가 가장 낮은 성적. 컴팩트한 중간 상태 표현 같은 토큰 효율 설계가 실질적으로 성능과 비용을 같이 결정한다는 것.

![하네스별 토큰 비용](/images/2026-09-02-gabench-graph-analysis-agents/table-8-p8.png)

4. 도구 호출 수와 성공률의 관계도 instructive함. 호출 수보다 호출의 질이 성공률을 결정하는 경향. 강한 모델이 더 적은 호출로 더 높은 성능을 냄. 그래프 이론 태스크의 도구 선택 정확도에서는 DeepSeek-V4-pro가 62.26~98.29로 가장 높았음. "더 많이 호출하게 하기"가 아니라 "올바른 도구를 골라내게 하기"가 개선 방향이라는 뜻.

![도구 호출 수와 성공률](/images/2026-09-02-gabench-graph-analysis-agents/fig-3-p8.png)

5. 내 해석 세 가지. 첫째, 그래프 개방형 QA는 하네스를 바꿔도 최고 성공률이 16.71%임. 정형 워크플로가 있는 그래프 ML과 달리 해석·서술이 필요한 영역은 아직 자동화 신뢰가 낮음. 이 영역 과제는 사람 검토를 전제로 설계해야 함. 둘째, 그래프 분류의 도구 선택 정확도가 42.09로 노드 분류(75.57)나 링크 예측(78.32)보다 크게 낮음. 그래프 수준 워크플로 구성이 약하다는 신호라서 이런 태스크는 도구 체인을 에이전트에게 맡기지 말고 사전에 설계해주는 게 안전함. 셋째, 하네스 실험은 도구 스키마와 프롬프트를 통제하고 돌릴 수 있다는 점 자체가 이 논문이 준 방법론적 도구. 자체 도입 검토에도 같은 통제 설계를 쓸 것.

6. 실무 체크리스트로 압축. 모델 교체 전에 하네스를 먼저 비교할 것. 입력 토큰 소비를 하네스별로 측정할 것. 그래프 수준 태스크는 도구 체인을 사전 설계할 것. 해석·서술형 과제는 자동화 상한이 낮다는 걸 전제로 사람 개입 지점을 둘 것. 반복 실행을 지원하는 하네스가 다단계 워크플로에 유리하다는 결과 하나만 기억해도 도구 선택 실수를 줄일 수 있음.
