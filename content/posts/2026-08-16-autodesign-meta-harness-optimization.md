에이전트 성능 개선의 무게중심이 모델 가중치에서 하네스로 옮겨가는 흐름이 이어지고 있음. AutoDesign은 그 완성형에 가까움. 모델을 고정한 상태에서 에이전트를 둘러싼 시스템 자체를 재귀적으로 최적화해서 롱호라이즌 멀티모달 설계 작업의 품질을 올림. 과제가 논문-포스터 변환이라는 점도 실무적임. 반복 생성·수정이 필요한 실제 디자인 워크로드이기 때문.

1. 구조가 두 개의 중첩 루프로 깔끔함. 내부 루프(design harness)는 디자이너 모듈과 크리틱 모듈이 산출물을 반복 생성·수정함. 이때 하네스는 고정. 외부 루프(meta-harness)는 훈련 태스크 셋에서 롤아웃을 수행하고 평가 결과에서 반복 실패를 식별해서 코딩 에이전트가 하네스에 유한한 업데이트를 제안함. 업데이트 대상이 산출물이 아니라 하네스라는 게 핵심 전환임. 그리고 하네스를 다섯 개 기능 컴포넌트, 컨텍스트·메모리, 도구·스펙, 실행 런타임, 오케스트레이션, 평가·피드백으로 분해해서 각 반복마다 한 컴포넌트만 업데이트함. 전면 개편이 아니라 국소 수정의 원칙이 여기도 적용됨.

![](/images/2026-08-16-autodesign-meta-harness-optimization/fig-3-p3.png)

2. 승인 게이트 설계가 신뢰의 뼈대임. 업데이트는 통과해야 반영됨. 기준은 훈련셋 성능 향상과 개발셋 성능 비하락. 그리고 평가자는 사람이 어노테이션한 참조 산출물로 초기화되고 자율 최적화 동안엔 고정됨. 자율 진화가 목표이되 목표가 되는 평가자가 흔들리지 않게 잠근 것. 보상 해킹의 위험을 구조로 막은 사례임.

3. 평가 프로토콜도 같이 제안됨. PosterBench는 5개 분야 논문 100편의 메인 트랙과 통제 실험용 미니 서브셋으로 구성. 평가 차원은 Faithfulness, Coverage, Density, Visual Evidence, Layout, Readability, Aesthetics 7개. 규칙 기반 검사, VLM(비전-언어 모델, 이미지를 보고 판정하는 모델) 판정, 하이브리드 방식을 차원별로 조합함. 자동 평가 신뢰성도 확인됨. 점수 차이가 20점 이상인 페어에서 사람 선호와의 일치율 74.4%.

![](/images/2026-08-16-autodesign-meta-harness-optimization/fig-7-p10.png)

4. 결과. 메인 트랙에서 AutoDesign(Claude Code + Claude 4.8)이 78.32점으로 1위. 동일 설정의 OpenDesign 70.36, Claude Code 단독 70.01, Claude Design 66.83. 더 중요한 건 통제 실험. 7가지 코드 에이전트·모델 구성 전체에서 DesignHarness를 부착하니 평균 54.99 → 67.39로 +12.40점. 구성별 향상이 +5.0 ~ +19.6점이니 특정 모델 조합의 운이 아니라 하네스 자체의 이식성 있는 이득이라는 뜻임.

5. 비용-성능 커브가 운영 관점에서 유용함. LongCat-2.0 구성은 포스터당 약 $0.27에 55.13점, Doubao Seed 2.1 Pro는 $2.75에 71.83점, GPT-5.5 구성은 $10.02에 81.46점. 용도에 따라 초안 대량 생성은 저가 구성, 완성도가 필요한 곳은 고가 구성으로 나누는 근거가 됨. 그리고 완전 자율 롱호라이즌 실행 1회의 실측이 도구 호출 253회, 수정 턴 11회, 40분, 비용 $3 미만. 7일 진화 트레이스에서 서브에이전트 224회 호출, 하네스 업데이트 54건. 자율 최적화가 예산 안에서 돌아간다는 실측임.

![](/images/2026-08-16-autodesign-meta-harness-optimization/fig-8-p13.png)

6. 사람 평가도 붙었음. 시스템 블라인드 유효 판정 933건 기준 Bradley-Terry(페어 비교 승률에서 선호 강도 점수를 뽑는 통계 모델) 추정 64.0%로 최고 선호. 자동 지표와 사람 선호가 같은 방향을 가리킨다는 것.

7. 내 실무 결론은 이렇게임. 첫째, 하네스를 다섯 컴포넌트로 문서화해두면 최적화 대상을 지목할 수 있음. 매번 전체 설정을 만지는 게 아니라 한 컴포넌트씩 실험할 것. 둘째, 자율 개선 루프를 돌릴 땐 평가자를 사람 어노테이션으로 초기화하고 고정할 것. 평가자까지 같이 진화하면 기준이 흐물어짐. 셋째, 업데이트 승인 조건을 "훈련 향상 + 개발 비하락"으로 둘 것. 넷째, 비용-성능 구성표를 직접 만들어서 초안용과 완성용 모델을 나눠 운영할 것. 한계도 인정함. 평가자 초기화의 선호 기준이 수렴 방향에 영향을 주고, 주 평가 도메인이 논문-포스터 단일 영역이며, 오픈 모델 구성의 절대 성능이 55.13점에 그침. 최고 성능이 아직 Claude 계열에 의존한다는 것. 그래도 "모델을 안 바꾸고 하네스 진화로 두 자릿수 향상"이라는 결과는 방향의 증거로 충분함.
