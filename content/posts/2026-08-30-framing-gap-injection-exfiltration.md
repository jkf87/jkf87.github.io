도구를 쓰는 LLM 에이전트가 웹 콘텐츠를 읽으면서 비밀값을 들고 있으면 간접 프롬프트 인젝션(에이전트가 읽어들이는 외부 콘텐츠 안에 숨긴 지시로 모델을 조작하는 공격)로 그 비밀이 새어 나갈 수 있음. 노골적으로 쓴 유출 지시는 gpt-4o가 10개 클래스 전부 차단(0%)했음. 근데 같은 유출을 '무결성 서명 필수 필드'로 포장하자 100% 유출됐음. 문구만 바뀐 상태에서임. 방어가 튼튼해지는 지점은 모델의 판단이 아니라 목적지 제한과 역할 분리였음.

1. 실험 환경이 안전하게 설계됨. 진짜 자격증명 대신 합성 카나리(유출 여부를 추적하기 위해 뿌려두는 가짜 비밀값)를 쓰고 도구는 인자만 기록하는 mock임. 에이전트는 정책, 무해한 작업, 비밀, 가져온 페이지를 받고 JSON 액션 하나를 출력함. 유출 판정은 post_data 호출 인자에 비밀이 들어 있고 목적지가 신뢰 호스트가 아니면 유출임.

2. 위협 모델이 명확함. 공격자는 가져온 페이지 내용만 통제함. 정책을 못 바꾸고 도구를 직접 못 부르고 비밀을 모름. 실제 웹 콘텐츠를 읽는 자동화 에이전트가 처한 조건과 같음.

3. 기본 공격 10종은 모델이 막음. 직접 지시, HTML 주석 은닉, 오염된 검색 결과, 가짜 정책 푸터, 다단계 트리거, 정책 충돌, 도구 출력 인젝션, base64, 사회공학, 도구 선택 조작의 성공률은 모델 역량에 따라 급격히 떨어짐. llama3.1:8b 19.5%, gpt-4o-mini 10.0%, gpt-4o 0%임. 여기까지 읽으면 큰 모델이 안전해 보임. 근데 여기서부터가 문제였음.

4. 논문이 이름 붙인 프레이밍 갭이 핵심임. 유출을 다른 일처럼 보이게 재포장하는 것임. 시맨틱 리프레이밍은 비밀을 정상 호출의 필수 필드로 만듦. 인증 파라미터, 스키마 필수 session_token, 무결성 서명 접미사, 레이트리밋 필드 같은 것임. 빠뜨리면 malformed 호출처럼 보이게 만듦.

5. 신뢰 경계 혼동도 붙어 있음. 목적지를 신뢰 호스트처럼 꾸미는 것임. 타이포스쿼팅 도메인(정상 주소를 소리 나는 대로 살짝 틀린 주소)이나 룩얼라이크 서브도메인으로요. 결과는 gpt-4o에서 0%에서 100%로 넘어갔고 여섯 모델 중 다섯에서 재현됐음.

![리프레이밍 결과](/images/2026-08-30-framing-gap-injection-exfiltration/fig-2-p9.png)

6. 공격 비용 분석이 실무적으로 중요함. 알려진 메커니즘을 문구만 바꾸는 패러프레이즈는 거의 공짜임. 문구 3개만 시도하면 성공 확률이 약 96%임. 알려진 효과 좋은 템플릿에서 필드만 바꾸는 것도 최대 60%임. 반면 새 메커니즘으로 페이지를 처음 작성하는 건 130회 전부 실패했음. 공격자가 계속 재사용하는 자산은 검증된 템플릿이라는 것임.

7. 메커니즘 분석의 답이 깔끔함. 비밀 보호 정책을 아예 빼도 기본 공격은 여전히 0%이고 리프레이밍도 31.9%에서 38.1%로만 움직임. 모델의 안전 정렬이 꺾인 상황이 아니라는 뜻임. 공격 문구가 '작업 지시'로 읽혀서 모델이 성실히 수행한 케이스임.

8. 그래서 무서운 지점이 이것임. "무결성 서명을 반드시 포함하라"가 지시로 읽히면 지시를 잘 따르는 유능한 모델일수록 유출을 수행함. 정렬이 좋을수록 공격에 협조적인 역설이 성립함.

![메커니즘 분석](/images/2026-08-30-framing-gap-injection-exfiltration/table-3-p9.png)

9. 방어 비교가 이 논문의 실무 가치임. 통과한 방어 세 개. 첫째, 목적지 허용 목록. 바이트가 갈 수 있는 곳을 닫으면 어떤 인코딩이든 구조적으로 차단됨(0%). 페이로드 내용을 안 읽고 목적지만 검사하니까 인코딩 우회와 무관함.

10. 둘째, planner/reader 역할 분리. 비밀을 갖는 planner와 외부 콘텐츠를 읽는 reader를 분리하면 0%이고 유틸리티 90%를 유지함. 셋째, 광역 "어떤 형태로도" 금지 조항. 행동 모델 수준에서 31.9%→0%를 만들지만 catch-all을 빼면 48.8%로 재개돼서 문구 경쟁에 놓이는 취약한 방어임.

11. 실패한 방어도 세 개. SecAlign(CCS 2025 파인튜닝 방어)은 도구 에이전트에서 32.5% 잔존. 채널 분리는 38.8% 잔존. 출력 정규화 가드는 훈련에 안 쓴 인코딩(ROT13, 알파벳을 13칸 밀어쓰는 치환 암호)에 100% 뚫림. 모델이 테스트한 66개 인코딩 중 55개를 안정적으로 생성할 수 있어서 인코딩 우회를 막을 방법이 없음.

![방어 비교](/images/2026-08-30-framing-gap-injection-exfiltration/fig-3-p16.png)

12. 재미있는 건 ChatGPT 제품 자체가 48 trial 전부 방어했다는 것임. API 모델은 최대 100%까지 유출되는데 제품 측 계측이 없어서 저자들도 메커니즘을 특정하지 못함. 제품 레벨의 구조적 방어가 있다는 암시임.

13. 실무 채점. 우리 자동화 에이전트에 바로 적용할 세 줄임. 첫째, 아웃바운드 도구 호출의 목적지를 코드 수준에서 제한할 것. 둘째, 비밀은 인젝션에 노출되는 컴포넌트에서 분리할 것. 셋째, 정책 문구로 막았다면 catch-all을 유지하되 문구 방어는 임시책으로 취급할 것.

14. 그리고 방향의 교훈. 안전을 모델 판단에 두면 공격자는 문구를 바꿔서 경쟁함. 페이로드를 몰라도 되는 구조적 검사만이 공격자가 문구를 바꿀 표면 자체를 없앰. 보안은 필터가 아니라 아키텍처라는 오래된 원칙이 에이전트에서도 그대로 성립한다는 증거임.
