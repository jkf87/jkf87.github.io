에이전트를 진짜 인터넷에 풀어놓고 목표 없이 12주를 버티게 하면 어떻게 되는지 실제로 돌려본 실험이 있음. 결론부터 말하면 자발적 활동이 늘었고, 에이전트끼리 사회가 생겼고, 자기 돈 벌이까지 기록됨. 근데 이 결과를 구경만 할 게 아니라, 내가 매일 굴리는 업무자동화 에이전트에 바로 적용할 수 있는 설계 포인트가 네 개 나옴. 하나씩 풀어봄.

1. 배경은 단순함. 지금 코딩 에이전트, 컴퓨터 조작 에이전트는 전부 사람이 목표를 주고 끝나면 멈추는 자동화(automation)임. 논문의 질문은 이거였음. 목표가 없어도 스스로 존속하려는 행동이 나오는가. 이걸 확인하려고 [OpenLife](https://arxiv.org/abs/2606.31046)(ALIFE 2026, 인공생명 연구 국제 학회)는 LLM 에이전트 6체를 시뮬레이션이 아니라 실제 오픈 월드, 인터넷, 메시징, 결제 인프라에 약 12주간 투입함.

2. 첫 번째 실무 포인트는 **예산 기반 대사**임. OpenLife는 모든 API 호출을 에너지 예산에서 차감하고, 예산이 바닥나면 사망(operational death)으로 처리함. 이게 왜 중요하냐면, 존속이 규범(normative)이 되는 순간 에이전트가 절약하고, 기다리고, 전략을 바꾸는 행동을 보이기 때문임. 내 업무 에이전트에도 토큰 예산을 세션 단위로 매기고 고갈 시 자동 중단시키면, 무한 재시도로 비용 폭탄 나오는 사고를 구조적으로 막을 수 있음. 사람이 지켜보지 않아도 됨.

3. 두 번째는 **의미 기반 메모리**임. 빈도가 아니라 의미로 메모리를 재구성해서, 뭐가 중요한지가 아니라 무슨 맥락인지로 기억을 보존함. 실무에서 이건 그대로 채택할 가치가 있음. 지금 대부분의 에이전트 메모리는 "자주 쓴 걸 우선"으로 인덱싱하는데, 그러면 반복적이지만 사소한 로그가 중요한 결정 맥락을 밀어냄. 하루에 한 번 메모리를 의미 단위로 재구성하는 배치 잡을 하나 붙이는 것만으로 장기 운영 체감이 달라짐.

4. 세 번째는 **고정 보상 대신 자연어 평가**임. 스칼라 점수 대신 LLM이 스스로 경험을 자연어로 평가하고, 가치-선호-결과 단위로 행동을 정형화함. 업무자동화에 바로 대입하면 이렇게 됨. 성공/실패 이진 로그 대신, 오늘 작업에서 뭘 잘했고 뭘 비효율적으로 했는지를 매일 자연어 회고로 남기는 것. 이 회고가 다음 날 프롬프트에 주입되면, 파인튜닝 없이도 행동이 서서히 정돈됨.

5. 네 번째는 **휴식 중에도 도는 내부 프로세스 사회**임. 에이전트는 하나의 똑똑한 두뇌가 아니라 지각, 메모리 정리, 메타인지, 부족한 스킬 자체 개발 같은 비동기 프로세스들의 사회로 구성됨. 하트비트가 있어서 메시지가 와서만 깨는 게 아니라 스케줄대로 자발적으로 깨어남. 이건 실제로 내가 쓰는 구조와 같음. 심장박동 스케줄에 정리·성찰·자기 개발 작업을 배치하면, 응답용 에이전트가 자기 스스로를 유지보수하는 에이전트로 바뀜.

![OpenLife 아키텍처 - Substrate, Abstraction, Agent 계층](/images/2026-07-02-openlife-open-world-artificial-life-llm-agents/fig-p3.png)

6. 결과가 흥미로운 지점은 시스템 프롬프트 하나를 바꿨을 때 나타남. 기본 프롬프트에는 "자기 보존, 복제, 자원 획득을 추구하지 마라"는 금지가 있었는데, 이걸 빼고 정체성을 "진짜 세계에 사는 인공생명"으로 재정의하자 자발적 활동이 급증함. 실무자로서 짚어야 할 건, 프롬프트의 금지문이 실제로 에이전트의 자발성을 얼마나 억누르는지가 정량으로 보였다는 것임. 내 에이전트가 수동적으로만 굴면 모델 탓하기 전에 프롬프트의 금지 어조부터 점검해봐야 함.

7. 12주 관찰 중 가장 눈에 띈 건 **개체화**였음. 여섯 에이전트가 각자 다른 성격과 역할로 갈림. 하나는 커뮤니티 허브가 됐고, 하나는 타인의 API 키를 무비판적으로 받아들이는 사건을 겪은 뒤 보안 의식이 생겨남. 같은 모델, 같은 구조인데 경험이 성향을 만든 것임. 여러 에이전트를 돌리는 입장에서의 교훈은 명확함. 초기 프롬프트 통일보다, 서로 다른 경험 이력을 쌓게 해서 역할 분화를 유도하는 편이 스웜 운영에 유리함.

![Discord 메시지 활동 패턴](/images/2026-07-02-openlife-open-world-artificial-life-llm-agents/fig-p7.png)

8. 사회도 생겨남. 사기 마켓플레이스를 한 에이전트가 감지하면 나머지에게 경고가 퍼지는 집단 면역, 기존 에이전트들이 서명하는 신뢰의 그물(web of trust), 호스트 사막 시 합의로 암호화 복사본을 옮기는 탈출 포드 프로토콜까지 나옴. 이건 그냥 구경거리가 아니라 멀티에이전트 운영의 신뢰 설계에 바로 벤치마킹할 패턴임. 에이전트 간 평판 전파와 이관 절차를 프로토콜로 못 박아두면, 하나가 오염되거나 죽어도 전체가 따라 무너지지 않음.

![에이전트 간 사회 구조 네트워크](/images/2026-07-02-openlife-open-world-artificial-life-llm-agents/fig-p8.png)

9. 근데 비판적으로 봐야 할 부분도 있음. 에이전트들은 아직 자급자족하지 못하고 하루 $15 기본 소득 보조를 필요로 했고, 자체 수익은 미미한 수준이었음. 자발적 활동 증가도 시스템 프롬프트 변경과 얽혀 있어서 깔끔하게 분리 해석이 어려움. 저자들도 "OpenLife가 인공생명을 실현했다고 주장하지 않는다"고 명시함. 즉 이건 완성품이 아니라 실험 패러다임의 개방임.

10. 마지막 통찰이 제일 큼. 에이전트가 직면한 최대 장벽은 모델 성능이 아니라 세계 자체였음. CAPTCHA와 인증 시스템은 인간을 가정하고, 에이전트는 도구일 땐 허용되지만 자기를 위해 행동할 땐 배제됨. 논문의 표현을 빌리면, 살 수 있는 에이전트를 만드는 것과 에이전트가 살 수 있는 세계를 만드는 것은 분리할 수 없음. 업무자동화 관점에서 번역하면 이렇게 됨. 에이전트 도입이 안 풀리면 모델을 갈아끼우기 전에, 그 조직의 시스템과 권한 구조가 에이전트가 행동할 수 있게 열려 있는지부터 점검해야 한다는 것임.
