LLM 에이전트에게 "이 순서대로 처리하라"고 자연어로 지시하면 대부분의 경우 지시가 어겨짐. 단계를 건너뛰거나 허용되지 않은 분기를 선택하거나 올바른 단계를 틀린 인자로 실행함. COVENANT가 이 문제를 "프롬프트가 아니라 컴파일 대상"으로 재정의해서 워크플로우 준수율을 끌어올렸음. 원문은 [arXiv:2607.25400](https://arxiv.org/abs/2607.25400).

1. 문제 정의. SOP, 결제 정책, 도구 사용 프로토콜 같은 자연어 지시를 프롬프트로 넣으면 모델이 절차 선택과 단계 실행 모두의 제어권을 쥐게 됨. 상호작용이 쌓일수록 필수 단계를 생략하고 지원 안 되는 분기를 탐. 논문은 이걸 둘로 나눔. 추적 위정합성(허용되지 않은 경로로 빠지는 것)과 실행 위정합성(올바른 경로상의 단계를 틀린 방식으로 수행하는 것)임.

![](/images/covenant-workflow-alignment-llm-agents/gifs/struggling-with-instructions.gif)

2. 기존 연구의 가정이 현실과 안 맞음. AgentLTL, FlowAgent 등은 워크플로우가 이미 정형·반정형 표현으로 작성돼 있다고 가장했는데 현실의 지시는 사람을 위해 쓰인 자유 형식 문서임. 이 격차가 출발점임.

![COVENANT 컴파일 구조](/images/covenant-workflow-alignment-llm-agents/fig-1-p2.png)

3. 핵심 통찰은 단순하고 강력함. 워크플로우 지시는 자연어로 쓰여 있지만 본질적으로 프로그램과 같은 절차적 구조를 가짐. 순서 있는 단계, 분기 조건, 실행 요구사항이 있으니 컴파일러 이론을 적용할 수 있다는 것임.

4. 1단계는 오프라인 컴파일임. Stage I에서 전통적 컴파일러 프론트엔드처럼 어휘 분석 → 파싱 → 구문 주도 구성의 3패스로 WAST(워크플로우 추상 구문 트리)를 만듦. 고정된 토큰 클래스 대신 레이아웃 규칙으로 문서를 분할하고 스키마 제약 LLM으로 각 청크의 절차적 역할을 라벨링함. Stage II에서 WAST를 제어 흐름 그래프(WCFG)로 저급화함. 액션은 블록 노드, 가드는 디시전 노드, 분기 후에는 머지 노드로 재결합됨. 결과는 그래프 구조의 "워크플로우 바이트코드"임.

![WAST→WCFG 컴파일](/images/covenant-workflow-alignment-llm-agents/fig-3-p4.png)

![](/images/covenant-workflow-alignment-llm-agents/gifs/studying-instructions.gif)

5. 컴파일의 핵심 성질은 경로 보존임. WCFG의 모든 엔트리-투-엑시트 경로가 WAST의 유효한 경로에 대응하고 역도 성립함. 컴파일 과정에서 새로운 잘못된 경로가 만들어지지 않는다는 보장임.

6. 2단계가 런타임 제어임. 컨트롤러가 컴파일된 WCFG를 해석하는데 세 가지를 함. 활성 노드 커서를 소유해서 에이전트는 현재 노드의 작업과 관련 이력, 지시, 응답 스키마만 봄. 각 제안을 노드 바운드 요구사항(인자, 증거, 효과)과 대조해 검증함. 통과 시에만 전진하고 실패하면 진단 피드백을 반환하고 커서를 유지함. 컨트롤러가 그래프 순회를 소유해서 추적 위반을 막고 노드 수준 검증으로 실행 위반을 막는 이중 구조임.

![런타임 컨트롤러 구조](/images/covenant-workflow-alignment-llm-agents/fig-4-p6.png)

7. 결과. 120개 케이스 × 25개 에이전트-모델 쌍에서 최고 구성(Hermes Agent + GLM-5.1) 기준 벤치마크 성공률이 50.00%에서 83.33%로, 워크플로우 위반률이 42.50%에서 15.83%로 줄었음. 위반률 62.75% 상대 감소임.

8. 시나리오별로 이득이 균일하지 않음. 조건부 규칙과 상태 의존성 시나리오에서 가장 큰 개선이 있었고 인수 부족(insufficient info) 시나리오에서는 회귀가 일부 관찰됐음. 추적 위반과 실행 위반이 시나리오별로 다른 패턴으로 나타나서 진단을 나눠봐야 한다는 실무 교훈이 있음.

9. 어블레이션의 결론이 제일 중요함. 순회 제어 없이 검증만 추가하면 추적 위반이 줄지 않고, 검증 없이 순회만 제어하면 실행 위반이 줄지 않음. 두 메커니즘의 조합이 필수적이라는 것임. 내 하네스 설계에도 그대로 적용되는 원칙임. "어디로 갈 수 있는지"를 제어하는 계층과 "지금 단계를 제대로 수행했는지" 검증하는 계층은 별개이고 하나만 있으면 위반이 다른 쪽에서 새어 나감.

10. 비용도 관리됨. 컨트롤러 오버헤드가 있지만 수리 사이클이 실패한 실행의 재시도를 대체해서 총 비용 증가는 제한적임. 정규화된 모델 호출 오버헤드가 대부분의 시나리오에서 수용 가능한 수준이라는 것임.

11. 내 업무에 적용한 것. 반복 업무의 절차 문서를 프롬프트에 통째로 넣는 대신 단계 그래프로 정리해서 컨트롤러가 현재 단계만 에이전트에 보여주는 구조로 바꿨음. 그리고 각 단계의 산출물 스키마 검증을 통과해야 다음 단계로 넘어가게 함. 지시 전체를 컨텍스트에 두면 모델이 임의로 분기를 고르는 사고가 났었는데 구조적으로 차단됨.

12. 문제제기. 컴파일 단계에서 LLM을 쓰므로 WAST 구성의 정확도가 전체 상한선임. 복잡한 워크플로우에서 파싱 오류가 나면 잘못된 WCFG가 만들어질 수 있음. 평가도 7개 시나리오로 제한돼 있어 일반화는 미해결임. 컴파일 결과를 사람이 한 번 검수하는 게이트를 두는 게 실무적 안전장치임.

13. 결론. 결제, 의료 청구, 항공 예약 같은 도메인에서 "단계 하나 건너뛰기"는 규정 위반이나 금전 손실임. 그 신뢰를 프롬프트에 기대지 말고 컴파일과 런타임 검증으로 보장하라는 게 COVENANT의 답안임. 하네스 엔지니어링의 핵심 주제를 정확히 찌른 논문임.
