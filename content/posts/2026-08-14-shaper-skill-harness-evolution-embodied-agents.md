모델은 그대로 두고 스킬과 하네스만 고쳤더니 embodied 에이전트 성능이 확 오름. Microsoft Research의 [SHAPER](https://arxiv.org/abs/2608.11350)(동결된 모델 위에서 텍스트 스킬과 Python 하네스 코드만 피드백으로 진화시키는 프레임)는 VLM 플래너(이미지·텍스트를 같이 보는 비전-언어 모델)와 VLA 실행기(비전 입력을 로봇 행동으로 바꾸는 모델)를 동결한 채 텍스트 스킬과 Python 하네스 코드만 롤아웃 피드백으로 진화시킴. 진화 1회당 API 비용이 $2.25~$2.83인데 SFT(정답 예시 데이터로 가중치를 미세조정하는 지도학습)를 넘어서는 성적을 냄. 앞서 정리한 하네스 진화 계열 연구의 embodied 버전이면서 비용 구조가 결정적으로 다름.

1. 시스템 관점이 깔끔함. 에이전트를 네 컴포넌트로 쪼갬. 상위 계획을 세우는 VLM 플래너(동결), 로우레벨 액션을 실행하는 VLA 액터나 환경 API(동결), 플래너 프롬프트에 들어가는 텍스트 절차 지시인 스킬(최적화 대상), 컨텍스트를 조립하는 build_context() Python 함수인 하네스(최적화 대상). 파라미터는 얼리고 비파라미터 부분만 고침. 어디를 움직일지 명확하게 그어둔 것이 좋은 설계의 출발이라는 걸 다시 보여줌.

2. 진화 방식의 핵심은 "텍스트 그래디언트"(실행 결과를 되돌아보며 어떻게 고칠지 텍스트로 쓴 개선 방향)임. 멀티모달 궤적 전체를 옵티마이저에 보여주면 컨텍스트가 폭발하니까, 각 턴의 before/after 관찰 쌍을 턴별 판정으로 압축하고, 에피소드 단위 요약으로 다시 압축하고, 배치 통계와 핞쳐서 텍스트 그래디언트를 만듦. 동결된 모델을 옵티마이저 프롬프트로 호출해서 새 스킬/하네스를 제안받고, 샌드박스 검증과 검증 세트 평가를 거쳐 Top-K 빔을 유지함. 그리고 순서가 있음. 스킬 먼저 진화, 선택된 스킬을 고정한 다음 하네스 진화의 2단계. 내 경험과도 맞음. 프롬프트가 안정된 다음에 코드를 고치는 순서가 역방향보다 오류가 적음.

![SHAPER 개요](/images/2026-08-14-shaper-skill-harness-evolution-embodied-agents/fig-2-p4.png)

3. 결과가 두 벤치마크에서 일관됨. VLABench(언어 지시를 받아 가상 환경에서 로봇 조작을 수행하는 벤치마크)에서는 테스트타임 스케일링(실행 시점에 샘플을 여러 번 뽑아 고르는 방식)(MG-Select, VOTE)이 direct execution보다 못 했는데 스킬+하네스 진화는 +11.25pp를 만들어냄. 샘플링을 많이 한다고 안정적 향상이 안 나오는 환경에서는 진화가 답이라는 것. 특히 분포 이동이 클수록(C3, 다른 태스크 형태) 개선 폭이 커져서 Seed 40.0%에서 Full SHAPER 50.0%가 됨. ESI-Bench(능동적 시야 이동으로 증거 수집)에서는 동결된 27B가 하네스 진화까지 더하니 GPT-5 Passive 참고치(40.3%)를 42.9%로 넘어섬.

4. 하네스가 바뀌면 무엇이 달라지는지 구체 사례가 좋음. 거울 반사 카테고리가 20.0%에서 60.0%로 오른 원인은 이랬음. 기존 하네스는 최근 5개 뷰만 유지해서 초반에 본 거울 속 대상이 사라지고, 에이전트가 30스텝 동안 왔다갔다 하다 "모르겠다"를 냈음. 진화된 하네스는 전체 이력에서 의미 있는 프레임 3개를 선택하고 결정론적 crop을 추가하고 1스텝의 거울 이미지를 7스텝의 후보 3개와 비교해서 정답을 냄. 즉 컨텍스트 관리 정책 하나가 정확도를 세 배로 만든 것. 하네스가 "래퍼"가 아니라 능력의 일부라는 증거임.

![ESI-Bench 하네스 진화 사례](/images/2026-08-14-shaper-skill-harness-evolution-embodied-agents/fig-4-p9.png)

5. 스킬 진화의 실제 효과도 구체적임. Seed 스킬은 "관찰하고 서브태스크 내라"가 전부였는데 진화된 스킬은 태스크 의도를 짧은 정규 명령으로 매핑하고, 턴마다 진행 상태를 성공/실패/부분/정체로 분류하고, 같은 명령 반복을 감지해서 다른 명령 형태로 전환하고, VLA 액터의 명령 분포에 맞춰 스텝 예산을 조정함. 실제 에피소드에서 seed는 같은 retrieval 명령을 반복하다 400스텝 한도에 걸렸고 진화된 스킬은 부분 성공 감지 후 pick-up으로 전환해서 297스텝에 완료함. "반복 감지 → 전환" 규칙은 로봇이 아니라 내 텍스트 에이전트에도 필요한 규칙임.

6. 비용 구조가 테스트타임 스케일링과 근본적으로 다름. 진화는 한 번에 $3 미만이고 끝나면 스킬과 하네스는 고정됨. 배포 횟수가 늘어도 per-deployment 비용이 0임. 테스트타임 스케일링은 매 실행마다 비용이 선형으로 붙음. 그래서 같은 예산이면 샘플 여러 번 뽑는 것보다 한 번 진화시키는 게 장기적으로 압도적으로 쌈. 내 작업 자동화에서도 "매번 여러 번 시도하게 하는" 설계보다 "한 번 스킬을 다듬는" 설계가 비용상 유리하다는 것과 같은 구조임.

7. 한계도 인정함. cross-embodiment transfer(다른 로봇 형태로 전이)와 실물 로봇 검증은 아직이고 두 벤치마크 모두 시뮬레이션임. 근데 결론은 유효함. 파인튜닝을 못 하는 상황에서 성능을 올리는 경로는 스킬과 하네스의 체계적 진화이고, 그 비용은 생각보다 훨씬 쌈. 어디를 동결하고 어디를 진화시킬지 먼저 그리는 것이 첫 단계라는 것.
