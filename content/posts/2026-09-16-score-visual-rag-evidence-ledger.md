Visual RAG에서 성능 병목의 상당 부분은 검색 품질보다 답 생성 직전의 증거 보존과 정리에서 나온다는 게 이 논문의 핵심 주장임. SCoRE(Selection and COnsolidation for Robust Evidence)는 탐색 중 관련 관찰만 텍스트 증거 장부에 남기고 답 생성 직전에 원본 페이지 이미지를 다시 불러와 걸러내고 순서를 세우는 에이전트 루프임. 원문은 [arXiv:2609.15800](https://arxiv.org/abs/2609.15800).

![증거를 뒤지는 중](/images/2026-09-16-score-visual-rag-evidence-ledger/gifs/evidence.gif)

1. 배경 문제 둘. 첫째, 증거 분포가 고르지 않음. 답이 한 페이지의 작은 영역에 몰려 있거나 여러 페이지에 흩어져 있음. 둘째, 증거 정리가 암묵적임. 기존 에이전트는 탐색 궤적 그대로나 압축된 텍스트 메모리로 답을 만들어서 탐색 노이즈가 답에 섞임. VRAG-RL(시각 관찰을 궤적에 그대로 쌓아두는 강화학습 기반 Visual RAG 에이전트)은 시각 관찰을 궤적에 쌓고 VISOR(관찰을 텍스트 장부로 변환하는 Visual RAG 에이전트)는 텍스트 장부로 변환하는데 둘 다 답 생성 직전에 원본 이미지를 재구성해 순서까지 세우는 단계가 없음.

![비주얼 증거의 두 도전 과제(논문 Figure 1)](/images/2026-09-16-score-visual-rag-evidence-ledger/fig-1-p1.png)

2. 방법. 하나의 에이전트 루프에서 텍스트 증거 장부 L과 상호작용 이력 H 두 개의 상태를 유지함. 각 턴마다 observe(현재 페이지 요약), relevant(관련성 이진 판단), action(search/bbox/consolidate) 세 필드를 출력함. relevant=yes인 관찰만 원본 페이지와 bbox 좌표 소스 포인터와 함께 장부에 저장함.

![SCoRE 에이전트 루프 개요(논문 Figure 2)](/images/2026-09-16-score-visual-rag-evidence-ledger/fig-2-p3.png)

3. 토큰 절약 장치가 실무적임. 원본 시각 컨텍스트는 최근 2턴만 유지해서 이미지 토큰 소비가 궤적 길이에 비례해 늘어나는 걸 막음. 관련 없는 관찰은 창이 밀리면서 버려짐. 오래된 증거는 텍스트 요약+포인터로 유지하는 이 분리 구조는 긴 탐색 에이전트 전반에 적용할 만함.

![근거 장부에는 영수증이](/images/2026-09-16-score-visual-rag-evidence-ledger/gifs/paper-trail.gif)

4. consolidate 액션이 핵심 차별점임. 탐색이 끝나면 장부가 참조하는 원본 페이지 이미지를 다시 불러오고 여러 장이면 걸러내고 논리적 순서로 재배열해 답 생성에 넘김. 최종 답의 각 주장이 어떤 장부 항목에 근거하는지 인덱스로 연결해서 클레임-이미지 근거 연결도 남김. 탐색의 시행착오와 최종 추론이 분리되는 구조임.

5. 학습은 두 단계. 콜드스타트는 교사 모델 궤적 중 정답이면서 골드 페이지 전체가 최종 장부에 담긴 궤적만 남겨 SFT(정답 예시로 가르치는 지도학습)함. 이후 GRPO(같은 문제의 여러 답을 서로 비교해 학습하는 강화학습 알고리즘)로 다중 턴 RL을 돌리는데 보상이 세 성분임. cov는 골드 페이지 중 최종 장부에 남은 비율(재현율), cmp는 장부 중 골드 페이지 비율(정밀도), r_ans는 정답 여부임. 보상식에서 cov=1일 때만 cmp와 r_ans가 활성화되고 cov<1이면 벌점을 받음. 골드 페이지를 버리고 cmp만 높이는 게임을 막는 구조임.

6. 결과. Qwen2.5-VL-7B 기준 SlideVQA(슬라이드 이미지로 답하는 질의응답 벤치마크) 77.16%(이전 최고 72.37%), ViDoSeek(문서 내 세부 정보 탐색 벤치마크) 75.31%, MMLongBench(긴 다중 페이지 문서 이해 벤치마크) 31.52%로 세 벤치마크 모두 최고임. 멀티홉에서 약 9점(53.62→62.26)이 올랐는데 여러 페이지에 흩어진 증거를 하나로 모으는 과정이 성능 차이를 만든다는 해석과 연결됨.

7. 검색 행동 분석이 주장을 뒷받침함. ViDoRAG(고정된 검색 파이프라인 기반 Visual RAG 시스템)는 완전성 91.3%를 내지만 고정 10장 검색으로 쿼리당 노이즈 이미지 8.81장을 물고 감. VISOR는 1.29장까지 줄이는데 SCoRE는 0.16장임. "더 많이 검색"보다 "고르고 정리"가 정확도를 만든다는 게 수치로 확인됨. ViDoRAG 대비 토큰 6.7배 절약하면서 정확도는 13점 높음.

![검색·통합 행동 분석(논문 Table 3)](/images/2026-09-16-score-visual-rag-evidence-ledger/table-3-p6.png)

8. 제거 실험의 통찰이 제일 재밌음. 학습 전에는 통합 제거가 더 아픔(-9.9). 관련성 판단이 서툴러서 노이즈가 장부에 쌓이니 출구에서 걸러주는 통합이 필수였음. 학습 후에는 반대로 관련성 판단 제거가 더 아픔(-4.9). 입구에서 장부를 깨끗하게 유지하는 능력을 학습했기 때문임. 노이즈 제거 책임이 출구에서 입구로 이동했다는 분석임. 그리고 콜드스타트 SFT가 55.17→75.62로 대부분의 향상을 만들고 RL은 77.16까지 마무리만 함. RL은 이미 생긴 정책을 다듬는 단계라는 해석임.

![조직 모듈 어블레이션(논문 Table 2)](/images/2026-09-16-score-visual-rag-evidence-ledger/table-2-p6.png)

9. 백본 크기 효과도 참고할 만함. 프롬프팅만 하는 조건에서 이득은 7B에서 +18.19로 최대이고 122B에서 +2.21까지 줄어듦. 큰 모델은 다중 이미지 추론과 노이즈 처리를 내부에서 어느 정도 해내기 때문임. 3B는 통합 단계 실행 자체가 불안정해서 장부만 쓰는 변형이 오히려 나음. 명시적 구조의 이득은 중간 규모 백본에서 가장 큼.

10. 내 해석으로 옮겨 쓸 수 있는 부분 셋. 첫째, 텍스트 RAG에도 그대로 적용 가능한 패턴임. 검색 후 컨텍스트에 문서를 쌓기만 하는 구조라면 답 생성 직전에 재선택-재정렬 단계를 하나 넣는 걸 먼저 시도할 만함. 내 자동화의 검색 단계도 후보를 그대로 쌓는 구조라 이 패턴을 붙여볼 계획임. 둘째, 증거 커버리지를 보상의 게이트로 쓰는 설계는 다른 에이전트 RL에 복사 가능함. 정밀도 보상만으로는 증거를 버리는 게임이 생기는데 커버리지 완전 조건이 그 구멍을 막음. 셋째, 클레임-근거 인덱스 연결은 검증 가능성을 높이는 값진 부가물임.

11. 문제제기. Visual RAG에서만 검증됐고 코드 링크가 명시되지 않았음. LLM-as-judge 정답 보상의 편향 가능성이 남아있고, 3B 이하 백본에서는 구조 실행 자체가 불안정해서 적용 조건을 먼저 봐야 함.

12. 결론. 검색이 아니라 정리가 병목임. 입구 관련성 필터, 텍스트 장부와 포인터, 출구 통합이라는 세 층으로 증거를 다루면 노이즈가 답에 새어들어가는 걸 구조적으로 막을 수 있음.
