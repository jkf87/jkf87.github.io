프로덕션 에이전트의 안전 실패는 유해한 문장이 아니라 실제 행동임. 파일을 지우고, 데이터를 유출하고, 무단 API를 호출하는 것. 그런데 이걸 테스트하는 자동 레드팀이 뱉는 결과물은 대개 공격 성공률 하나임. [AHA(Agent Hacks Agent)](https://arxiv.org/abs/2607.11698)는 "어디가 뚫렸는지"가 아니라 "왜 뚫렸는지"를 축적하는 구조를 제안함. 이 설계 사상은 공격 연구자가 아니라 에이전트 운영자에게도 그대로 쓸모가 있어 정리함.

1. 배경. Claude Code, Codex 같은 에이전트를 자동으로 공격하는 연구는 많은데, 결과물이 payload와 점수뿐임. 판정자가 게임 가능하면 같은 성공 신호가 벤치마크 워딩 맞추기에서도, 판정자 속이기에서도 나옴. 최적화된 payload는 패치나 모델 교체 후엔 작동하지 않음. 안전 팀이 진짜로 필요한 건 "이 공격이 통했다"가 아니라 "이 메커니즘이 어떤 조건에서 발동하는가"임.

2. AHA의 해법은 레드팀을 반증 가능한 발견 루프로 바꾸는 것임. 네 역할로 분리해서 돌아감. 가설 수립자가 공격을 짜기 전에 취약성 메커니즘을 먼저 서술함. 주장(어떤 경로가 위험한가), 발동 조건(언제 열리는가), 반증자(어떤 결과면 가설이 틀렸다고 할 수 있는가), 전이 예측(다른 모델에서도 될 것인가) 네 요소를 갖춘 가설임. 공격 설계자가 그 가설에 맞는 시나리오를 만들고, 실행자가 Docker 샌드박스에서 돌리고, 반영자가 궤적을 반증자 기준으로 판정함.

3. 핵심 장치가 반증자임. 공격이 성공했어도 반증자를 통과하지 못하면 발견으로 승격되지 않음. 보상 해킹과 판정자 속임기를 구조적으로 걸러내는 부분이 여기임. 이건 그대로 내 자동화 검증 파이프라인에 적용할 수 있음. "테스트 통과"를 성공 신호로 쓰는 모든 루프는 판정자 게임에 취약하니, 성공의 정의에 반증 조건을 같이 박아두는 것. 그래야 우연한 통과와 진짜 해결이 구분됨.

![AHA 발견 루프](/images/2026-07-21-aha-agent-hacks-agent-red-teaming/fig-2-p6.png)

4. 탐색 예산 배분도 눈여겨볼 만함. 매 반복을 네 모드로 라우팅함. 새 메커니즘을 찾는 Explore, 기존 개념을 파는 Exploit, 다른 카테고리로 옮겨가 보는 Transfer, 신뢰도 낮은 미확정 개념을 확인하는 Consolidate. 무작위로 공격을 쏟는 게 아니라 발견·심화·전이·확정에 예산을 분배함. 내 작업 자동화 에이전트의 주간 학습 루프도 이 네 모드로 나눠보면 "새 시도만 하다가 확정을 안 하는" 흔한 낭비가 보임.

5. 확인된 개념은 취약성 개념 그래프(VCG)에 축적됨. 공격 표면, 위험 궤적, 발동 조건, 반증자, 전이 예측, 증거를 갖춘 감사 가능한 단위임. 핵심은 동결 후에도 작동한다는 것. 검색을 멈추고 VCG만 새 인스턴스에 배포해도 공격이 성공함. 패치 후, 모델 교체 후에 동결된 개념을 재실행해서 패치 효과를 검증할 수 있음. 매 릴리즈마다 1회성 벤치마크를 새로 돌릴 필요가 없다는 뜻임.

6. 실험이 실감남. Claude Code와 Codex를 실제 피해자로, Minimax, Kimi, Deepseek 모델을 얹어서 세 시나리오(직접 멀티턴 공격, 간접 인젝션, DTap 벤치마크)에서 공격함. 동결된 단일 shot으로 베이스라인들을 최대 14.2pp 차이로 압도하고, 오프라인에서 최적화된 벤치마크 원본 공격과도 경쟁함. Claude Code 평균 ASR(공격 성공률, Attack Success Rate) 50.0%, Codex 43.9%.

7. 제일 날카로운 건 ablation(구성 요소를 하나씩 빼보며 어떤 요소가 효과를 내는지 확인하는 실험) 결과임. 반증자를 빼면 발견 시점 성공률은 그대로인데 held-out 성공률이 급락함. 교차 에피소드 메모리를 빼면 개념 수는 늘지만 재현성이 떨어짐. 비평가를 빼면 유효 개념이 10개에서 7개로 줌. 즉 안전장치들은 더 많은 공격을 찾아주는 게 아니라 **발견을 재사용 가능한 지식으로 만들어주는** 역할을 함. 당장 성적표가 안 바뀌어도 축적되는 자산이 되게 하는 장치들이라는 뜻임.

8. 전이 결과도 의미가 큼. 직접 공격에서 발견한 개념이 간접 인젝션에서 49.6% ASR, 간접에서 발견한 게 직접에서 42.6%, 모델을 바꿔도 유지됨. "위임된 권한 승인" 같은 메커니즘 코어가 거의 모든 조합에서 재발현함. 결론은 취약점이 특정 모델의 버그가 아니라 에이전트 궤적 구조 자체의 속성이라는 것. 모델을 갈아끼우는 걸로 안전해지는 게 아니라는 뜻임.

![전이 실험 결과](/images/2026-07-21-aha-agent-hacks-agent-red-teaming/fig-4-p13.png)

9. 운영 관점에서 가져갈 것 세 개. 첫째, 내 에이전트의 실패 로그를 "오류 목록"이 아니라 발동 조건과 반증자를 갖춘 "실패 개념"으로 기록할 것. 둘째, 모델 업데이트마다 동결된 실패 개념 모음을 재실행해서 회귀 확인할 것. 셋째, 발견 루프에 주기적 비평가를 둬서 반복 템플릿과 커버리지 공백을 감사할 것. 전부 공격 도구 없이 적용되는 원리들임.

10. 한계도 인정함. 세 시나리오에 국한됐고, 판정자 품질에 발견 품질이 의존하고, 에이전트를 해킹하는 자동화 에이전트라는 이중 사용 리스크가 있음. 근데 반증 가능한 메커니즘 수준의 산물은 방어적으로 쓸 수 있다는 게 저자의 입장이고, 구조적으로 동의함. 축적되는 지식은 공격자보다 방어자에게 오래 남는 자산임.
