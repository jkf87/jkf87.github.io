Tsinghua 데이터베이스 그룹이 ACID 트랜잭션 개념을 LLM 에이전트 실행으로 재해석한 [ACID-Agent](https://arxiv.org/abs/2608.13900)를 냈고, KramaBench에서 Claude Code 대비 전체 점수 10.6%p 상승(64.0 → 74.6)을 확인했음. 대신 토큰 비용이 백본에 따라 최대 5배 가까이 늘어나는 트레이드오프가 있음. 앞서 정리한 MemTX와 같은 "데이터베이스 교훈의 에이전트 이식" 계열이라 정리함.

1. 핵심 아이디어는 LLM 에이전트의 장기 실행 과정을 agentic transaction으로 보는 것. 데이터 과학 워크플로에서 반복되는 탐색 → 실행 → 검증 사이클이 그 단위임. DB의 ACID를 이렇게 옮김. 원자성은 사이클 전체가 검증을 통과해야만 커밋하고 실패하면 롤백하는 것. 일관성은 실행 과정이 비결정적이어도 커밋 결과는 사전/사후 조건을 만족하는 것. 격리는 병렬 실행 중 실패한 시도의 중간 상태가 다른 실행이나 메모리로 안 새어나가는 것. 지속성은 커밋된 상태와 근거를 append-only 워크스페이스에 저장해서 나중에 재구성 가능하게 하는 것. 기존 코딩 에이전트가 중간 결정을 바로 전파하는 것과 달리 검증을 통과한 업데이트만 다음 단계로 넘기는 게 차이임.

![ACID-Compliant Data Agent 예시](/images/2026-08-20-acid-agent-transactional-agent-system/fig-1-p1.png)

2. 구현은 두 축임. 오프라인 스킬 허브는 기존 리포지토리를 표준 CLI를 가진 에이전트 스킬로 패키징하고 LLM이 생성한 테스트로 동작을 검증함. 멱등성 키, write-ahead 액션 로그, 체크포인트, 자동 보상을 넣어서 부분 실패가 워크스페이스를 더럽히지 않게 함. 온라인 단계 실행은 커밋-오어-리트라이 게이트를 돌림. 핵심 신호는 confidence divergence, 탐색 단계에서 고른 결정과 실제 코드에 들어간 결정의 신뢰도 차이를 재서 임계값 이하면 재시도하는 것. API 모델이 토큰 확률을 안 주니까 로컬 Qwen3-0.6B로 신뢰도를 추정한 게 실무적 트릭임. 작은 로컬 모델을 판정용으로 쓰는 이중 구성은 비용 설계의 좋은 예임.

![시스템 개요](/images/2026-08-20-acid-agent-transactional-agent-system/fig-2-p3.png)

3. 수치를 냉정하게 봐야 함. Qwen3.5-397B 백본에서 Claude Code 64.0 → ACID-Agent 74.6으로 10.6%p 오르는데 코드 스텝이 9.4에서 22.8로 두 배 이상 늘어남. GLM-5.2 백본에서는 74.2 → 77.4로 3.2%p인데 실행당 비용이 $0.12에서 $0.61로 5배 가까이 오름. 즉 이미 강한 백본에서는 개선 폭이 작아지고 비용은 커짐. 도메인별로도 Biomedical 55.6→77.8 같은 큰 개선과 상위 도메인(Astronomy, Legal)에서 차이가 0인 구간이 섞여 있음. 검증 게이트가 크게 이기는 곳은 중간에 무너지기 쉬운 긴 워크플로라는 것.

![3회 실행 일관성 비교](/images/2026-08-20-acid-agent-transactional-agent-system/fig-3-p4.png)

4. 내가 가져가는 건 "ACID"라는 라벨보다 검증 게이트를 통과한 것만 커밋한다는 구조임. 그리고 롤백이 불가능한 외부 효과(이메일 발송, 배포)에는 보상 트랜잭션 개념을 쓰라는 부분이 실무와 닿아 있음. 기존 하네스에 바로 적용할 수 있는 최소 버전은 세 개임. 각 실행 단위 끝에 검증 스텝을 두고 통과 못 하면 이전 상태로 되돌리기, 실패한 시도의 중간 컨텍스트를 메모리에서 분리하기, 커밋된 결과는 로그로 남겨서 나중에 재구성 가능하게 하기. 전부 MemTX에서 뽑은 원칙과 겹치는데, 그만큼 이 방향이 수렴 중이라는 뜻임.

5. 풀 버전(스킬 허브, 로컬 신뢰도 모델, 의존성 기반 격리)은 데이터 에이전트 워크플로처럼 길고 취약한 작업에서 가치가 있고, 일반적인 용도에는 최소 버전부터 시작하는 게 현실적임. 비용 대비 효과의 곡선을 태스크 가치로 판단하라는 게 이 논문의 숫자가 주는 실무 교훈임.
