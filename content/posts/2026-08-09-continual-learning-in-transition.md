"파인튜닝하면 예전 능력을 까먹는다"가 continual learning의 전부였던 시절이 있었음. 근데 LLM 에이전트 시대에 이 틀이 흔들리고 있음. 에이전트는 배포 뒤에도 살아있고, 능력을 파일과 메모리에 쌓고, 그래디언트 없이도 개선됨. 이 서베이는 그 전환을 When·How·Where 세 축으로 정리함. 에이전트를 운영하며 "우리 시스템은 어디서 학습하고 있나"를 물을 때 지도가 되는 문서임.

1. 고전적 CL의 세 가정이 먼저 정리됨. 학습은 배포 전 훈련 단계에서만 발생한다, 능력은 매개변수에 저장된다, 업데이트는 오프폴리시 그래디언트(모델이 직접 낸 행동이 아니라 미리 수집된 데이터로 기울기를 갱신하는 방식)로 한다. 재생(예전 과제 데이터를 다시 섞어 망각을 막기), 그래디언트 투영(이전 과제에 중요한 매개변수 방향으로 갱신이 못 가게 제한하기), 매개변수 분리, 정규화의 네 방법족이 전부 이 가정 위에 서 있었음. 근데 에이전트 시대에 세 가정이 전부 해제됨. 서베이의 힘은 이 가정 자체를 축으로 삼아 전환을 좌표화한 데 있음.

![Figure 1: 3차원 continual learning 개요](/images/2026-08-09-continual-learning-in-transition/fig-1-p2.png)

2. When 축. 학습 시점이 사전학습 → 포스트트레이닝 → 추론 시점으로 확장됨. 핵심 구분은 지속성임. 일반 추론 시 계산, 그러니까 검색이나 샘플링은 쿼리가 끝나면 시스템이 안 바뀜. 반면 추론 시 CL은 정보를 시스템에 기록해서 이후 행동을 바꿈. TTT-LM이나 TTRL 같은, 추론 시점에 모델을 스스로 갱신하거나 출력을 정제하는 계열이 여기 속함. "배포 후에도 학습이 일어나는가, 그리고 그것이 남는가"를 묻는 축임.

3. Where 축이 실무자에게 제일 와닿음. 능력 저장 위치가 매개변수에서 하네스로 확장됨. 메모리 계열은 MemoryLLM의 학습 가능 메모리 풀, MemoryBank의 망각 곡선, A-MEM의 원자 명제 단위, MemRL의 보상 기반 진화가 있음. 스킬 계열은 Voyager의 코드 스킬 라이브러리와 SKILL0의 하네스→매개변수 내재화가 있음. 프로토콜 계열은 프롬프트 진화와 Cline·Cursor 같은 규칙 파일 외부화. 캐리어 계층의 트레이드오프도 정리됨. 매개변수는 쓰기 비용 최고·안정성 최고·용량은 모델 크기. 외부 메모리는 중간. 컨텍스트는 쓰기 최저·안정성 최저·길이 하드 리밋. 어디에 무엇을 저장할지가 설계 결정이라는 것.

![Figure 5: Where 축](/images/2026-08-09-continual-learning-in-transition/fig-5-p8.png)

4. How 축. 업데이트 방식이 오프폴리시 그래디언트에서 온폴리시 RL과 그래디언트 프리로 확장됨. 온폴리시가 CL에 유리한 구조적 이유가 이론적으로 정리돼 있음. 망각 정도가 새 작업에 대한 KL 발산(두 확률분포가 얼마나 다른지 나타내는 값)에 비례하는데 온폴리시 RL은 KL이 작은 해를 자연히 선호함. 오프폴리시 SFT는 임의로 먼 분포로 수렴할 수 있음. 그래디언트 프리 쪽도 풍부함. 모델 병합은 데이터 없이 가중치 공간에서 능력을 합성하고, 영차 미분(MeZO)은 순전파만으로 미분을 추정하며 망각 완화에서 1차 미분과 동등함. 메모리·스킬·프롬프트 진화는 그래디언트 없이 피드백만으로 개선되는 휴리스틱 학습임.

![Figure 6: How 축](/images/2026-08-09-continual-learning-in-transition/fig-6-p10.png)

5. 교차 프로파일 표가 지도 역할을 함. Reflexion은 추론 시점·하네스 메모리·그래디언트 프리. TTRL은 추론 시점·매개변수·온폴리시. AgentEvolver는 포스트트레이닝·매개변수+하네스·온폴리시. SKILL0는 포스트트레이닝→추론, 하네스→매개변수로 이동하는 구조. 자기 에이전트를 이 표에 배치해보면 "빠진 칸"이 곧 다음 실험 후보가 됨.

6. "하네스 엔지니어링으로 CL이 대체되는가"라는 질문에 대한 저자 입장이 신중하고 마음에 듦. 기능적으로는 대체하되 기구론적으로는 대체하지 않는다는 것. 근거가 셋. 하네스 수정 주체가 사람이면 폐쇄 루프가 아님. 폐쇄 루프 방법들은 아직 초기 단계. 하네스 능력은 컨텍스트 결합도가 높아 이전이 어려움. "파일 쌓으면 그게 곧 학습"이라는 낙관을 견제하는 균형 잡힌 판단임.

7. 남은 과제도 실무 체크리스트로 쓸 수 있음. 캐리어 간 조정 스케줄링, 그러니까 새 정보를 컨텍스트·메모리·스킬·매개변수 중 어디에 둘지 분배 정책. 다층 망각, 각 층의 망각 양상이 달라서 별개로 관리해야 함. 긴 호라이즌 에이전트의 오류 누적 증폭과 하네스 비미분성. 비코드 영역의 검증 가능한 보상 한계. 내 결론은 이렇게임. 에이전트 시스템을 설계할 때 "학습이 일어나는 층"을 명시적으로 선언하고 층마다 기록·망각·이전 정책을 따로 둘 것. 매개변수만이 학습의 자리라는 가정이 이미 낡았다는 게 이 서베이의 요지임.
