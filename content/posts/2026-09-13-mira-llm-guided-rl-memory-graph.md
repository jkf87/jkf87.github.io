LLM에게 물어보고 시작하는 강화학습이 요즘 흐름인데 대부분 매 스텝 LLM을 부름. 환각·비용·지연 문제가 따라옴. USC와 CMU가 ICLR 2026에 낸 [MIRA](https://arxiv.org/abs/2602.17930)는 다르게 접근함. 한 번 물어본 조언을 그래프에 쌓아두고 계속 재사용하는 것. LLM4Teach가 500회 이상 쿼리하는 데 MIRA는 약 30회 쿼리로 비슷한 최종 성능을 냄. "LLM 지식을 끌어오되 실시간 의존을 없애고 RL 수렴 보장은 유지하기"가 문제 정의인데, 이 발상은 그리드 월드 밖에도 적용돼서 정리함.

1. 구조. 메모리 그래프는 트라젝토리 노드와 서브골 노드로 구성됨. 오프라인 LLM 사전지식으로 초기화하고 훈련 중 에이전트 경험으로 노드를 교체·가지치기함. 핵심은 잘못된 LLM 조언이 낮은 추정 보상과 미사용 가지치기로 자연스럽게 사라진다는 것. 온라인 쿼리는 유틸리티 신호가 0 근처로 떨어질 때만 발동함. LLM 출력은 토큰 likelihood 기하평균 또는 다수 일치 테스트로 스크리닝을 통과해야 그래프에 들어감. 여러 판사가 독립적으로 일치할 때만 신뢰하는 원칙의 RL 버전임.

![MIRA 전체 구조](/images/2026-09-13-mira-llm-guided-rl-memory-graph/fig-1-p2.png)

2. 학습 신호 설계가 수렴 보장을 지킴. PPO(정책을 작게 나눠 안전하게 업데이트하는 RL 알고리즘) 어드밴티지에 그래프 유틸리티를 섞는데 초반에는 유틸리티 가중치가 크고 훈련이 진행되며 0으로 감쇠함. 최종 정책은 참 보상 함수에 대해 최적화되어 PPO 수렴 보장이 유지됨. Theorem 1이 희소 보상 구간에서 업데이트가 소멸하지 않음을 증명함. 가이던스는 이행 수단이고 감쇠 일정이 그걸 코드화한 것. 앞서 정리한 BCSD의 λ 감쇠와 같은 설계 철학이 RL-LLM 결합에서 재현된 것.

3. 결과. FrozenLake(빙판 위에서 목표지점까지 가는 그리드 월드), MiniGrid와 BabyAI(방 안 과제를 텍스트 명령으로 수행하는 그리드 환경)에서 REDBALL의 최적 리턴 도달이 절반 이하 iteration으로 줄었고 DOORKEY와 REDBLUEDOOR에서 HRL(상위 정책이 하위목표를 하위 정책에 내려주는 계층적 강화학습) 대비 약 2배 성공률. LAVACROSSING에서 PPO는 성공률 0 근처에 머물렀다는 대비도 있음. 쿼리 효율이 핵심인데 구체적 구성은 오프라인 7회 + 온라인 20±3회. LLM-RS(50+)보다 적은 쿼리로 더 높은 성능을 냈고 쿼리당 리턴으로 환산해도 위임.

![쿼리 효율 비교](/images/2026-09-13-mira-llm-guided-rl-memory-graph/fig-6-p9-llm-comparison.png)

4. 어블레이션의 교훈이 실무적임. 후반부에 LLM을 교체하거나 스크리닝을 제거해도 성능이 유지됐음. 메모리가 이미 형성되면 잘못된 제안의 영향이 제한된다는 뜻. 즉 초기 안내의 품질 관리가 중요하고 일단 좋은 메모리가 쌓이면 외부 의존을 줄여도 된다는 것. 반대로 LLM 모델을 바꾸면 추론 스타일이 메모리 품질에 그대로 반영됐으니 초기화에 쓸 모델 선택은 신중해야 함.

![LLM 모델별 어블레이션](/images/2026-09-13-mira-llm-guided-rl-memory-graph/fig-7c-p10-llm-models.png)

5. 내 해석과 적용. 그리드 월드 중심이라는 한계는 있지만 희소 보상 탐색 문제를 푸는 실용적 레시피로 읽힘. LLM 조언을 소모품이 아니라 축적 자산으로 쓰는 설계라는 점이 핵심인데, 이건 RL이 아니어도 그대로 적용됨. 내 작업에서 비싼 모델의 조언을 매번 받아 쓰는 대신, 한 번 받은 조언을 신뢰도 스크리닝을 거쳐 재사용 가능한 형태(스킬, 절차 그래프 노드)로 저장하고, 사용되면서 가치가 증명되는 것만 남기고 안 쓰이는 건 가지치기하는 것. 사용 기반 가지치기 + 감쇠하는 가이던스 가중치 조합은 에이전트 설계 일반으로 확장 가능한 패턴임.
