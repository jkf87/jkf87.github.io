RL 검색 에이전트 학습이 불안정한 원인을 보상 설계가 아니라 액션 인터페이스에서 찾은 논문이 나옴. 발견 자체가 재밌어서 정리함. 원문은 [arXiv:2607.27652](https://arxiv.org/abs/2607.27652).

1. 핵심 발견은 검색 등가 붕괴임. Search-R1 학습 중에 롤아웃들은 같은 질문에 서로 다른 검색어를 계속 만들어내는데, 실제로 검색해오는 증거 집합은 점점 같아짐. 스텝 30 기준으로 서로 다른 검색 결과를 가져오는 롤아웃 그룹 비율이 86%에서 10% 미만으로 떨어짐.

2. 왜 문제냐면 GRPO의 전제가 무너지기 때문임. 같은 증거 → 같은 답 → 같은 보상 → within-group advantage가 0. 8개 롤아웃을 돌려도 의미 있는 비교 샘플이 1~2개뿐임. 반대로 같은 증경인데 답이 다르면 그 차이는 검색 품질이 아니라 답변 생성 능력에서 온 건데, 이걸 검색 행동에 귀인시키면 신호가 오염됨.

3. 해법은 과감하게 단순함. 자유 형식 검색어 생성을 유한 액션 메뉴로 바꿈. 코퍼스를 문단-문장-엔티티 삼분 그래프로 프로그램 처리해두고, 정책은 Select(문장 확정)·Lookup(엔티티 탐색)·Answer 세 가지에서만 선택함. 검색어 문자열 생성은 환경이 결정론적으로 수행함. 정책은 "무슨 증거를 추구할지"라는 의미적 결정만 내림.

4. 그래프 구축이 저렴한 게 실무 포인트임. LLM 팩트 추출이 아니라 문장 분할, 엔티티 정규화, 임베딩만으로 준선형 시간 구축. API 비용 0달러. GraphRAG처럼 코퍼스 전체를 LLM으로 처리하는 병목을 회피함.

5. 결과는 6개 QA 벤치마크에서 1.5B 기준 Graph-R1 대비 +10.74점, 3B에서 +3.98점. 작은 모델일수록 구조화된 인터페이스 이득이 큼. 기여도 분리 실험도 깔끔함 — 메뉴만 바꿔도 붕괴가 완화되고, 크레딧 설계(SNC)는 메뉴가 있어야만 작동함. 인터페이스 설계와 크레딧 설계가 상호 의존적이라는 결론임.

6. 필자가 빌릴 것. 자동화 에이전트 설계에서 "출력은 다양한데 실제 효과는 같은" 앨리어싱은 검색 외에도 도구 호출 전반에서 생김. 툴 사용을 RL이나 자동화로 최적화할 때 자유 텍스트 인자 대신 유한 선택 메뉴를 주면 평가와 디버깅이 동시에 쉬워짐. 메뉴의 미리보기 가능성 — 선택 전에 결과를 read-only로 볼 수 있는 것 — 은 사람이 검수하는 파이프라인에서도 dry-run 게이트로 바로 쓰이는 패턴임.

7. 문제제기. 텍스트 전용이고 코퍼스가 사전 구축 그래프여야 해서 스트리밍 웹 검색에 직접 적용이 어려움. SNC의 frozen answerer가 정책과 어긋나면 크레딧 품질이 저하될 수 있음.

8. 남는 결론. 액션 인터페이스 설계는 보상 설계와 동등한 축이라는 걸 실험으로 보인 작업임. 에이전트 최적화가 막힐 때 보상을 손보기 전에 "내 에이전트가 선택하는 게 유한하고 검증 가능한가"부터 확인하는 순서가 맞음.
