에이전트가 실험하며 얻은 교훈을 통째로 버리지 말고 위키에 컴파일해서 쌓으면 스킬 진화 성능이 크게 오른다는 결과가 나옴. 구글 리서치의 [WikiSkill](https://arxiv.org/abs/2608.27454). 스킬과 메모리 관리 원칙이 명확해서 정리함.

1. 배경. 에이전트 스킬 자동 수정 연구(Trace2Skill, EvoSkill 등)는 배운 걸 별도의 지식 표현으로 보존하지 않음. 교훈이 최적화 히스토리 여기저기 흩어져서 다음 iteration에서 재사용이 안 됨. 같은 실패를 반복 분석하는 것.

2. 조치는 작업공간 3층 구조임. Raw(실행 트레이스 원본, 불변), Wiki(패턴 문서+진화 로그+스킬 영향 추적, 롤백 없이 계속 축적), Skills(실행 가능한 절차 지식, 검증 게이트 통과 시만 교체). 매 iteration마다 트레이스를 위키로 정리하고 그 위키를 근거로 스킬을 수정함. 점수가 오르면 스킬 업데이트 수용, 안 오면 스킬만 롤백 — 위키는 롤백하지 않고 유지함.

3. 이 롤백 비대칭이 핵심임. 스킬은 검증 없이 바뀌면 위험하고, 지식은 버리면 손해라는 설계 판단. Skill-α의 "전후 비교 후 수용"과 같은 원칙에 지식 보존이 추가된 것.

4. 숫자. Qwen 계열에서 스케일이 클수록 이득이 커져 4B +12.3pt, 9B +17.5pt, 27B +23.9pt. 그리고 9B+WikiSkill(47.4%)이 스킬 없는 27B(39.4%)를 역전. Gemini-3.5-Flash LiveMath는 33.0% → 72.6%. 기존 SOTA 대비 5개 모델 전부 +3.3~12.0pt 우위.

5. 에블레이션이 구조의 가치를 증명함. 스킬 제안자의 위키 접근을 끊으면 63.7% → 48.7%. 위키 유무만으로 +15.0pt. 스킬 제안 로직은 기존 기법과 크게 다르지 않다는 것 — 차이는 지식 축적 층의 존재였다는 뜻.

6. 재밌는 디테일. 추론 에이전트에게도 위키 접근을 주면 오히려 63.7% → 60.9%로 떨어짐. 훈련 rollout에서 위키를 직접 보면 스킬 대신 위키에서 지식을 가져와버려서 트레이스가 스킬 개발에 주는 신호가 흐려지는 것. 지식 노출 범위 자체가 설계 변수라는 것.

7. 스킬 영향 추적기도 베낄 만함. skill-impact.md가 수용/거부 이력과 diff를 자동 기록해서 제안자가 실패한 수정을 반복 제안하지 않게 함. "같은 실패를 반복하지 않는" 핵심 메커니즘이 감사 로그라는 것 — Phantom Gains의 null 재분석과 같은 "기록의 재활용" 발상임.

8. 스킬은 모델 간에 이동함. 27B가 만든 스킬을 9B가 쓰면 자기 스킬보다 나을 때가 있음(ALFWorld 70.2% vs 63.4%). 4B 스킬을 31B Gemma에 넣어도 LiveMath 33.9% → 73.1%. 스킬 발견과 스킬 실행은 별개 능력이라는 것.

9. 근데 부정 전이도 있음. Qwen 4B 스킬을 Gemini-3.5-Flash에 넣으면 SpreadSheet 50.5% → 18.1%로 추락. 원인은 4B용 스킬에 "한 줄짜리 파이썬 커맨드" 같은 저수단 워크어라운드가 박혀 있어서 강한 모델의 엔드투엔드 접근을 막은 것. 스킬이 일반 절차인지 모델 특화 우회책인지에 따라 이동성이 갈림.

10. 여기서 내 스킬 관리 점검. 성공 건만 남기고 실패 편집은 버리는 게 관례임. WikiSkill의 증거는 실패를 구조화해서 저장하는 메모리가 실질 이익이라는 것. rejected 제안+diff+점수를 기록하는 감사 로그를 스킬 작업 디렉토리에 붙일 것.

11. 모델 교체 시 스킬 자산의 이동성도 검토할 것. 강한 모델로 넘어갈 때 약한 모델 시절의 워크어라운드가 해가 될 수 있음. 모델을 바꾸면 스킬 중 "우회책" 성격의 것을 걸러내는 정리 패스가 필요함.

12. 한계. OfficeQA처럼 긴 다단계 검색에서는 4B가 스킬을 실행 못 하고 소폭 하락. SpreadSheet 스킬은 출처 모델에 따라 이동성 편차가 큼. 스킬 발견과 실행이 별개라는 점 자체가 배포 시 고려사항.

13. 결론. 성능의 원천은 스킬 제안 알고리즘이 아니라 지식이 복리로 쌓이는 층이 있느냐였음. 근데 지식 축적 층도 롤백 규칙이 다르고(위키는 유지, 스킬은 롤백) 접근 권한이 다름(제안자만) — 축적과 검증과 노출을 분리해서 설계하는 것까지가 결론임.
