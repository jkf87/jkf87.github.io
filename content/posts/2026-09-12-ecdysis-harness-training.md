하네스(모델을 실제로 구동하는 프롬프트·도구 규칙·루프 제어 등 실행 설계 전반) 자기진화의 흔한 방식은 개별 실패 기록마다 코딩 에이전트를 호출해 하네스를 수정하는 직렬 탐색임. Ecdysis(arXiv 2609.11677)는 이게 느리고 부정확한 이유를 짚음. 하나의 실패 기록은 모델 고유의 한계와 하네스의 체계적 결함을 구분하는 증거로 불충분하다는 것. 그래서 배치 레벨 교차 인스턴스 실패 집계와 FDCR(Failure-Driven Collaborative Refinement)을 결합해서 학습 시간 최대 1.84배 단축, 추론 정확도 최대 18.56% 상대 개선을 냄.

1. 문제 정식화가 인상적임. 하네스 수정량을 ΔH = t·ΔH_model + (1−t)·ΔH_harness로 분해하고 t가 클수록 현재 모델·학습 태스크에 과적합된 수정이 된다고 분석함. 사전 분석이 뼈아픔. 하네스 제거 시 평균 29.72%, 고정 인간 설정 하네스 50.28%, 그런데 실패마다 순차 수정하는 방식은 43.33%로 인간 설정에 미달. 무작정 자기진화를 돌리면 하네스가 없느니만 못했던 것. 순응과 수정을 구분하는 게 성패를 갈랐다는 이야기임.

2. 방법이 두 축임. 첫째, 배치 레벨 실패 집계. 라운드별 실패 트랙젝토리를 태스크 ID, 종료 사유, 툴 호출 이력을 담은 구조화된 기록으로 수집하고 서로 다른 태스크 2개 이상에서 반복되는 실패 그룹을 우선 증거로 취급함. 코딩 에이전트 호출은 라운드당 1회로 제한돼서 SE 대비 호출 수가 줄고 정상 완료율도 67%에서 100%로 오름. 둘째, FDCR. Analyst, Critic, Engineer가 공유 트랜스크립트상 2라운드 진단을 하고 Moderator가 구조화된 수정 명세를 생성하면 코딩 에이전트가 명세에 따라 하네스를 수정함. 진단과 구현이 분리된 구조. 후보는 학습 점수가 개선될 때만 채택됨.

3. 성능 순서가 정리돼 있음. τ²-Bench(항공사·소매 등 시뮬레이션 고객 응대로 에이전트 능력을 재는 벤치마크) 10조합 평균 정확도가 Direct 38.17% → Human-Aug. 51.67% → SE 46.67% → w/o FDCR 54.67% → w/ FDCR 59.33%. SE 대비 +27.1%, 인간 최적화 하네스 대비 +14.8%. SE가 인간 설정보다 낮았다는 사실과 대비하면 자기진화가 정상 작동하게 만든 것 자체가 성과임. Pass³(3회 실행 모두 성공할 확률)는 SE 대비 +55.2% 상대 개선.

4. 학습 효율 숫자가 실무적임. τ²-Airline 학습 시간이 SE 8,120.6초 → w/ FDCR 4,403.0초(1.84배), w/o FDCR 2,510.8초(3.23배). API 비용은 τ²-Retail에서 SE $8.484 → w/o FDCR $2.485(-70.71%), w/ FDCR $5.763(-32.07%). FDCR이 정확도는 올리지만 비용이 든다는 트레이드오프가 투명하게 공개돼 있어서 자기 예산에 맞게 구성을 고를 수 있음. 입력 캐시 히트율도 89%대에서 93~96%로 오름.

5. 일반화 결과가 핵심 기여임. Qwen3-8B로 진화한 하네스를 Qwen3-32B에 재진화 없이 적용해도 τ²-Airline에서 51.67% → 68.33%. 모델 순응 비율 t가 60.0%에서 45.5%로 낮아진 효과로 논문이 설명함. 교차 태스크 집계가 "이 모델의 버릇에 맞추는 수정" 대신 "하네스의 체계적 결함을 고치는 수정"을 만든다는 것. 그리고 데이터 효율. 학습 실패 5건, 원 학습 세트의 4분의 1만으로 전체 데이터 학습과 비교 가능한 성능. 무작위 5건 선택은 열세였으니 반복 패턴이 있는 실패를 고르는 게 핵심이라는 뜻임.

6. 실무 이식은 이렇게임. 첫째, 하네스 개선을 실패 로그 한 건 단위로 돌리지 말 것. 라운드 단위로 모아서 두 태스크 이상에서 반복되는 실패만 수정 후보로 올릴 것. 과적합 수정과 진짜 결함 수정이 갈리는 지점. 둘째, 진단과 구현을 분리할 것. 진단은 구조화된 수정 명세로 나오고 구현은 코딩 에이전트가 명세대로 하는 이 구조가 완료율을 100%로 만듦. 셋째, 수정 채택 조건을 학습 점수 개선으로 못 박을 것. 넷째, 하네스 진화 효과는 타 모델 전이로 검증할 것. 전이가 안 되면 모델 순응에 불과함. 다섯째, 실패 데이터가 적어도 반복 패턴을 골라내면 소량으로 시작 가능함. 한계는 있음. 평가가 τ²-Bench 두 서브셋과 AgentBench(다양한 도메인 과제로 범용 에이전트 능력을 재는 벤치마크)에 집중됐고 모델 순응 비율 t는 세밀한 수동 분석에 기반하며 베이스 하네스·코딩 에이전트 선택 민감도 분석이 없음.
