Tencent Hy Foundation Model Frontier 등이 만든 T1(arXiv 2609.11042)의 핵심은 단순함. Qwen3.5-122B-A10B를 실제 리눅스 셸에서 태스크당 최대 300턴 이상 돌리고, 태스크별 검증기를 실행한 결과로 보상을 주는 강화학습만으로 Terminal-Bench 2.1(에이전트가 실제 리눅스 셸에서 다단계 실무 태스크를 수행해 검증기 통과율로 채점하는 벤치마크)을 43.8%에서 64.0%로 올렸다는 것. 같은 Terminus-2 하네스(모델을 실제 셸·도구와 연결해 태스크를 실행·채점하는 프레임) 기준으로 GPT-5.4(54.8%), DeepSeek-V4-Flash(56.9%), Claude Opus 4.6(63.8%)보다 높고 Opus 4.7(66.1%)에 근접함. 활성 파라미터는 10B. 전체 상승분 20.2점 중 SFT가 5.6점, RL이 14.6점을 담당해서 총 상승분의 약 4분의 3을 실행 기반 RL이 만들었다는 게 중심 근거임.

1. 난제가 두 개로 정의됨. 첫째, 학습-추론 불일치. MoE 모델(전문가 혼합: 레이어마다 수많은 전문가 네트워크 중 소수만 활성화해 효율을 높인 구조)은 토큰마다 256개 전문가 중 8개를 고르는데(전체 121.4B 중 116.0B가 전문가 가중치) 추론 스택과 학습 스택의 미세한 수치 차이가 이 선택을 뒤집으면 실제 행동을 만든 파라미터와 다른 파라미터에 그래디언트가 감. 둘째, 희소 보상. 롤아웃 한 배치에 수백 sandbox-시간이 드는데 이진 통과/실패는 트랙토리당 1비트뿐. 저자들의 첫 이진 보상 캠페인은 SFT 베이스라인을 넘지 못했음.

2. 기법 1, TITO(Token-In-Token-Out). 멀티턴 로그를 학습 샘플로 이을 때 샘플러가 실제 뽑은 정확한 토큰 식별자 그대로 학습하는 것. 재인코딩된 근사 토큰은 학습 스트림에 절대 안 들어감. 턴 경계에서 프리픽스 관계를 점진적으로 약한 순서로 테스트하고 떨어지는 만큼만 수리하며 툴 출력 같은 관측은 마스킹된 컨텍스트로 들어가 그래디언트를 받지 않음. 1,402개 샘플 운영 실행에서 loss 영역 드리프트율이 정확히 0.0000%로 측정됨.

![TITO 스티칭](/images/2026-09-15-t1-terminal-agent-rl/fig-5-p10.png)

3. 기법 2, R3 롤아웃 라우팅 재생. 라우팅 문제를 구조로 해결함. 추론 시 기록한 전문가 선택 마스크를 학습 forward에서 그대로 재사용. 정규화는 살아있는 logits으로 하되 선택은 기록된 마스크로 고정함. TITO와 R3를 합쳐 훈련-추론 log-probability 차이를 0.021에서 0.013으로 줄이고 loss 영역 토큰 드리프트를 0으로 만듦.

4. 기법 3, 밀집 검증 보상. 이 논문의 절반. 검증기가 어설션별로 통과/실패를 따로 보고하니 통과한 어설션 절대 개수를 전역 고정 스케일(S=20)로 점수화하는 밀집 프로세스 보상을 씀. 배치 최댓값 정규화는 극단 샘플 하나가 배치 전체 보상 스케일을 바꿀 수 있어서 안 씀. 보상은 마지막 응답 토큰에 들어가고 크리틱이 호라이즌 전체에 크레딧을 분배하며 크리틱은 배우 학습률의 30배로 warm-start 함. 보상 해킹 방지로 숨은 요구사항·테스트 누출·솔루션 지름길·검증기 약함에 해당하는 태스크를 하드 리젝함.

![test-count 보상 하의 평균 롤아웃 보상](/images/2026-09-15-t1-terminal-agent-rl/fig-8-p15.png)

5. 데이터 구성이 결과를 좌우함. Tmax-15k(공개 코퍼스 변환, 이진 보상만 가능) 47.2%, RST-38k(재귀 합성, 밀집) 59.9%, T1-15k(8개 감사 차원으로 선별, 밀집) 64.0%. 같은 예산에서 태스크 풀 질과 보상 밀도가 성적을 갈랐다는 것. 세 평가 벤치마크는 학습 풀에 태스크를 제공하지 않아서 오염을 배제한 실제 전이라는 주장의 근거가 됨. 카테고리 편중도 결과로 나타나서 스크립팅·개발·시스템 관리가 3분의 2를 차지하는데 디버깅은 1.3%뿐인데도 결과가 디버깅 100.0, 시스템 관리 88.9였음.

![T1-15k의 카테고리 구성](/images/2026-09-15-t1-terminal-agent-rl/fig-3-p7.png)

6. 실패 기록이 실용적으로 유익함. 크리틱 보정이 좋아져도 정책이 나아지지 않는 경우가 있음. 어려운 태스크가 전부 0을 받으면 잘 예측해도 소용이 없어서 보정과 정책 개선을 따로 진단해야 함. 컨텍스트 관리가 학습 가능성을 결정해서 요약 길이 mismatch로 전체 요약 시도의 98.3%가 실패한 캠페인에서 에이전트는 완료한 작업을 반복했고 평균 턴이 22에서 30으로 늘었음. 롤아웃 처리량이 학습 분포를 바꿔서 스케줄러가 빨리 끝난 것만 받으면 느린 어려운 태스크 트랙토리가 취소됨. 측정된 한 스텝에서 561개 중 48개가 취소됐고 풍부한 보상도 취소된 트랙토리에서 신호를 살릴 수 없음. 그리고 GRPO(같은 태스크의 여러 시도를 한 그룹으로 묶어 상대 성적으로 학습 신호를 만드는 RL 알고리즘)가 정체된 이유도 명시적. 전원 실패/전원 성공이 흔한 긴 호라이즌에서 그룹 상대 advantage가 그래디언트를 못 주고 같은 태스크 G번 샘플링 요구가 다양성과 경쟁해서 51.7%에서 정체됐음.

7. 내 해석. 이 논문의 진짜 기여는 64.0%라는 숫자보다 레시피의 검증 가능성임. TITO, R3, 밀집 보상, 크리틱 warm-start가 각각 어떤 불일치를 몇 점씩 줄이는지 수치로 보여줬으니 같은 조건을 맞춘 다른 팀도 비슷한 하한선을 기대할 수 있음. 한계도 명확. 동일 하네스 보상 최적화이고 카테고리 편중이 있으며 LHTB에서는 GLM-5.2(31.6), DeepSeek-V4-Pro(30.7)가 여전히 앞섬. 그리고 하네스 의존성. 같은 모델이 하네스에 따라 6점 이상 움직임(Claude Opus 4.6이 Claude Code 70.1, Terminus-2 63.8). 벤치마크 표를 볼 때 하네스 컬럼을 확인하는 습관이 이 논문의 부수 교훈임. 시간 단위 스텝의 실행 기반 RL 인프라가 며칠간 살아있다는 사실 자체가 결과의 상당 부분이라는 지적에도 동의함.
