자가진화 에이전트의 메모리 시스템엔 조용한 함정이 있음. 무관한 기억이 성공 에피소드에 우연히 포함되면 양의 보상을 받고, Q값이 올라 더 자주 검색되고, 오염이 자기강화됨. RoMeRL은 이 메모리-보상 함정을 궤적별 Q값 학습 자체를 버리는 걸로 푼 프레임워크임.

1. 문제 구조부터. 기존 학습 기반 메모리 시스템은 각 궤적에 개별 Q값(해당 행동·기억이 얼마나 가치 있는지 추정하는 수치)을 할당하고 작업 결과 보상으로 업데이트함. 궤적이 쌓이면 두 문제가 생김. 첫째, 피드백 희석. Q값 차원이 궤적 수에 비례해서 늘어나니 개별 Q값이 업데이트받을 확률이 줄어들고 대부분의 메모리가 cold-start에 놓임. 둘째, 메모리-보상 함정(MRT). 궤적 수준 보상이 공동 검색된 메모리들에 일괄 할당되니 무관한 기억도 보상을 받는 것임.

![Memory-Reward Trap](/images/2026-08-09-romerl-memory-reward-trap-agent-memory-rl/fig-1-p2.png)

2. 논문의 정형화가 깔끔함. 기억의 관측 효용과 한계 기여도가 다를 수 있고, 실제 기여도가 0 이하인데 관측 효용이 양수인 상황을 함정으로 규정함. 보상 해킹의 메모리 버전이라고 보면 됨.

3. RoMeRL의 조치는 축소 차원 메모리 상태임. 궤적 인덱스 기반 Q값 학습을 버리고 작업별로 고정 4차원 상태를 유지함. 두 축은 결과 극성(성공/실패)과 기억 역학(정산/적응)의 조합임.

4. 네 좌표가 각자 역할을 가짐. PCC(+,C)는 가장 효율적인 성공 궤적, PAC(+,A)는 최초 실패 후 첫 성공 궤적, NCC(−,C)는 하류 보상이 누적된 실패 궤적, NAC(−,A)는 가장 최근 실패 궤적임. 새 경험은 기존 좌표의 내용을 교체할 뿐 새 차원을 추가하지 않으니 학습 대상 Q값이 항상 4개임.

![RoMeRL 구조](/images/2026-08-09-romerl-memory-reward-trap-agent-memory-rl/fig-2-p4.png)

5. 이론적 근거 세 개가 설계를 뒷받침함. 정리 1은 Q값 추정 오차에서 분산 항은 피드백으로 줄지만 관측 편향은 안 준다는 것. 정리 2는 N개 궤적을 ε 오차 내로 추정하려면 O(N/ε²·log(N/δ))의 피드백 예산이 필요하다는 것. 정리 3은 차원을 d로 고정하면 좌표당 피드백이 풀 대비 N/d배 집중된다는 것임.

6. 결과. ALFWorld(텍스트 가상 집안에서 일상 과제를 수행하는 에이전트 벤치마크)와 LifelongAgentBench(운영체제·데이터베이스 작업으로 장기 학습 능력을 재는 벤치마크)(OS, DB)에서 백본 LLM은 동결하고 메모리 시스템만 비교함. 전체 평균 성공률 0.830→0.862(+3.2pp). 근데 진짜 이야기는 운영 지표에 있음.

![메인 결과](/images/2026-08-09-romerl-memory-reward-trap-agent-memory-rl/table-1-p8.png)

7. Cold-Q 비율이 44.9%→9.0%로 80% 감소함. 피드백 밀도는 4.96→29.93으로 6배가 됨. 메모리 풀 크기는 ~45K에서 ~7K로 84.4% 줄고 LLM 호출도 21.1% 감소함. 성능 소폭 상승에 시스템 전체가 가벼워진 구조임.

8. 스트레스 테스트가 함정 방어를 직접 확인함. 의도적 노이즈 주입에서 RoMeRL은 노이즈 비율 0.15%, MemRL+UCB는 1.20%였음. 우연히 끼어든 나쁜 기억이 살아남는 비율을 8배 낮췄다는 뜻임.

![피드백 밀도와 Cold-Q](/images/2026-08-09-romerl-memory-reward-trap-agent-memory-rl/fig-3-p8.png)

9. 크로스 모델 전이도 확인됨. 7B 모델로 구축한 메모리 상태를 3B에 적용해도 성공률 향상과 스텝 감소가 있었음. 4차원 상태가 특정 모델에 과적합되지 않는다는 뜻임.

10. 실무 채점. 이건 우리 에이전트의 경험 재사용 루프에 바로 묻는 문제임. 첫째, 성공 에피소드에 포함됐다는 이유만으로 기억을 쌓고 있진 않은가. 검색된 기억 전부에 공으로 공을 주면 오염이 쌓임. 둘째, 기억 저장소가 계속 자라면 개별 항목이 사실상 방치됨. 관리되지 않고 쌓이기만 하는 창고임. 차원을 고정하고 교체하는 구조가 답이 될 수 있음.

11. 베낼 것 두 개. 첫째, 성공/실패 × 정산/적응의 4분류는 자체 메모리 관리 정책으로 바로 옮길 수 있음. 각 칸에 대표 사례 하나씩만 유지하고 새 경험은 교체하는 것임. 둘째, 실패 궤적 중 최근 것(NAC)과 보상 누적된 것(NCC)을 구분해 두는 것. 최근 실패는 환경 변화 신호라서 대우가 달라야 함.

12. 한계. 평가 환경이 ALFWorld와 LifelongAgentBench로 제한적이고, 4차원이라는 구체적 설계가 다른 도메인에서 최적인지는 확인이 필요함. 교체 정책이 중요한 정보를 밀어낼 수도 있다는 리스크도 있음.

13. 그래도 교훈은 명확함. 메모리 시스템의 실패는 저장 실패보다 오염과 방치에서 더 자주 옴. 차원을 고정하고 피드백을 집중하는 것이 무한정 쌓는 것보다 낫다는 걸 이론과 실험으로 보여준 케이스임.
