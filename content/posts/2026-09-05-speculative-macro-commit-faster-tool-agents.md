툴 에이전트의 지연시간은 모델 추론만이 아니라 도구 실행 대기가 큰 몫을 차지함. 이 구조를 공략한 가속 기법이 나와서 정리함. 원문은 [arXiv:2609.03236](https://arxiv.org/abs/2609.03236).

![지연시간과의 속도전](/images/2026-09-05-speculative-macro-commit-faster-tool-agents/gifs/speed-run.gif)

1. 배경부터. 인용 문헌 측정으로 툴 실행이 총 지연시간의 35~61%를 차지하는 사례가 있음. 토큰 단위 speculative decoding(작은 모델이 토큰을 먼저 제안하고 큰 모델이 검증해 통과한 만큼 한 번에 확정하는 디코딩 가속 기법)은 한 번의 모델 호출 내부만 가속하고, 액션 단위로 올라와도 기존 방식(SA)은 인접 한 스텝씩만 재사용함. 채굴한 매크로를 메타툴로 노출하면 오픈 모델이 그걸 거의 선택 안 한다는 게 저자들의 관찰임.

2. SMC의 구조는 두 모델 병렬임. 큰 액터 모델(Qwen3.5-27B INT4)이 공식 궤적의 다음 툴 호출을 결정하고, 작은 드래프터(Qwen3.5-4B)가 미래 액션 체인을 예측해 격리된 상태에서 미리 실행해 결과까지 확보해둠. 드래프터 호출은 격리 환경에서 돌아가니 라이브 상태를 오염시키지 않음.

![커밋은 지름길로](/images/2026-09-05-speculative-macro-commit-faster-tool-agents/gifs/shortcut.gif)

3. 커밋 규칙이 핵심임. 액터의 다음 호출이 드래프트 체인의 첫 액션과 일치하면 그 액션이 앵커가 되고, 나머지 스텝들을 액터 개별 재검증 없이 통째로 공식 궤적에 커밋함. 이때 여러 개의 액터 호출과 툴 대기를 건너뜀. 불일치면 드래프트를 버리고 재시작. 최소 스킵 깊이 가드가 얕은 커밋을 걸러서 임계경로상 이득이 있는 커밋만 남게 함.

![SMC 익스큐터 의사코드(논문 Algorithm 1)](/images/2026-09-05-speculative-macro-commit-faster-tool-agents/algorithm1-executor.png)

4. 매크로 채굴도 보수적임. 성공 트레이스에서 반복 패턴을 뽑되 사용자 ID·타임스탬프 같은 값을 슬롯으로 정규화하고, 후보마다 드래프터가 실제 재현하는지 라벨링한 뒤 Beta 사후분포(성공·실패 시행을 누적하며 신뢰도를 갱신해 나가는 통계 분포) 하위 분위수로 신뢰도를 계산해 통과한 것만 라이브러리에 넣음. 채굴은 필터일 뿐이고 실제 커밋 여부는 런타임 규칙이 따로 결정한다는 분리가 안전성의 뼈대임.

5. 결과는 τ² Telecom(τ²-Bench의 통신사 고객 지원 도메인) 2,285 태스크에서 순차 기준 대비 -18.59%(27.60s→22.47s), 단일 스텝 투기 대비 추가 -10.23%. 그리고 정확도 99.52% 유지, 태스크별 아웃컴이 순차 기준과 완전히 동일함. AppWorld(일상 앱들을 모사한 환경에서 복합 과제를 수행하게 하는 에이전트 벤치마크)에서는 기준 대비 -44.93%까지 가지만 태스크 완수가 168 중 2개 하락함.

![벤치마크 메인 결과(논문 Table 1)](/images/2026-09-05-speculative-macro-commit-faster-tool-agents/table1-main-results.png)

6. 절제 실험 세 개가 설계 교훈을 줌. 첫째, 매크로를 메타툴로 노출하면 오히려 느려지고 정확도도 하락 — 숨은 런타임 상태 + 앵커 검증 조합만 속도와 정확도를 동시에 잡음. 둘째, 커밋 정밀도 단계 분석 — 라이브러리 매치만으로 34.6%, 드래프터 실행 70.6%, 앵커 검증 87.9%, 깊이 가드 90.4%를 거쳐 실제 발동한 158개 커밋은 158/158 전부 아웃컴 보존. 각 게이트가 실제로 하는 일이 수치로 보임. 셋째, 커밋 횟수가 많다고 빨라지지 않음 — 임계경로의 액터 호출을 실제로 건너뛰는 가드된 커밋만 유용하다는 것.

![커밋 단계별 정밀도(논문 Table 5)](/images/2026-09-05-speculative-macro-commit-faster-tool-agents/table5-commit-precision.png)

![인터페이스 어블레이션(논문 Table 4)](/images/2026-09-05-speculative-macro-commit-faster-tool-agents/table4-interface-ablation.png)

7. 필자 관점. 근사 최적화라는 걸 알고 써야 함. SA가 한 스텝 검증으로 무손실을 보장하는 것과 달리 SMC는 스킵한 스텝을 재검증하지 않음. τ²에서는 무손실이었지만 AppWorld에서 2태스크 하락이 있었고, 되돌릴 수 없는 API가 있는 도메인에선 안전 규칙이 필수임. 그리고 GPU 3장(액터+복제본+드래프터)이 필요해서 대기 시간이 비싸고 GPU가 남는 서빙 환경에 맞는 트레이드오프임.

8. 파이프라인 적용 관점에서 빌릴 것. "검증 한 번으로 여러 스텝 통째로 커밋"하는 패턴은 배치 자동화에도 적용됨. 첫 파일의 게이트 통과가 예측과 일치하면 나머지 파일군을 같은 규칙으로 커밋하고, 이탈이 감지되면 다시 파일 단위 검증으로 되돌리는 이중 모드가 그 축소판임. 드래프트-액터 분리, 앵커 검증, 깊이 가드라는 세 부품 구성 자체가 재사용 가능한 설계도임.

9. 문제제기. 평가가 두 벤치마크로 한정됐고 드래프터가 반복 패턴을 재현할 수 있는 도메인에만 적용됨. 하드웨어 코스트 분석이 논문 설정 기준이라 상용 서빙 조건에서의 손익은 별도 검증이 필요함.

10. 남는 결론. 툴 에이전트 가속의 다음 격차는 모델 호출 내부가 아니라 루프 전체의 임계경로에 있음. 모델 인터페이스를 그대로 두고 익스큐터가 검증해 커밋한다는 접근은 오픈 모델에서도 잘 작동하는 실용적 경로라는 게 이 논문의 기여임.
