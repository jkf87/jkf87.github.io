자기개선 에이전트 연구는 대부분 에이전트 자체를 고치는 길을 걸어왔음. 프롬프트를 진화시키고, 하네스를 탐색하고, 코드를 직접 수정함. 근데 이 길의 유지비가 크다는 게 드러났음. 개선이 특정 에이전트 설계에 묶이고, 로컬 교훈끼리 충돌이 쌓이고, 다른 모델로 이식이 안 됨. Caltech이 이 문제를 뒤집었음. 에이전트는 버리고 지식만 큐레이션하라는 것. 일회용 에이전트 + 영속 지식 베이스의 조합이 에이전트 중심 최적화를 성능과 비용 양쪽에서 이겼음.

1. 설계 철학은 단순함. 에이전트 설계를 고정하고 오직 지식만 바뀌게 격리함. 각 에이전트는 공유 지식 베이스에서 증류 묶음을 받아 표준 도구로 태스크를 시도하고, 결과를 증거 기반으로 기록한 뒤 사라짐. 상태 유지 없음. 에이전트가 아니라 지식 베이스가 영속하는 개선 대상이 되는 것임. "어떤 에이전트를 쓰느냐"보다 "어떤 지식을 물려주느냐"가 성능을 결정하는 구조임.

![Figure 1: 에이전트 중심에서 지식 중심 자기개선으로의 전환](/images/2026-07-25-knowledge-centric-self-improvement/fig-1-p2.png)

2. 큐레이션이 3단계로 돌아감. 첫째, 태스크 수준 포럼. 태스크를 시도한 에이전트가 정답만이 아니라 어떤 가설을 테스트했고 어떤 전략이 실패했는지를 증거 기반 주장으로 올림. 후속 에이전트가 그걸 인용하며 정제하거나 반박함. 둘째, 크로스 태스크 포럼. 로컬 관찰이 다른 태스크에서도 살아남는지 검증함. 충돌을 불안정이 아니라 증거로 취급하는 게 핵심임. 셋째, 증류. 살아남은 주장을 타입화된 필드, 즉 이전 가능한 통찰, 확인된 제약, 기각된 가설, 함정, 검증 방법으로 압축하고 모호한 조언은 버림.

3. 결과가 묵직함. ARC-AGI(추상 패턴 규칙을 맞히는 추상 추론 벤치마크), Polyglot(다양한 언어의 프로그래밍 문제 풀이 벤치마크), SWE-Bench Pro(실제 소프트웨어 저장소의 이슈를 고치는 코딩 벤치마크의 고난도 확장판), Terminal-Bench 2(터미널 명령으로 실제 작업을 수행하는 벤치마크)에서 Darwin Gödel Machine, HyperAgents 같은 에이전트 자체 개선 베이스라인과 비교했는데 전 벤치마크에서 해결률이 높으면서 달러 비용은 더 낮았음. "에이전트를 진화시키는 게 최선"이라는 통념을 뒤집은 숫자임.

4. 내가 제일 주목한 건 크로스 LLM 이식임. 한 모델 패밀리에서 큐레이션한 지식을 다른 패밀리의 에이전트가 소비해도 양방향으로 개선이 나옴. GPT가 쓴 지식을 Haiku가 썼을 때 Polyglot 8.3% → 11.7%, Haiku가 쓴 지식을 GPT가 썼을 때도 23.3% → 28.3%. 큐레이션된 지식이 모델 고유의 습관이 아니라 기증자에 무관한 구조를 담고 있다는 증거임. 모델을 바꿔도 따라오는 자산이 지식이라는 뜻이고, 이건 곧 플러그 앤 플레이 에이전트 생태계가 가능하다는 뜻임.

5. 왜 이기는지에 대한 설명이 실무 감각과 맞음. 자율 추론의 병목이 에이전트 아키텍처의 복잡도가 아니라 접근 가능하고 정제된 정보의 품질이라는 것. 아무리 정교한 에이전트도 쓰레기 컨텍스트에서는 못 씀. 그리고 지식 베이스는 에이전트 내부 매개변수와 달리 열어보고 압축하고 감사할 수 있음. 개선이 검사 가능해진다는 게 운영 관점에서 큰 이점임.

![Figure 3: 두 태스크 패밀리에서 지식 큐레이션의 실제 예시](/images/2026-07-25-knowledge-centric-self-improvement/fig-3-p6.png)

6. 내 자동화 운영에 이식할 것은 이렇게임. 첫째, 에이전트 설정을 계속 손보는 대신 태스크별 교훈을 "증거 기반 주장" 형식으로 축적할 것. 성공만 기록하지 말고 기각된 가설과 함정도 남길 것. 둘째, 주간 정리 때 태스크 간에 반복되는 패턴과 충돌하는 교훈을 구분해서 증류할 것. 모호한 조언은 버릴 것. 셋째, 지식은 모델 바깥에 둘 것. 그래야 모델 교체 때 자산이 남음. 이 논문의 3단계 포럼 구조가 하나의 구현일 뿐 최적은 아니지만, 원칙 자체는 당장 적용 가능함.

7. 한계도 분명함. 효과 격리를 위해 에이전트를 의도적으로 단순하게 유지해서 에이전트 중심 기법과의 시너지는 미탐색. 검증 도메인도 추상 추론, 코딩, 터미널로 제한적. 인간 전문가가 지식 베이스에 기여하는 채널도 없음. 근데 방향은 확실함. 자기개선 투자의 무게중심을 에이전트에서 지식으로 옮기는 게 레버리지가 크다는 것.
