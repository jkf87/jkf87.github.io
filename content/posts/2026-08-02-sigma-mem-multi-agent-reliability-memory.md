다중 에이전트 시스템이 실패하는 지점은 모델이 멍청해서가 아니라 신뢰 결정임 — 누구 말을 들을지. Σ-Mem은 이걸 기억으로 풂. 여러 모델을 섞어 쓰는 오케스트레이터를 굴리는 사람에게 직결되서 정리함.

1. 배경. 다중 에이전트 시스템에서 중앙 모델이 동료 답변을 직접 검증 못 하는 상황이 많음. 동료 셋이 Berlin, Berlin, Zurich라고 답하면 다수결로 Berlin. 근데 Berlin이라 답한 둘이 상관된 오류를 공유할 수 있음 — 과거에 같이 틀린 적이 많다면 소수인 Zurich가 더 믿을 만함. 다수결은 이걸 못 봄.

2. 기존 에이전트 메모리 연구는 콘텐츠 메모리(무슨 일이 있었나)에 집중함. [Σ-Mem](https://arxiv.org/abs/2607.27958)은 다른 차원을 추가함 — 신뢰 메모리(누가 언제 믿을 만한가). 기록하는 증거는 두 개. 각 동료가 어떤 유형의 작업에서 얼마나 정확했는지의 역사적 역량, 그리고 동료들이 독립적으로 맞추는지 같이 틀리는지의 관계.

3. 설계는 수학적으로 안정적임. 동료별로 대칭 행렬을 유지하고 정답 피드백마다 랭크-1 갱신(행렬에 외적 항 하나만 더하는 가벼운 갱신). Weyl 부등식(행렬이 조금 변할 때 고유값이 그 이상 움직일 수 없다고 제한하는 선형대수 정리) 때문에 단일 이벤트가 기억 스펙트럼을 뒤집지 못함. 한 번의 노이즈가 신뢰를 무너뜨리지 않으면서, 일관된 신호는 누적되면 진짜 역량을 반영한다는 보장. 감쇠 인자로 옛 기록의 영향이 서서히 줄어듦.

4. 읽기 인터페이스가 세 가지라는 게 실무적임. 잔차 조향 선택(학습된 기억 벡터를 중앙 모델의 중간층 표현에 더해 출력을 조정해 평가하는 방식, 제일 정확하지만 비쌈), M-Route(중앙 모델 없이 기억 점수만으로 라우팅, 제일 빠름), M-Weighted Voting(동료 응답을 안 보고 신뢰도 가중 투표만).

5. M-Route 결과가 핵심임. 중앙 모델 판단과 동료 응답을 전혀 안 쓰고 기억만으로 라우팅해도 다수결과 최고 고정 동료를 이김. 기억 상태 자체가 이미 신뢰 판단에 충분한 정보를 담고 있다는 것 — 비용 없이 신뢰 판단을 얻을 수 있다는 뜻.

6. 반사실적 실험에서 극적임. 원래 수학 잘하던 동료가 갑자기 틀리기 시작하는 시나리오에서 Qwen3-0.6B가 46.22% → 71.10%로 회복. 기억 없는 모델은 항상 같은 동료를 골라서 신뢰 대상이 바뀌면 무력해짐. 모델 업데이트나 도구 장애로 동료 성능이 바뀌는 실제 상황과 같은 구조.

7. 일반화도 확인됨. 동료 3명으로 훈련하고 4-5명으로 늘려도 작동. 수학·RAG·코드로만 훈련하고 미지의 6개 벤치마크에서 30케이스 중 27개에서 기본 모델 능가, BBH(Big-Bench Hard, 어려운 추론 과제 모음)에서는 +8.3~8.9포인트. 도메인별 강점 방향이 새 작업에 이전된 것.

8. 여기서 문제제기. 갱신에 정확도 라벨이 필요함. 실무에선 정답 피드백을 어떻게 얻나. 늦게 오는 피드백(결제 성공, 사용자 승인, 테스트 통과)이라도 붙잡으면 되는데, 피드백이 아예 없는 태스크에선 기억이 못 자람. 피드백 수집 경로 설계가 이 시스템의 숨은 선행 작업.

9. CF@50에서 성적이 오히려 떨어지는 예외도 솔직함. 증거의 절반이 원래 동료를, 절반이 바뀐 동료를 지지하면 기억도 모호해진다는 것. 버그가 아니라 기억의 충실성. 모호한 증거에 대해 확신하는 시스템이야말로 위험하다는 교훈.

10. 실무 적용은 가볍게 시작할 수 있음. 수학적 장식 없이도 핵심은 추적 가능함 — 동료(모델/도구/서브에이전트)별로 태스크 유형과 성공/실패 로그를 쌓고, 라우팅 시 그 기록을 점수로 쓰는 것. 내 오케스트레이터에도 모델별 성공률 로그는 있지만 태스크 유형별로 쪼개진 신뢰 표는 없었음. 이게 개선 포인트.

11. 상관 오류 추적도 벤치마킹할 것. 비슷한 계열 모델들을 동료로 두면 같이 틀리는 경우가 많음. 다수결로 다양성을 확보한 것처럼 보여도 실제로는 한 모델의 편향을 세 번 샘플링한 것일 수 있음. 동료 조합을 짤 때 독립성까지 볼 것.

12. 한계. 동료 수가 수십~수백 개로 늘어날 때의 행동은 미탐구. 잔차 조향은 오픈웨이트 접근이 필요해서 클로즈드 API 조합에는 M-Route/가중 투표만 해당됨.

13. 결론. 신뢰를 프롬프트나 고정 휴리스틱에 맡기지 말고 추적되는 상태로 만들 것. 그리고 가능하면 피드백이 쌓일수록 판단이 좋아지는 구조로. 근데 결국 그 신뢰의 품질은 정답 피드백의 품질이라는 것 — 신뢰 시스템을 만들기 전에 채점 시스템부터 만들어야 한다는 결론임.
