에이전트 코딩 워크로드를 RL로 돌리면 GPU가 가장 느린 롤아웃을 기다리며 놀아남. SAO(Single-rollout Asynchronous Optimization)는 이 병목을 그룹 샘플링 자체를 버리는 걸로 풀었고, GLM-5.2 훈련에 실제로 들어갔음. 설계 결정 몇 개가 따로 가져올 만해서 정리함.

1. 문제의 시작은 동기식 배치임. 롤아웃 batch 전체가 끝나야 최적화가 시작되는데, 코딩 에이전트 롤아웃은 길이 편차가 극심함. 짧은 트레젝토리는 금방 끝나고 긴 게 straggler가 되어서 클러스터가 놀아남.

2. 비동기로 바꾸면 두 문제가 터짐. 첫째, 정책 지연. 트레젝토리 생성 중에 롤아웃 엔진이 여러 버전으로 업데이트되어 행동 확률 추적이 불가능해짐. 둘째, GRPO는 프롬프트마다 여러 응답을 뽑아 그룹 평균으로 어드밴티지를 계산하는데, 비동기에서는 그룹 내 느린 샘플을 기다려야 해서 비동기의 이점이 사라짐.

3. SAO의 첫 결정. 중간 정책(π_old) 추적을 포기함. 대신 π_rollout의 로그 확률을 직접 써서 현재 정책과의 비율을 계산하고, 신뢰 구간 [1−εℓ, 1+εh] 밖의 토큰은 그레이디언트에서 완전히 마스킹함. 즉 과거 행동 확률이 현재 정책의 확률과 지나치게 벌어진 토큰은 학습에서 아예 제외한다는 뜻임. 정확하지만 비싼 추적 대신 대략적이지만 공격적인 클리핑을 택한 것임.

![SAO 아키텍처](/images/2026-07-11-sao-single-rollout-asynchronous-agentic-rl/fig-p2.png)

4. 두 번째 결정. 프롬프트당 롤아웃 하나만. 완료되는 즉시 훈련에 투입함. 환경이 단일 궤적 피드백만 주는 온라인 에이전트 설정과도 자연스럽게 맞음.

5. 근데 단일 롤아웃은 분산이 큼. SAO는 가치 모델로 보완함. Critic을 Actor보다 2:1로 더 자주 업데이트하고, 가치 모델의 어텐션 층은 고정(frozen attention)한 채 FFN만 미세조정함.

6. 세 번째 결정. 관찰 토큰을 건너뛰는 GAE(시간차 오차를 지수평활해서 각 행동의 기여 가치를 추정하는 알고리즘)임. 에이전트 트레젝토리는 모델이 만든 액션 토큰과 환경이 준 관찰 토큰이 섞여 있는데, 관찰에 그레이디언트를 흘리면 노이즈가 됨. 액션-투-액션 경위에서만 GAE를 계산해서 이걸 끊음.

7. 결과 숫자. Qwen3-30B-A3B 기준 AIME2025(미국 수학 올림피아드 초청 시험 문제 세트) 97.3, BeyondAIME 74.8, HMMT Nov 2025(하버드-MIT 수학 대회 문제 세트) 88.3, IMOAnswerBench 74.0. GRPO 대비 BeyondAIME +20%p임. SWE-Bench Verified(실제 GitHub 이슈를 재현해 고치는 코딩 벤치마크 중 사람이 검증한 문제 세트)도 27.0에서 29.8로 올라감.

![주요 벤치마크 성능 비교](/images/2026-07-11-sao-single-rollout-asynchronous-agentic-rl/fig-p6.png)

8. Ablation에서 제일 큰 걸린 건 가치 모델 설계임. Running mean baseline을 쓰면 AIME2025가 97.3에서 79.8로 무너짐. Frozen attention을 빼면 90.6로 내려감. 단일 롤아웃 RL의 성패는 베이스라인 추정 품질에 달려 있다는 뜻임.

9. 내가 주목하는 건 온라인 학습 적합성임. 환경이 바뀌면 GRPO는 그룹 전체를 새 환경에 재평가해야 하지만 SAO는 롤아웃이 도착하는 즉시 적응함. API 스펙이 바뀌거나 도구가 추가되는 실무 배포 상황과 구조가 같음.

10. 실무 채점. 에이전트 파인튜닝을 자체 인프라로 돌리는 조직이라면 "완료된 트레젝토리부터 바로 훈련 투입"이 인프라 활용률 문제의 정해임. 다만 단일 롤아웃은 분산 관리를 가치 모델에 전부 떠안기므로, critic 설계에 공을 들일 준비가 안 되면 GRPO 유지가 나음.

11. 한계도 남아 있음. 1T+ 규모 검증이 없고, frozen attention이 다른 아키텍처에서도 유효한지 미확인임. 그리고 GLM-5.2가 공개 모델이라 해도 재현에 필요한 튜닝 노하우가 논문에 다 담기진 않았음.

12. 그래도 방향은 명확함. 에이전트 RL의 병목은 점점 알고리즘보다 파이프라인 구조로 옮겨가고 있음. 완료되는 족족 쓰는 구조가 느린 그룹을 기다리는 구조를 이기는 건 자연스러운 귀결임.
