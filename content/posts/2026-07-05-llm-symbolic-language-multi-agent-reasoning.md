멀티에이전트 파이프라인을 돌리면 토큰 비용이 곧 배포 비용임. 에이전트 간 통신을 자연어로 쭉 쓰는 게 기본값인데, ICML 2026 논문이 이 전제를 깨는 결과를 냈음. 원문은 [arXiv:2606.29354](https://arxiv.org/abs/2606.29354).

1. 문제 설정부터임. Chain-of-Thought는 추론 성능을 올리지만 자연어 사고 과정은 필연적으로 김. 인간 가독성을 위해 쓰는 언어가 LLM 내부 추론에도 최적일 보장은 없음. 그러면 모델이 자기한테 맞는 압축 언어를 스스로 만들면 안 되나가 논문의 질문임.

2. CLSR는 다중 에이전트로 이걸 해결함. 에이전트들이 각자 컴팩트한 상징 언어(LSF)를 제안하고, 서로 비평하고, 변이시키고, 정확도-토큰 비용 기준으로 선택함. 진화 세대가 깊어질수록 더 나은 언어가 살아남음. 인간이 문법을 설계하는 게 아니라 선택 압력이 설계함.

3. 결과 숫자는 실용적임. 표준 CoT 대비 생성 토큰 3~6배 절감, 7개 벤치마크에서 정확도는 유지 또는 소폭 상승. Qwen3-8B/32B, LLaMA3-8B, DeepSeek-R1에서 다 유효했다는 점이 백본 종속성이 아니라는 근거임.

4. 근데 핵심 장치는 라우팅임. 추론 시점에 라우터가 쿼리 난이도를 보고 전략을 고름. 쉬운 쿼리는 저렴한 LSF 하나로 빠르게 끝내고, 어려운 쿼리만 여러 LSF를 앙상블하거나 다중 라운드로 돌림. 난이도별 연산 차등 배분이라는 발상은 검증 에이전트 쪽에서도 반복 검증된 패턴임.

5. 이걸 업무 자동화에 어떻게 쓰나. 에이전트 A가 조사 결과를 에이전트 B에 넘길 때 자연어 리포트 대신, 반복 작업 도메인에서는 도메인 약어 체계를 프롬프트로 굳혀두는 식으로 축소판을 먼저 만들 수 있음. 필자 블로그 파이프라인도 "요약→재작성→게이트" 단계 간 전달 페이로드를 줄이면 그대로 비용 절감임. LSF 전체를 도입 안 해도 전달 포맷 압축만으로 이득이 남.

6. 이론 기여도 참고할 만함. 임의 상징 체계에서 정확도 달성에 필요한 최소 토큰 수의 정보이론적 하한을 도출했고, 충분히 표현력 있는 언어와 라운드가 있으면 코드 실행 기반 추론을 상징 통신으로 모방 가능함을 증명함. "압축 언어가 성능 천장을 만든다"는 직관적 우려를 부정한 셈임.

7. 문제제기. 벤치마크가 수학·QA에 치중돼 있음. 코드 생성이나 창작, 실무 문서 처리에서 LSF가 어떤 형태가 될지는 미지수임. 그리고 라우터 + LSF 풀 + 다중 에이전트 조정은 시스템 복잡도를 키움. 관리 비용이 절감 토큰을 못 먹는 소규모 파이프라인이면 그냥 자연어 압축 프롬프트가 나음.

8. 그래서 남는 판단은 이거임. 멀티에이전트 통신 비용이 실제로 아픈 규모(하루 수만 호출급)에서만 CLSR 계열 접근이 이득임. 그 아래 규모는 전달 포맷 압축으로 충분함. 비용 그래프를 먼저 그리고 기술을 고르는 순서가 맞음.
