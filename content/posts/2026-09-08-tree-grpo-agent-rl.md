Tree-GRPO(ICLR 2026, Alibaba AMAP)는 에이전트 RL의 롤아웃을 독립 체인 대신 트리 탐색으로 뽑고 트리 노드를 Thought-Action-Observation 스텝 단위로 잡는 방법임. GRPO(같은 문제의 여러 답을 서로 비교해 학습하는 강화학습 알고리즘)의 트리 확장판임. 원문은 [arXiv:2509.21240](https://arxiv.org/abs/2509.21240), 코드는 [GitHub](https://github.com/AMAP-ML/Tree-GRPO)에 공개돼 있음.

1. 문제는 두 가지 고비용임. 첫째, 롤아웃 예산. 멀티턴 에이전트 궤적은 수천 토큰에 도구 호출 여러 개인데 GRPO 계열은 프롬프트마다 독립적인 완전 궤적을 N개 뽑아서 앞부분이 거의 겹치는 샘플을 매번 처음부터 다시 생성함. 검색 API 같은 유료 도구가 붙으면 더 아픔. 둘째, 희소한 감독 신호. 보상은 결과 하나로만 들어오는데 어떤 스텝이 성공·실패에 기여했는지 모름.

![Tree-GRPO 개요](/images/2026-09-08-tree-grpo-agent-rl/fig-1-p1.png)

2. 출발점이 명확함. 궤적을 공통 접두사를 공유하는 트리로 뽑으면 같은 예산으로 샘플이 늘고, 분기점마다 형제 서브트리 간 보상 차이가 스텝 단위 신호가 됨.

![](/images/2026-09-08-tree-grpo-agent-rl/gifs/tree-branches.gif)

3. 노드 정의가 핵심 차이임. 기존 트리 기반 RL은 노드를 토큰이나 문장 단위로 잘랐는데 Tree-GRPO는 하나의 완전한 에이전트 스텝(생각, 행동, 관찰 쌍)으로 잡음. ReAct 구조처럼 스텝 경계가 명확한 태스크에 맞는 단위임.

4. 샘플링은 세 단계임. 프롬프트마다 M개 독립 체인을 트리 씨앗으로 뽑고, 각 트리에서 완결 리프를 제외한 노드 N개를 무작위로 골라 그 노드까지의 전체 컨텍스트에서 나머지를 이어 생성해 새 가지로 삽입함. 이걸 L번 반복하면 프롬프트당 M×(L×N+1)개 롤아웃이 나옴. 확장은 평균적으로 최대 깊이의 절반 지점에서 시작해서 한 번 확장의 기대 비용이 완전 궤적의 절반이고, 같은 예산에서 체인 방식 대비 약 1.5배 샘플을 확보함.

![트리 샘플링 구조](/images/2026-09-08-tree-grpo-agent-rl/fig-3-p4.png)

![](/images/2026-09-08-tree-grpo-agent-rl/gifs/buy-one-get-one.gif)

5. 어드밴티지는 두 층위의 합임. intra-tree는 같은 트리 안 롤아웃끼리 그룹을 만드는데 스텝 단위 선호학습 목적이 들어있지만 가지 수가 적으면 베이스라인 추정이 불안정함. inter-tree는 전체 트리의 롤아웃을 묶어서 베이스라인은 안정적이지만 과정 신호가 없음. 두 개를 더해서 씀. 소거 실험에서 intra-tree만 쓰면 가지 수가 적을 때 학습이 붕괴하는데 inter-tree를 더하면 회복돼서 +16% 개선이 유지됨.

6. 이론 결과가 깔끔함. 이진 선호 가정 하에서 intra-tree GRPO의 그래디언트 구조가 step-level DPO(선호 쌍을 비교해 모델을 학습시키는 선호학습 알고리즘)와 동일하고 차이는 가중치 항뿐임. 트리 구조가 온라인 RL 안에 암묵적 스텝 단위 선호학습을 끼워 넣는 셈임. PRM(각 단계의 기여도에 점수를 매기는 별도 보상 모델) 같은 추가 주석이나 모델 없이 결과 보상만으로 과정 신호가 자동으로 만들어진다는 게 실무적 매력임.

7. 결과. 11개 데이터셋에서 Qwen2.5와 Llama3.2의 1.5b-14b로 실험함. 멀티홉 QA에서 체인 기반 GRPO 대비 3b 이하 모델에서 +16~+69% 상대 개선. Qwen2.5-1.5b는 체인 기반이 멀티턴 도구 사용을 거의 학습 못 하는 반면 SFT 없이도 ReAct 패러다임을 습득함. 예산 2롤아웃/프롬프트 극저예산에서는 +112%까지 벌어지고, Qwen2.5-3b 기준 체인 GRPO와 동등한 성적을 예산 1/4로 달성함.

![벤치마크 개선 폭](/images/2026-09-08-tree-grpo-agent-rl/fig-5-p9.png)

8. 개선 폭이 갈리는 조건도 정직함. 싱글홉 QA는 +1~+9%에 그침. 한두 번 검색으로 끝나서 트리 깊이가 얕아 과정 신호의 이득이 제한적이기 때문임. 웹 에이전트 QA는 GAIA에서 평균 +28%인데 BrowseComp처럼 수십 회 웹 상호작용이 필요한 벤치마크는 학습 데이터가 못 미쳐 개선이 미미했다고 한계를 인정함.

9. 부수 효과도 값짐. 희소 보상에 노출된 체인 기반 모델은 짧은 지름길로 수렴하는 경향이 있는데 트리 기반은 평균 도구 호출 수가 2.4에서 3.0으로 늘며 더 긴 탐색을 유도함. 소형 모델의 학습 안정성도 트리 기반이 우세했음.

10. 내 실무 판단. 토큰·도구 호출 예산이 실제 병목인 멀티턴 에이전트 RL에서 트리 샘플링은 예산 효율과 크레딧 할당을 동시에 개선하는 구조적 선택지임. 작은 모델 + 빠듯한 예산 + 긴 호라이즌 조합일수록 이득이 크고 큰 모델의 싱글홉성 태스크엔 기대할 게 없음. 대가도 있음. 트리 수를 줄이고 확장을 늘리면 같은 예산에 롤아웃은 많아지지만 탐색 범위가 좁아지고, 병렬 추론 엔진에 순차적 멀티턴 롤아웃이 붙는 트리 탐색은 구현이 성가심.

11. 결론. 롤아웃 샘플 방식(공유 접두사 트리), 노드 정의(에이전트 스텝 단위), 어드밴티지 두 층위 합이라는 세 결정이 같은 예산으로 샘플 1.5배와 무료 과정 신호를 동시에 가져옴. 에이전트 RL 예산 설계의 기본 옵션 후보로 올려둘 논문임.
