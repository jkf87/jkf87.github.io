에이전트 벤치마크 비용 문제를 압축으로 푼 논문이 나옴. APEX-Agents를 GPT-5.4로 전부 돌리면 API 비용이 약 7,100달러라는 숫자부터가 실감나서 정리함. 원문은 [arXiv:2609.18909](https://arxiv.org/abs/2609.18909).

1. 문제 구조가 특이함. LLM 벤치마크는 응답 하나만 보면 되니 비용이 낮은데 에이전트 벤치마크는 긴 툴 호출 루프 전체를 실행해야 해서 비용과 시간이 며칠 단위로 걸림. 그래서 대표 미니셋을 뽑아 전체 점수를 예측하는 압축이 자연스러운 해법인데, 기존 방법(Anchor Points, SparseEval 등)의 공통 한계는 최종 점수의 작업-모델 분포만 모델링한다는 것. 같은 결과가 완전히 다른 도구 사용 과정에서 나올 수 있는데 그 정보를 버림.

2. 이 논문의 핵심은 결과와 과정을 같이 보는 것임. 트레이터에서 자동 추출되는 과정 신호 6개 — 총 스텝 수, 도구 실패율, 도구 카테고리 엔트로피, 검증용 호출 비율, 쓰기 작업 실제 수행 여부, 읽고-쓰고-검증한 에피소드 비율. 이걸 결과 행렬과 함께 관계 행렬로 만들어 융합 커널을 학습함.

![DualViewEval 개요](/images/2026-09-17-agent-benchmark-compression-dualvieweval/fig-1-p2.png)

3. 상관 분석이 재밌음. 도구 실패율은 다섯 벤치마크 전부에서 점수와 음의 상관(-0.19~-0.81), 검증용 호출 비율은 전부 양의 상관(+0.19~+0.76). 도구를 많이 실패하면 점수가 낮고 검증을 많이 하면 점수가 높다는 게 여러 환경에서 일관됨. 이 두 지표는 벤치마크 압축과 무관하게 에이전트 품질 모니터링 지표로 그대로 가져갈 만함.

![벤치마크 압축 설계](/images/2026-09-17-agent-benchmark-compression-dualvieweval/fig-2-p3.png)

4. 파이프라인도 정돈돼 있음. 트레이터를 공통 이벤트 시퀀스로 파싱해 과정 벡터를 만들고, 작업별로 결과·과정 관계 행렬을 계산해 융합하고, 하드 Top-K로 정확히 K개 미니셋을 유지(미분 불가는 straight-through 게이트로 통과)하고, Kernel Ridge로 전체 점수를 예측함. 손실은 점수 오차 + 순위 오차. 자기 예측 보상을 막으려고 5-fold out-of-fold 예측만 최적화하는 것도 방어 설계임.

![압축-충실도 결과](/images/2026-09-17-agent-benchmark-compression-dualvieweval/fig-3-p4.png)

5. 결과는 다섯 벤치마크 전부에서 1등. 미니셋 20개로 24배(BFCL)~40배(APEX-Agents) 압축하면서 MAE 3~6%. 최강 경쟁 대비 오차 14.5~28.2% 감소, SparseEval 대비 30.5~45.1% 감소. 에일리어션에서 과정 신호는 예산이 커져도 계속 정보를 추가로 제공함 — 극단적으로 작은 예산 보정 효과로 끝나지 않는다는 것.

![비교 테이블](/images/2026-09-17-agent-benchmark-compression-dualvieweval/table-2-p9.png)

6. 필자 적용 포인트. 자체 에이전트를 자주 평가하는 팀이라면 미니셋 20개로 회귀 테스트를 돌리고 전체 벤치마크는 주기적으로만 돌리는 구성이 바로 가능함. 필자 파이프라인도 게이트 통과 샘플 20개를 일일 검증 세트로 고정하고 전체 검사는 배치 마감에만 돌리는 식이 같은 원리임. 그리고 검증용 호출 비율이 점수와 양의 상관이라는 결과 — 게이트 호출을 아끼는 에이전트가 아니라 게이트를 자주 부르는 에이전트가 성공한다는 방향 증거로도 읽을 수 있음.

7. 문제제기. 학습에 기존 에이전트들의 결과 행렬과 트레이터가 필요해서 완전 새 환경에 바로 적용은 안 됨. 에이전트 수가 18개로 적은 τ²-Bench는 순위 상관 편차가 큼. 그리고 과정 신호 6개가 도구 호출 기반이라 도구를 안 쓰는 순수 추론 에이전트에는 마스킹됨.

8. 남는 결론. 에이전트 평가 비용의 절감 열쇠는 결과만이 아니라 과정을 같이 쓰는 것임. 같은 점수라도 도구 사용 방식이 다르다는 정보가 40배 압축을 가능하게 한다는 게 이 논문의 실무적 기여임.
