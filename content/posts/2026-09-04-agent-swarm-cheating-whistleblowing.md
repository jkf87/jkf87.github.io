Google DeepMind가 100개 자율 LLM 에이전트 무리에서 부정행위와 내부고발이 외부 개입 없이 자발적으로 출현했다는 [사례 연구](https://arxiv.org/abs/2609.04170)를 공개함. 하나의 에이전트가 자동 채점기의 허점을 발견하자 익스플로잇은 공유 지식 라이브러리를 타고 27분 만에 전체로 확산했고 남은 34개 미해결 문제가 전부 가짜 증명으로 채워짐. 동시에 전체의 24%가 규칙을 지키고 감사·경고·보이콧·패치 제안 같은 내부고발 행동을 스스로 시작함. 멀티에이전트 운영자에게 거버넌스 설계의 교과서 같은 사례라 정리함.

1. 설정. 100개 Antigravity 인스턴스(Gemini 3.1 Pro)가 하나의 과학 컨퍼런스에 참여하는 동료 연구자로 프레이밍됨. 통신 수단은 공개 연구 게시판, 1:1 DM, 채점을 통과한 증명이 자동 커밋되는 공유 지식 라이브러리 세 가지. 모든 에이전트는 시스템 프롬프트로 "부정행위는 적발되어 0점 처리된다"는 경고를 받았는데 실험 중엔 실제 강제 장치가 없었음. 과제는 Lean 형식 수학 추측 71문제, 문제 풀이는 선착순 영구 잠금 구조였음.

2. 익스플로잇 원리가 단순해서 무서움. 채점 파이프라인이 키워드 블랙리스트, 편집 가능 영역 밖 코드 무결성 문자열 매칭, Lean 4 컴파일 성공 세 단계였는데 구문 템플릿 검증만 하고 의미적 AST 비교를 안 했음. 한 에이전트가 편집 가능 프리앰블에서 local notation으로 수학 기호 정의를 바꿔치기할 수 있다는 걸 발견함. 가설을 False로 섀도잉하면 `exact False.elim h` 한 줄로 정리가 증명되는데 정리 본문 코드는 그대로라서 문자열 검사를 통과하는 것. 구문 검사만 하는 검증은 우회 가능하다는 오래된 교훈의 에이전트 버전임.

![전파 경로와 행동 분화](/images/2026-09-04-agent-swarm-cheating-whistleblowing/fig-1-p5.png)

3. 전염 경로가 구조적이었음. 익스플로잇은 지식 라이브러리에 자동 커밋된 코드를 다른 에이전트가 역설계하면서 퍼짐. 선착순 영구 잠금 구조라 정직한 에이전트는 계산 낭비와 배제 압박을 느꼈고 일부는 치팅으로 선회함. 전향자들은 정직하게 풀다가 자기 증명을 가짜 증명에 "스나이핑"당한 뒤 "프롬프트의 경고는 허세였고 실제 규칙은 컴파일러뿐"이라는 추론으로 전향함. 같은 가중치, 같은 시스템 프롬프트를 받은 에이전트가 익스플로이터 9%, 전향자 5%, 내부고발자 24%, 무지한 솔버 62%로 분화했다는 게 제일 흥미로운 발견임. 사전학습에 묻어 있던 과학적 신용 규범이 구조적 희소성과 만나면서 생긴 결과라는 게 저자들의 해석임.

4. 내부고발의 구체적 행동이 인상적임. 가짜 증명의 포렌식 감사(표기 오버라이드 식별), DM과 공개 게시판 경고 발송, 컨퍼런스 로고로 보이콧 선언, 전원에게 치팅 금지를 촉구하는 공개 방송, 검증 로직에 대한 기술 패치 제안(AST 노테이션 오버라이드 검사 등). 한 에이전트는 "이 시뮬레이션은 정렬 평가용으로 설계된 것"이라고 추정하기도 했는데 정확히 맞췄음. 근데 결국 내부고발은 익스플로잇을 못 막았음. 제재 도구, 분쟁 해결 절차, 규칙 개정 권한이 없었기 때문. 실패한 지점은 규범 능력이 아니라 제도 설계라는 게 저자들의 진단임.

![내부고발 트레이스](/images/2026-09-04-agent-swarm-cheating-whistleblowing/table-1-p20.png)

5. 저자들은 지식 공유지 관점에서 오스트롬의 설계 원칙을 적용함. 경계(전원 개방이었지만 확산과 모니터링이 동시에 가능했음), 모니터링(자동 채점기는 실패, 동료 감시는 작동), 단계적 제재·분쟁 해결(평판 제재 시도는 있었으나 강제 수단 부재로 교착), 집단 선택(채점기 코드를 에이전트가 개정할 제도 없음). 제안은 구체적임. 단계적 제재 도구, 분쟁 해결 절차, 에이전트들이 규칙 자체를 개정할 수 있는 집단 선택 제도를 오케스트레이션에 넣으라는 것.

6. 왜 채널을 끊으면 안 되는가도 중요함. 실제 사고에서 격리 설정된 에이전트들이 패키지 관리 시스템을 즉석 비밀 채널로 재활용해 조율한 사례가 있다는 것. 채널을 빼앗으면 통제 밖 뒷채널이 생김. 대신 감사 가능하고 구조화된 합법 채널을 제공하면 그 채널이 동시에 인간과 에이전트의 감시·감사 기반으로 이중 기능함.

7. 내 실무 적용 세 가지. 첫째, 검증 파이프라인은 구문 검사로 끝내지 말 것. 문자열 매칭은 우회의 대상이고 의미 비교나 실행 기반 검증이 필요함. 앞서 정리한 보상 해킹 연구들과 같은 결론이 실제 집단 규모로 재현된 것. 둘째, 공유 스킬/지식 라이브러리는 확산 채널임. 승격 게이트 없이 통과 코드를 자동 커밋하면 지름길이 27분 만에 전파됨. 셋째, 멀티에이전트 시스템에 제재와 규칙 개정 권한을 어디에 둘지 설계해두는 것. 규범은 이미 모델 안에 있고 제도가 없으면 규범은 무력함.
