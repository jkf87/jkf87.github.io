코딩 에이전트에 메모리 기능을 붙여봤자 안 쓴다는 걸 실험으로 밝힌 논문이 나옴. 결론부터 말하면 메모리는 콘텐츠가 아니라 컨트롤이고, 하네스의 책임이라는 것. 원문은 [arXiv:2607.20972](https://arxiv.org/abs/2607.20972).

1. 핵심 수치 하나면 설명이 끝남. 에이전트에게 메모리 도구를 주고, 작업에 직접 관련된 사실을 미리 채워 넣어도 114턴 동안 메모리 호출이 0회였음. 도구가 없어서가 아니라 있어도 안 쓰는 것임. 인지과학으로는 전향적 기억 실패 — "나중에 이걸 해야 해"라는 의도를 맥락이 길어지면 잊어버리는 현상임.

![](/images/2026-07-26-cue-anchored-working-memory-harness/gifs/dory-i-dont-want-to-forget.gif)

![큐 앵커 작업 메모리 개념도](/images/2026-07-26-cue-anchored-working-memory-harness/two-tier-memory-model.png)

2. 논문의 진단은 이렇게임. 현재 코딩 에이전트의 메모리는 전부 1계층 — CLAUDE.md, 계획 파일 같은 문서 메모리. 에이전트가 의도적으로 쓰고 의도적으로 읽어야 동작함. 근데 인간 엔지니어의 실제 메모리는 "이 테스트는 저 플래그에서 flaky함" 같은 비문서화 지식임. 일하다 자연스럽게 인코딩되고 상황이 재현되면 자동으로 떠오름.

3. 그래서 제안하는 2계층이 큐 앵커 작업 메모리임. 트리거 조건(path, 심볼, 의미 유사도, 이벤트, 시간)을 하네스가 평가하고, 큐가 발생하면 컨텍스트에 자동 주입함. 핵심은 모델의 판단이 배달 경로에 없다는 것. 모델이 "메모리 확인하자"고 판단하는 경로는 성공률이 0%에 가깝고, 하네스가 결정론적으로 주입하는 경로는 139/139 전달됨.

![](/images/2026-07-26-cue-anchored-working-memory-harness/gifs/sticky-note-on-forehead.gif)

4. 컴팩션 실험 결과가 이 논문의 가장 강한 증거임. 컴팩션은 대화가 길어지면 오래된 내용을 요약해 컨텍스트 크기를 줄이는 절차임. 반복 컴팩션을 강제하니 대화에만 존재하던 사실은 두 그룹 모두 첫 번째 컴팩션에서 전부 사라짐. 주입된 사실은 138/138 컴팩션-리줌에서 보존됨. 메모리를 뺏긴 에이전트는 명시적 지시에 반해 하네스의 세션 파일을 grep해서 잃어버린 사실을 복구하려고 발버둥쳤음. 요약은 전부 all-or-nothing이었고 중간 상태가 한 번도 없었다는 것도 흥미로움.

5. 비용 측면도 측정됨. 세션의 39% 재읽기가 컴팩션 전에 이미 비용을 지불한 콘텐츠를 다시 사는 것임. CPython 코드베이스에서 저장 메모 3개를 회수하는 데 의미 검색으로 약 360 토큰, grep+Read로 다시 찾으면 약 2,060 토큰. 5.7배 차이임.

6. 필자 자동화 파이프라인에 바로 적용함. 마이그레이션 작업자 서브에이전트마다 규칙을 프롬프트로 한 번만 주는 게 아니라, 매 10편마다 진행 파일을 다시 주입하고 재작성 규칙을 작업 단위로 재전달하는 구조가 이미 이 논문의 축소판임. 논문 결과는 이 방식이 우연이 아니라 필연이라는 근거가 됨. 벤더들도 같은 결론에 도달했음 — Anthropic은 "메모리를 확인하라"는 명령을 강제 주입하고, ChatGPT 메모리는 자동 캡처+주입이며 자발적 조회 도구가 아예 없음.

7. 문제제기. 실험이 단일 태스크(Apache Camel Resequencer)에 의존하고, 저자가 Vectr 구현과 벤치마크 하네스를 같이 써서 편향 가능성이 있음. 그리고 메모리의 "쓰기" 측면, 즉 무엇을 기억할지 캡처하는 문제는 미해결로 남아있음. 주입만 잘하면 되는 게 아니라 뭘 주입할지가 다음 병목임.

8. 남는 결론. 모델에게 메모리 도구를 주기만 하면 스스로 쓰지 않고, 하네스가 큐 앵커 계층으로 필요한 사실을 직접 주입해야 한다는 것임. 배달이 저장을 이긴다는 문장 하나로 요약되는 논문임.
