최적화 에이전트가 현실 운영의 연속 변경 요청을 못 처리한다는 문제를 상태 유지로 푼 논문이 나옴. 하네스 설계 원칙이 많이 보여서 정리함. 원문은 [arXiv:2609.11636](https://arxiv.org/abs/2609.11636).

1. 문제 정의가 실무 그대로임. 기존 LLM 최적화 에이전트는 자연어를 모델·솔버 코드로 바꿔 실행하는 건 강한데 한 번 처리하고 끝남. 근데 실제 운영은 동적임 — 신규 주문, 차량 이탈, 우선순위 변경. 이때 필요한 건 앞서 정한 배정 유지, 과거 탐색의 유용한 후보 재사용, 데이터·제약이 바뀌어도 기존 결정과 모순되지 않는 수정임. 매번 처음부터 다시 만들면 셋 다 안 됨.

2. 구조의 첫 축은 TSS 워크벤치임. LLM이 전부 손으로 짜는 대신 결정 세그먼트에 타입(배정, 순열, 실수 벡터)을 선언하면 초기화·교차·변이·리페어 연산자가 타입에 맞게 고정 바인딩됨. 솔버 선택도 선형이면 LP/MILP, 조합이면 GA, 다목표면 NSGA-II로 선언된 공식이 결정함. LLM이 쓰는 건 build_problem과 evaluate 두 함수뿐이라 코드 생성의 실패 면적이 좁아짐.

![MAPLE 프레임워크](/images/2026-09-13-maple-memory-augmented-optimization-agent/fig1-framework.png)

3. 두 번째 축은 상태 관리 둘임. LPD가 업데이트 요청을 읽고 데이터 테이블·결정 선언·평가 로직 중 어디가 바뀌어야 하는지 특정함(180개 업데이트 중 170개에서 실제 편집과 일치). LSM이 이벤트·수락된 결정·탐색 후보를 저장해서 "그 고객 차량 유지" 같은 참조 요청을 수락된 계획에서 꺼내 검색 중 강제함. 3단계 참조를 거치는 요청 포함 30/30 해석, 18/18 배정 유지 정확 강제.

4. 세 번째는 재시작 선택기임. 업데이트마다 Warm(이전 개체군 절반까지 그리디 리페어 후 재평가)과 Full(전면 재시작) 중 선택하는데, LLM이 재사용 위험을 평가해 제안하면 고정 증거 게이트가 알고리즘으로 검증해 최종 결정함. 파괴적 변경 직전엔 재사용, 이후엔 재시작이라는 타이밍 판단이 게인을 만듦. 컴파일·계약·스모크 테스트 실패 시 유한 횟수 리페어 후에도 유효하지 않으면 업데이트를 거부하고 이전 상태를 유지함 — 상태 롤백 원칙이 안전장치임.

![업데이트 처리 흐름](/images/2026-09-13-maple-memory-augmented-optimization-agent/fig3-update-flow.png)

5. 결과는 동적 설정에서 압도적임. NLDO 벤치마크 15 트라젙토리 180 업데이트 전부 완주하며 단일목표 품질 0.951, 다목표 하이퍼볼륨 0.875. Persistent ReAct는 0.501/0.042, ORLM은 다목표 0.000였음.

6. 근데 정직한 반전이 있음. 정적 단발 모델링인 NLP4LP-hard에선 OptiMUS(69.5%)가 MAPLE(59.3%)보다 높음. MAPLE의 이득은 연속 갱신 상황에 특화돼 있다는 걸 숫자가 그대로 보여줌. 만능이 아니라 용도가 명확한 도구라는 것.

7. 절제 연구에서 TSS 제거의 결과가 설계 교훈의 핵심임. TSS를 빼면 LLM이 직접 짠 코드에서 사고가 나서 720개 결과 중 140개가 무효가 됨. 원인이 구체적인데 "차량이 경로 하나만 담당한다"는 검사가 빠지고 GPU 비호환 배치를 못 걸렀다는 것. 스캐폴딩이 유효성의 핵심이고, 토큰도 72.8k→51.6k로 줄어서 품질과 비용을 동시에 잡음.

8. 필자 적용 포인트. 이 논문의 기여는 "더 똑똑한 LLM"이 아니라 상태를 유지하는 실행 구조 + 코드 생성 면적을 줄이는 타입 시스템 조합임. 둘 다 바로 벤치마킹할 만함. 첫째, LLM 제안을 고정 증거 게이트가 검증하는 설계 — 필자 게이트 구조와 같은 원칙의 다른 구현임. 둘째, 무효 출력엔 상태 롤백이라는 규칙 — 마이그레이션 중 게이트 실패 파일을 되돌리는 처리와 동일함. 셋째, LLM이 짜는 코드 면적을 타입 선언으로 줄이는 접근 — 반복 작업 스크립트를 템플릿 + 슬롯 선언으로 바꾸면 사고 면적이 줄어든다는 원칙임.

9. 문제제기. NLDO가 합성 데이터 기반이라는 걸 논문이 Ethics 항목에 명시함. 재시작 선택의 에피소드 평균 게인이 0.010에 p=0.219로 통계적 유의성이 약함. 메인 모델 외에 Kimi k2.7로 확인한 결과가 소폭 하락해서 모델 의존성도 완전히 배제된 건 아님.

10. 남는 결론. 동적 운영 환경의 최적화 에이전트는 상태 유지와 스캐폴딩이 성패를 가름함. 파이프라인을 설계할 때 "LLM이 결정하는 영역을 어디까지로 좁을 것인가"가 첫 질문이라는 게 이 논문이 남기는 실무 원칙임.
