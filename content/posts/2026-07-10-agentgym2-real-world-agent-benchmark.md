에이전트 벤치마크에서 90점을 받았다. 배포하면 40점으로 떨어진다. 왜인지 ACL 2026에 나온 AgentGym2가 명확히 보여줌. 기존 벤치마크가 너무 친절했다는 것. 도구가 미리 골라져 있고, 지시는 깨끗하고, 중간 단계는 생략되어 있었음. 에이전트 도입 검토 중이라면 벤치마크 점수 만으로 모델을 고르는 습관을 고칠 계기가 되는 글임.

1. 구조를 먼저 보면, 기존 벤치마크는 도구를 미리 골라주고 지시를 정확하게 주는 구성이었음. AgentGym2는 도구도 직접 찾고 지시도 지저분한 상태로 풀게 함. 구체적으로 도구는 사전 선택이 아니라 범용 도구 박스에서 스스로 발견해야 하고, 입력에는 잡음과 모호성이 섞여 있고, 과제는 단편 작업이 아니라 데이터 수집부터 분석까지 end-to-end(처음부터 끝까지 전 과정을 한 번에 수행)임. 여기에 일부러 방해 요소(distractor, 과제와 무관한 정보·도구)를 주입함.

![Figure 3: AgentGym2 프레임워크 개요. Environment, Tools, Configurations, Agent의 4계층 구조로, 에이전트를 도구와 환경으로부터 분리한다.](/images/2026-07-10-agentgym2-real-world-agent-benchmark/fig3-framework-overview.png)

2. 도구 박스는 웹 브라우징, 정보 검색, 파일 처리, 멀티모달 이해, 코드 실행 5개 카테고리에 27개 이상의 액션임. 특정 과제에 맞춘 도구가 아님. 에이전트가 조합을 스스로 찾아야 함. 도메인은 GitHub, Reddit, Kaggle 등 실제 플랫폼의 사용자 요청 기반으로 27개 이상. 시나리오는 복잡 도구 사용, 데이터 분석, 심층 검색 세 축임.

3. 결과가 핵심임. 15개 모델을 돌려서 GPT-5가 약 44%, Claude Sonnet 4.5가 약 37%. 최첨단 모델조차 절반을 못 풀었음. 오픈소스 Nex-N1 계열은 에이전트 post-training(기반 모델을 공개한 뒤 추가로 하는 하류 과제 훈련)으로 9~10%p 향상됨. 모델 크기 스케일링은 효과가 있었지만, 상호작용 라운드를 늘리는 건 성능으로 이어지지 않았음. "더 생각하게 하자"는 프롬프팅의 한계를 보여주는 대목임.

4. 잡음 실험이 실무적으로 제일 뚜렷함. 검색 쿼리에 잡음을 주입하니 GPT-5가 7.4%, Claude가 6.4% 하락함. 실제 사용자 질문은 지저분함. 오타, 모호한 표현, 불완전한 맥락이 기본값임. 클린 쿼리로 만든 데모와 실사용 사이의 간극이 이 숫자로 나타난 것임.

![Figure 1: 비용, 상호작용 라운드 수, 파라미터 규모에 따른 성능 변화. 현실 환경에서는 더 많은 상호작용이 항상 더 나은 결과로 이어지지 않는다.](/images/2026-07-10-agentgym2-real-world-agent-benchmark/fig1-performance-dimensions.png)

5. 반복 실패 패턴이 세 가지로 정리됨. 불충분한 탐험, 즉 충분히 둘러보기 전에 성급히 답함. 환각, 즉 없는 도구나 정보를 쓰려 함. 도구 조합 실패, 즉 개별 도구는 다루면서 여러 개를 묶지 못함. 내 에이전트 로그를 열어보면 대부분 이 세 가지 중 하나로 분류될 것임. 디버깅 카테고리를 미리 세워두면 원인 파악이 빨라짐.

6. 그래서 내 결론은 이렇게임. 첫째, 벤치마크 점수는 스크리닝 용도로만 쓰고, 자사 워크플로우에서 직접 평가할 것. 둘째, 평가 세트를 설계할 때 도구 발견(스스로 찾게 하기), 잡음 주입, end-to-end 과제를 최소 하나씩은 포함할 것. AgentGym2가 그 설계의 참고 틀이 됨. 셋째, 모델 교체보다 에이전트 post-training과 도구 탐색 설계에 힘을 쓸 것. 거기서 두 자릿수 향상이 나왔음.

근데 이 벤치마크도 완전한 현실은 아님. 통제된 주입이지 진짜 운영 환경의 무작위성은 아님. 그래도 "무균실 평가"에서 한 단계 나온 것 자체가 가치임. 44%라는 숫자는 겸손의 근거이자 개선 방향의 좌표임.
