에이전트 성능은 모델만큼 실행 환경, 즉 하네스가 결정함. 근데 하네스 튜닝은 아직도 사람 수작업임. 시스템 프롬프트 고치고, 서브 에이전트 배치 바꾸고, 결과 전달 규약 손보는 일을 반복함. Sakana AI가 이 작업을 자동화한 RHI(Recursive Harness Self-Improvement)를 냈음. 결론부터면 하네스를 스스로 개정하게 만드니 몇 번 만에 비싼 추론 설정보다 싸게 좋은 성적이 나왔다는 것임.

1. 첫 번째 전제는 하네스를 prompt-level 명세로 표현한다는 것임. 에이전트 루프 전체를 자연어로 서술함. 어떤 서브 에이전트가 있고 어떤 순서로 부르며 중간 결과를 어떻게 넘길지를 코드가 아니라 프롬프트로 정의함. 이래야 개선 루프가 돌 수 있음. 코드 수준 구조를 건드리는 게 아니라 프롬프트를 편집하는 작업으로 최적화가 환원되기 때문임.

2. 두 번째는 개선 신호의 출처임. 자기 실행 이력에서 pairwise 피드백을 뽑음. 이전 반복의 하네스 버전들을 짝지어서 "버전 A는 서브 에이전트 간 데이터 전달이 명시적이었고 B는 암시적이었으며 A가 12% 높았다" 식의 구체적 비교를 자동 생성함. 그걸 받은 코딩 에이전트가 다음 하네스를 개정함. 사람이 A/B 테스트 보고 설정 고치는 일의 자동화임.

![RHI 전체 파이프라인](/images/2026-07-21-recursive-harness-self-improvement/fig-2-p6.png)

3. 수렴이 빠른 게 놀라움. 양적 금융, 로보틱스, 약학 도메인의 30개 ML 연구 태스크에서 2~3회 반복이면 충분했음. 하네스 최적화가 수십 번의 실험을 요구하는 게 아니라는 것. RHI가 최적화하는 지점은 두 군데로 압축됨. 문맥 관리, 즉 태스크 맥락과 오류 내역을 서브 에이전트에 어떻게 전달할지. 그리고 에이전트 간 정보 흐름, 즉 산출물 주고받기 구조임. 개선이 결국 "정보가 어떻게 흐르느냐"로 수렴한다는 통찰이 핵심임.

![RHI 하네스 분해](/images/2026-07-21-recursive-harness-self-improvement/fig-3-p9.png)

4. 성능 숫자를 보면 추론 비용 최대 60% 절감. 저비용 에이전트의 성능 한계를 최대 추론 노력 설정보다 위로 끌어올림. sonnet-4.6은 2회 반복 후, opus-4.7은 1회 반복 후에 test-time scaling의 경험적 한계가 상승했음. 토큰을 더 태우는 대신 정보 흐름을 고쳐서 성적을 낸다는 게 요지임.

![Sonnet 모델에서의 RHI 효과](/images/2026-07-21-recursive-harness-self-improvement/fig-5-p12.png)

5. 논문은 이걸 정보이론으로 설명함. 하네스는 본질적으로 태스크 관련 정보의 병목 채널임. RHI는 이 채널의 처리량을 암시적으로 최적화함. 그래서 토큰을 더 안 써도 모델이 더 정확한 결정을 내림. "프롬프트를 더 길게"가 아니라 구조를 고치는 것과 같은 효과라는 것. 비용 절감 논리가 부수 효과가 아니라 원리에서 나온다는 점이 이 방법의 설득력임.

![Opus 모델에서의 RHI 효과](/images/2026-07-21-recursive-harness-self-improvement/fig-6-p13.png)

6. 근데 한계부터 채점하고 써야 함. 평가가 30개 합성 ML 태스크임. 실제 프로덕션 일반화는 미검증. 도메인도 셋으로 좁음. 그리고 prompt-level 표현이라 새 도구 추가 같은 코드 수준 구조 변경은 못 다룸. 그럼에도 실무에 가져올 것은 명확함. 첫째, 하네스 프롬프트를 버전 관리 대상으로 보고 실행 이력과 짝지어 저장할 것. 둘째, 하네스 개정을 사람 직접 수정 대신 "두 버전 실행 비교 → 개선안 생성" 루프로 한 번 돌려볼 것. 셋째, 추론 예산을 올리기 전에 정보 흐름 구조부터 점검할 것. 60% 절감이 항상 나오진 않겠지만 방향 확인은 저렴함.
