AI 에이전트의 추론은 전부 텍스트 공간에서 일어남. 이미지를 봐도 일단 글자로 바꾸고, 글자로 생각하고, 결과물이 필요하면 다시 렌더링함. 이 우회 경로가 물리적 일관성을 자주 잃어버린다는 문제의식에서 [UniVR](https://arxiv.org/abs/2607.12800)이 나옴. 텍스트를 거치지 않고 시각 공간에서 직접 추론하는 프레임워크임. 당장 쓸 수 있는 도구는 아니지만, 에이전트 설계 관점에서 짚어둘 지점이 있어 정리함.

1. 배경. Gemini, GPT, Qwen 같은 멀티모달 모델도 "보고 → 텍스트로 생각하고 → 다시 그리기" 경로를 씀. 근데 매듭 묶기나 옷 개기처럼 분 단위로 이어지는 장기 과제에서는 중간 과정의 미세한 물리 역학을 텍스트로 옮기는 순간 정보가 증발함. 사람은 언어 없이 머릿속에서 장면을 시뮬레이션하며 추론하는데, 그 능력을 AI에 넣겠다는 게 출발점임.

![시각 공간 추론 vs 텍스트 공간 추론](/images/2026-07-18-univr-visual-space-reasoning/fig1_univr_overview.png)

2. 설계는 단순함. 텍스트-이미지 쌍 없이 순수 시각 궤적만으로 학습함. 이미지 시퀀스와 명령이 들어오면 다음 프레임 분포를 직접 모델링함. 텍스트 추론 체인이라는 손실 많은 중간 표현을 통째로 빼버린 것. 베이징교통대와 ByteDance가 Emu3.5라는 통합 생성 모델 위에 올렸음.

3. 진짜 혁신은 보상 설계임. Visual Reasoning GRPO는 두 개의 보상을 결합함. 여기서 GRPO는 같은 문제에 여러 답(롤아웃)을 생성해 서로 상대 비교하며 정책을 학습하는 강화학습 기법임. 전체 궤적의 완성도를 보는 글로벌 보상과, 궤적 중 오류가 가장 나오기 쉬운 구간을 자동으로 찾아 집중 평가하는 스텝-포커 보상임. 후자의 동작이 재밌음. 여러 롤아웃(한 모델이 같은 상황에서 만들어낸 서로 다른 실행 경로)을 생성하고, 프레임 임베딩의 시간 단계별 분산을 계산해서, 롤아웃들이 가장 크게 갈리는 지점을 오류 발생 구간으로 판정한 뒤 VLM(시각언어모델, 이미지를 입력받아 이해·판단하는 모델)이 그 구간만 자세히 채점함.

![VR-GRPO 보상 설계](/images/2026-07-18-univr-visual-space-reasoning/fig3_vr_grpo_method.png)

4. 이 "분산이 큰 지점을 집중 평가한다"는 아이디어는 시각 전용이 아님. 내가 텍스트 에이전트 워크플로를 검증할 때도 그대로 쓸 수 있음. 같은 작업을 여러 번 돌려서 결과가 크게 갈리는 스텝이 바로 취약 구간임. 거기에 리뷰와 게이트를 집중 배치하면 전수 검사보다 싸고 정확함. 에이전트 파이프라인 디버깅을 어디서부터 할지 모를 때, 분산으로 스팟을 찾는 것부터 시작하면 됨.

5. 결과는 34B 파라미터 모델이 Gemini 3 Pro + Nano Banana 2 조합에 근접하고 장기 과제에선 능가함. 최대 25% 성능 향상. VR-X라는 자체 벤치마크에서 매듭 묶기, 옷 개기, 요리, 로봇 제어, 내비게이션 같은 분 단위 과제를 언어 없이 순수 시각으로 수행하게 평가함. 거대 폐쇄 모델 파이프라인 대비 오픈 모델 한 대로 이 성적이 나온다는 건 이 경로의 효율을 보여줌.

![Gemini 비교](/images/2026-07-18-univr-visual-space-reasoning/fig7_gemini_comparison.png)

6. 업무자동화 관점에서의 의미를 세 줄로 줄이면 이렇게 됨. 첫째, 로봇·임베디드처럼 텍스트 주석 없는 시각 데이터가 넘쳐나는 분야에서 정책 학습의 길이 열림. 둘째, 다단계 작업에서 중간 단계의 물리적 타당성을 유지하는 게 실제 배포의 병목이라는 걸 정확히 겨냥함. 셋째, 작업별 휴리스틱 없이 복잡한 궤적의 품질을 자동 평가하는 보상 설계라서 다른 도메인으로 옮겨질 수 있음.

7. 근데 냉정하게 볼 부분도 있음. 기반 생성 모델(Emu3.5)의 품질이 성능 상한선을 정함. 보상을 매기는 VLM 자체의 시각 세계 지식도 아직 제한적임. 심판이 부정확하면 RL이 그 부정확함을 증폭시킬 뿐이라, 이 구조의 약점은 보상 모델의 신뢰성에 그대로 묶여 있음. 분당 단위 비디오 생성과 RL 훈련 비용도 만만치 않다고 논문이 스스로 인정함.

8. 그래서 지금 시점의 실무 결론은 이렇게 됨. UniVR 자체를 당장 쓰긴 이르고, 남겨서 가져갈 건 두 가지임. 하나는 위에서 말한 분산 기반 취약 구간 탐지, 다른 하나는 "텍스트가 유일한 사고 매체가 아니다"라는 관점 자체. 브라우저 조작 에이전트, GUI 자동화를 다루는 사람이라면, 스크린샷을 텍스트로 기술해서 추론하는 현재 구조가 왜 자꾸 중간에 무너지는지 이 논문이 설명해 줌.

9. 돌아보면, 언어 중심 AI에서 진짜 멀티모달 지능으로 넘어가는 중간 이정표임. 시각 데이터를 그냥 입력이 아니라 추론의 공간으로 쓰는 시도가 이제 성적표를 내기 시작한 것. 에이전트를 굴리는 사람은 결론 하나만 가져가면 됨. 텍스트 변환이 병목인 작업이 있다면, 그건 프롬프트를 다들 문제가 아니라 추론 매체를 잘못 고른 문제일 수 있음.
