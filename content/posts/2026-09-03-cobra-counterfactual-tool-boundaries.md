에이전트가 검색이나 API를 붙이면 생기는 비용 문제는 흔함. 불필요한 호출은 지연과 비용, 검색 노이즈를 만들고 오호출은 관련 없는 증거가 맞는 내부 지식을 덮어쓰는 오류 전파를 일으킴. 반대로 미호출은 최신 정보나 롱테일 사실에서 정확도를 떨어뜨림. [CoBRA](https://arxiv.org/abs/2609.00967)는 이 판단을 질문 난이도 같은 절대 신호 대신 질문별 반사실(counterfactual)로 바꿈. 도구를 부르면 이 질문에서 실제로 이득인지를 측정해서 학습하는 것. 실무적으로 바로 와닿는 부분이 많아 정리함.

1. 기존 adaptive retrieval의 문제의식이 좋음. 난이도, 자기 확신, 최종 보상 같은 절대 신호로 트리거하는데 어려운 질문이 도구 이득이 큰 질문은 아니고 자신 있는 모델도 오래되거나 롱테일 사실에서는 틀림. 저자들이 보여준 분포가 설득력 있음. 같은 베이스로 내부 전문가(도구 없음)와 외부 전문가(도구 필수)를 만들어 각 벤치마크를 풀게 하니 TriviaQA(상식 퀴즈형 질의응답 벤치마크)는 외부 우위 36.1%, 2WikiMultiHop(위키피디아 문서 여러 개를 건너야 답하는 다중홉 질의응답 벤치마크)는 내부 우위 42.3%로 갈림. 벤치마크 이름만으로 라우팅하면 안 되고 질문 단위로 판단해야 한다는 근거임.

![파이프라인](/images/2026-09-03-cobra-counterfactual-tool-boundaries/fig-2-p3.png)

2. 방법은 두 단계임. 먼저 반사실 경계 발견. 같은 질문에 내부/외부 전문가를 돌려서 페어드 롤아웃을 만들고 같은 유틸리티 함수로 채점해서 보상 차이(마진 Δ)를 계산하고, Δ와 임계값으로 내부 우위/외부 우위/모호 3분할함. 다음 경계 인식 정책 최적화. 마진이 명확한 샘플만으로 콜드스타트 SFT를 하고, 모호한 질문마다 내부/외부 두 롤아웃을 강제로 만들어서 보상 차이를 대칭적 마진 어드밴티지로 주입하는 MARS-RL을 돌림. 라우팅 레이블을 사람이 만들지 않고 같은 모델의 페어드 롤아웃에서 뽑는다는 게 아이디어의 핵심임.

3. 결과. Qwen3-4B, Wikipedia 검색 기준으로 인도메인 jEM(이 논문이 쓰는 정답 정확도 지표) 0.5883로 Search-R1-3B(검색 도구를 쓰도록 RL로 훈련한 대표적인 검색 에이전트 방법, 0.5466)를 앞서면서 도구 호출은 1.355회로 20.1% 적게 사용. OOD에서도 jEM 0.5416, 호출 0.997회로 성능·비용 모두 우위. 유틸리티(jEM − 0.10×호출)도 인도메인 +0.0759, OOD +0.0866 높음. 성능 향상이 "무조건 검색 더 하기"에서 오는 게 아니라는 것.

![주요 결과](/images/2026-09-03-cobra-counterfactual-tool-boundaries/table-2-p7.png)

4. 경계 평가가 이 논문의 진짜 주제임. 도구 없이 풀리는 문제에서의 오호출이 CoBRA 16.4%인데 ReAct은 67.3%, Search-R1은 99.9%. 도구가 필요한 문제에서의 미호출은 CoBRA 1.2%인데 베이스+라우터는 82.2%. 모호한 경계 문제에서도 jEM 0.9658로 Search-R1보다 +6.14pp 높으면서 호출 수는 더 적음. 오호출과 미호출을 따로 측정해야 도구 정책을 제대로 평가할 수 있다는 것. 나도 검색 도입 여부를 결정할 때 "평균 성능"만 봤지 이 두 지표를 본 적이 없었다는 게 반성 지점임.

5. Vanilla GRPO의 붕괴도 informative함. 최종 정답 보상만으로 학습하면 도구를 아예 안 쓰는 쪽으로 붕괴함(#Tool 0.000, jEM 0.3345). 라우팅은 최종 보상으로 안 배워지고 브랜치별 반사실 어드밴티지가 필요하다는 것. ablation에서도 롤아웃 분할만 넣으면 도구 사용이 0에 수렴해서 실패하고 브랜치 마진이 같이 들어가야 하며, 콜드스타트 SFT 유무가 9.5~16.5pp 차이를 만듦. 명확한 마진 샘플로 사전지식을 먼저 잡아주는 게 반사실 RL의 전제조건이라는 것.

![경계 행동 분석](/images/2026-09-03-cobra-counterfactual-tool-boundaries/table-3-p7.png)

6. 실무 도메인 검증도 있음. Tencent 음악 프로덕션 에이전트에 적용해서 혼합 보상 2.428→2.680 상승, 도구 호출률 39.3%→25.1% 안정, 사실성 0.997 유지. 품질은 올리고 호출은 줄였다는 것.

7. 한계와 적용 범위. Qwen3-4B 단일 모델에 검색 도구 하나 검증이고, 반사실 마진이 페어드 롤아웃 품질과 스코어러 신뢰도에 의존하며, 도구 비용을 호출 횟수로만 모델링함. 호출당 비용이 천차만별인 멀티도구 환경으로 확장하려면 유틸리티 함수 설계부터 다시 해야 함. 그래도 페어드 롤아웃으로 라우팅 레이블을 뽑는 아이디어는 검색 외에도 옮겨볼 만함. 내 적용은 이것임. 새 도구를 하네스에 붙일 때 도구 있이/없이 같은 작업 배치를 돌려서 마진을 측정하고, 마진이 명확한 경우에만 채택하고 오호출·미호출을 별도 지표로 추적하는 것. 도구는 많을수록 좋은 게 아니라 이득이 양수인 곳에만 있어야 한다는 걸 숫자로 확인한 논문임.
