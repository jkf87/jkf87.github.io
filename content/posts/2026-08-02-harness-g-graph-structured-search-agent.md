RL로 훈련된 검색 에이전트가 함정에 빌 때가 있음. 쿼리 문자열은 수십 가지로 다양하게 만드는데 실제로 검색되는 문서 집합은 거의 동일해짐. 표면적 쿼리 다양성이 진짜 검색 다양성으로 이어지지 않는 것임. Harness-G는 이 문제의 원인이 보상이 아니라 검색 인터페이스 설계 자체라고 진단하고 액션 공간을 통째로 바꿨음.

1. 이 현상의 이름이 retrieval-equivalence collapse임. GRPO(같은 프롬프트에서 뽑은 여러 응답을 그룹으로 묶어 상대 비교로 학습하는 강화학습 알고리즘) 같은 그룹 상대 최적화에서 치명적임. 같은 증거를 가져온 궤적들은 같은 정답을 내고 같은 보상을 받아서 군집 내 어드밴티지가 0으로 수렴함. 에이전트는 다양한 시도를 한다고 착각하지만 실제로는 하나의 검색 경로를 반복하는 것임.

![retrieval-equivalence collapse](/images/2026-08-02-harness-g-graph-structured-search-agent/fig-1-p1.png)

2. 자유 쿼리 인터페이스의 구조적 문제는 둘임. 첫째, 문자열-투-검색 다대일 매핑. "Who founded OpenAI?"와 "OpenAI founder"는 다른 문자열인데 같은 문서를 검색함. LLM은 표면적으로 다르고 의미적으로 동등한 쿼리를 쉽게 양산함. 둘째, 크레딧 할당 모호성. 같은 증거를 검색한 두 궤적의 점수 차이는 검색 품질이 아니라 downstream 추론에서 온 건데 GRPO가 검색 액션 탓으로 돌림.

3. 그래서 검색을 메뉴 탐색으로 재정의함. 코퍼스를 단락-문장-개체 삼분 그래프로 프로그램적으로 구축함. 문장 분할, 개체 인식·정규화, 밀집 인코딩만으로 LLM 없이 완성돼서 Graph-R1과 달리 API 비용이 0임.

4. 정책은 세 액션만 고름. Select(s)는 가시 문장을 확정 증거로 채택. Lookup(e)는 개체에 대한 추가 검색인데, 쿼리를 정책이 아니라 환경이 결정론적으로 생성·실행함. 그래서 두 개의 다른 Lookup은 정의상 다른 대상을 추구함. Answer는 확정 증거에서 답변 생성. 메뉴는 매 스텝 재구성돼서 확정 문장과 중복 검색이 제거되고 방문한 개체가 사라짐.

![인터페이스 재설계](/images/2026-08-02-harness-g-graph-structured-search-agent/fig-2-p2.png)

5. 이 설계의 구조적 보장 세 개가 중요함. 유한성은 메뉴 크기가 캡으로 bounded됨. 검증 가능성은 모든 액션이 명시적 타입과 대상을 가져서 잘못된 액션이 사후 처벌이 아니라 feasible set에서 원천 차단됨. 미리보기 가능성은 전환이 결정론적 인덱스 연산이라 어떤 액션의 결과도 상태 변경 없이 읽기 전용으로 확인 가능함.

6. 미리보기 가능성이 크레딧 설계를 가능하게 함. Structured Non-myopic Credit의 첫 항은 frontier-relative advantage임. frozen answerer가 현재 증거 상태에서 정답을 얼마나 잘 내는지 점수 매기고, 각 액션의 한계 이득을 같은 상태의 대안들 평균에서 빼줌.

7. 이 비교가 함의하는 바. 여러 메뉴 항목이 동등한 증거를 가져오면 이득이 비슷해서 어드밴티지가 0에 가까움. 표면적 선택으론 보상을 못 받고 다른 대안보다 진짜로 나은 선택을 해야만 양수 크레딧을 받음. 이 계산은 자유 형식 문자열 공간에서는 불가능했다는 게 포인트임.

8. 두 번째 항은 structured enablement credit임. 브릿지 개체를 발견하는 Select는 그 자체로 정답 확률을 안 올리지만 그 개체의 Lookup이 결정적 증거를 가져옴. SNC는 이 연쇄를 provenance edge로 추적해서 downstream 이득을 가능하게 한 이전 액션으로 전파함. 외부 보상 모델 없이 환경 내부 연산만으로 계산됨.

![전체 파이프라인](/images/2026-08-02-harness-g-graph-structured-search-agent/fig-3-p4.png)

9. 결과. 6개 QA 벤치마크에서 Qwen2.5-1.5B 기준 Graph-R1 대비 평균 F1 +10.74점. Bamboogle 71.04 vs 46.46, MuSiQue(위키피디아 여러 문서를 건너건너 찾아야 답이 나오는 멀티홉 질의응답 벤치마크) 34.50 vs 21.80. 3B에서도 +3.98점. 백본과 RL 알고리즘(GRPO, PPO, REINFORCE++, DAPO)을 바꿔도 붕괴 없이 안정적임.

10. 제일 중요한 통제 실험은 이거임. 동일한 환경 전환과 동일한 feasible 액션을 유지하고, 정책이 메뉴에서 직접 고르는지 같은 대상에 도달하려고 쿼리를 생성하는지만 바꿈. 메뉴 선택은 다중 검색 동치 클래스를 유지하고 자유 쿼리는 빠르게 단일 동치 클래스로 붕괴함. 유효한 탐험이 보상 신호만이 아니라 인터페이스 설계에 의존한다는 증거임.

11. 효율도 역설적임. 훈련 후반에 Harness-G가 더 많은 턴(3.6 vs 2.3)을 쓰면서도 더 짧은 응답(2.5k vs 4.3k 토큰)을 유지함. 구조적 탐색은 상호작용 빈도를 늘리되 자연어 생성 비용을 줄임. SNC 오버헤드는 스텝당 9~11%, 전체 3B 훈련에 약 170 GPU시간임.

12. 크로스 데이터셋 일반화도 확인됨. 6개 중 하나로 훈련하고 5개에서 평가하니 30개 조합 중 21개 승리, 평균 O.O.D. F1 44.10→47.38. 멀티홉 타겟에서 개선이 특히 컸음.

13. 실무 채점. 이 논문의 원칙은 검색 에이전트 훈련 밖에서도 유효함. 정책의 액션 공간이 aliased되어 있으면 아무리 좋은 보상을 줘도 정책이 진짜 대안을 구별 못 함. 도구 인터페이스를 설계할 때 "자유 입력" 대신 "유한 메뉴 선택 + 환경이 실행"을 고려할 것. 그리고 동치 붕괴 진단은 우리 파이프라인의 탐색 로그에서 검색 결과 집합 중복륭로 바로 측정 가능함.

14. 한계. 텍스트 전용이라 멀티모달 증거 확장은 과제고, 그래프 구축 품질(개체 정규화, 문장 분할)이 전체 성능 상한을 결정함.

15. 그래도 결론은 남음. 액션 공간 설계가 보상 설계와 동등한 축이라는 걸 실험으로 입증했다는 것. "더 나은 보상"만 쫓던 에이전트 RL 연구에 "정책이 보는 액션의 형태 자체"라는 새 축을 추가한 논문임.
