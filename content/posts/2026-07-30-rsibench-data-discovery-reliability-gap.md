LLM 에이전트가 자기 개선 루프를 돌릴 수 있으면 그 루프는 믿을 수 있는가. [RSIBench-Data](https://arxiv.org/abs/2607.25886)가 이 질문에 통제된 실험으로 답을 함. 결과가 양면적임. 에이전트는 58.33% 설정에서 첫 시도를 피드백 루프로 개선하지만, 피크에 도달한 뒤 계속 탐색하면 78.26%가 오히려 더 낮은 시도로 끝남. 발견은 하되 신뢰하지는 못한다는 것. 나도 매일 프롬프트와 스킬을 반복 개선하는 입장이라 이 숫자가 남의 일 같지 않아 정리함.

1. 설계가 깔끔함. 기존 벤치마크는 포스트트레이닝 스택 전체를 열어줘서 점수 향상이 데이터 전략 때문인지 하이퍼파라미터 때문인지 서빙 최적화 때문인지 구분이 안 됐음. RSIBench-Data는 베이스 모델(Qwen3.5-35B-A3B-Base), LoRA SFT 훈련(Tinker) — LoRA는 사전학습 모델 전체를 고정하고 소수의 저순위 어댑터 가중치만 추가 훈련하는 방식, SFT는 사람이 만든 정답 예시로 모델을 지도 미세조정하는 것임 — , 평가(Harbor-E2B 샌드박스), 예산(16시간, $500)을 전부 고정하고 에이전트가 제어할 수 있는 유일한 변수를 훈련 데이터 전략로 한정함. 데이터 소스 선택, 태스크 구성, 궤적 표현, 필터링, 난이도 커리큘럼, 데이터 믹스만 에이전트 손에 들어감. 성능 차이가 전부 데이터 정책으로 귀속되는 구조임.

![RSIBench-Data 파이프라인](/images/2026-07-30-rsibench-data-discovery-reliability-gap/fig-2-p5.png)

2. 이 통제 설계 자체가 실무 교훈임. "에이전트가 개선시켰다"는 주장을 검증하려면 바꾼 변수가 하나뿐인 환경이 필요함. 내 에이전트 개선 작업도 마찬가지임. 프롬프트, 모델, 도구, 워크플로우를 동시에 바꾸면 무엇이 효과를 냈는지 영원히 모름. 한 번에 하나만 움직이는 통제가 없는 개선은 이야기일 뿐임.

3. 실험은 Claude Code(Opus-4.8, Sonnet-5)와 Codex(gpt-5.6-sol, terra) 네 에이전트 × SWE-bench Verified/Multilingual/Pro(실제 GitHub 저장소 이슈를 고치는 코딩 벤치마크와 그 검증·다국어·고난도 확장판), Terminal-Bench 2.0, GPQA Diamond(전문가 수준 과학 객관식 벤치마크), AIME 2026(수학 경시 문제 벤치마크) 여섯 벤치마크임. 결과부터. 어떤 에이전트도 전 벤치마크에서 일관되게 1위하지 못함. Codex gpt-5.6-sol이 4개에서 선두인데 3개 SWE 벤치마크는 각각 다른 에이전트가 이김. 범용 리서처 에이전트는 아직 없고, 태스크 패밀리와 에이전트 정책의 상호작용이 순위를 정함.

4. 핵심 발견의 재해석. 58.33% 설정에서 피드백 루프가 첫 시도를 개선함. 즉 발견 능력은 있음. 근데 피크 도달 후 계속 탐색한 23개 설정 중 18개(78.26%)가 더 낮은 시도로 종료됐고 나머지 5개도 피크 회복 못 함. 피크 이후 개선한 사례는 단 한 건도 없었음. 발견 능력과 발견을 축적하는 능력이 독립적인 기술이라는 뜻임. AIME에서는 8번의 시도가 15% 이하에 머물다가 9번째에 55%로 급등하는 불연속 도약도 나옴. 개선은 점진이 아니라 전략 전환으로 옴.

![점수 궤적](/images/2026-07-30-rsibench-data-discovery-reliability-gap/fig-3-p9.png)

5. 이건 내 프롬프트 개선 경험과 정확히 같은 패턴임. 좋은 버전을 찾은 뒤 "더 좋게" 계속 만지다가 원래 성능을 깨먹는 것. 그래서 정답은 탐색을 안 하는 게 아니라 **정지 규칙과 체크포인트 보존**임. historical-best를 선택 규칙으로 두면 퇴보는 막을 수 있는데, 실제 런에서는 피크 이후에 수십~수백 달러가 추가로 낭비됐음. "언제 멈추는가"가 데이터 연구의 숨겨진 핵심 결정이라는 게 이 논문의 데이터가 보여주는 것.

6. 비용 데이터도 실무적임. 중위 유효 후보당 비용은 $62.51인데 분산이 $4.80~$363.77로 극심함. Codex gpt-5.6-terra는 GPQA에서 1.14시간 $4.80으로 64%에 도달한 반면, Claude Code Sonnet-5는 Terminal-Bench에서 8.87시간 $156.93을 쓰고 5.62%에 그침. 비싼 게 반드시 좋은 게 아니고, 같은 벤치마크에서도 피크 이후 추가 지출이 프론티어를 갱신 못 하는 경우가 흔함. 최적화 예산은 "얼마를 쓸까"보다 "어디서 끊을까"가 먼저임.

![비용 대비 점수](/images/2026-07-30-rsibench-data-discovery-reliability-gap/fig-4-p10.png)

7. 성공과 실패를 가른 메커니즘 네 가지가 나옴. 정확한 가설(타겟 모델의 실제 약점을 맞게 진단), 검증 기반 감독(실행 가능한 검증 신호로 데이터 구성), 행동 정렬 데이터(평가가 요구하는 행동과 훈련 데이터의 행동 일치), 강한 체크포인트 보존. 그중 행동 정렬 사례가 인상적임. 패치는 맞는데 합성 "완료" 액션으로 종료를 가르쳐서 7%로 퇴보했고, 실제 성공 궤적에서 추출한 제출 행동을 가르치니 9%로 올라감. 뭐가 맞는지 아는 것과 그걸 점수로 연결되는 행동으로 가르치는 건 다른 일이라는 것.

8. 탐색적 실험 하나가 뼈아픔. Kimi K2.6이 Kimi K2.6을 개선하려는 동일 모델군 RSI였는데, RSI는 재귀적 자기개선(recursive self-improvement)을 뜻함. 전략은 8% → 22%까지 진화했지만 모든 체크포인트가 미적응 기준선 33% 아래에 머물렀음. 즉 현재 에이전트의 자기개선 능력으로는 이미 잘하는 모델을 더 좋게 만드는 분포를 발견하지 못함. 데이터 파이프라인 개선이 점수를 올릴 수는 있어도 원점을 넘는 진짜 개선은 훨씬 어려움. "궤적이 오른다"와 "원점을 넘는다"는 다른 기준이라는 것.

9. 내가 가져갈 것 세 개. 첫째, 개선 루프에 historical-best 보존과 정지 규칙을 코드로 못 박을 것. 감에 의존한 "한 번만 더"가 통계적으로는 78% 확률로 퇴보임. 둘째, 개선 검증은 한 번에 한 변수만 움직이는 통제 환경에서 할 것. 셋째, 개선이 점수로 연결되는 행동까지 확인할 것. 알맞은 답을 만드는 것과 그 답을 내는 행동을 가르치는 건 다른 단계임. 발견의 시대는 끝났고 보존의 시대가 필요하다는 게 이 논문의 결론임.
