에이전트 RL을 돌리면 매 스텝 (현재 상태, 행동, 다음 상태) 튜플이 공짜로 쌓임. 근데 기존 agentic RL은 보상 신호만 쓰고 이 데이터는 버림. TAPO는 이걸 재활용함. 다음 상태를 예측하는 전이 감독을 정책 최적화와 교대로 넣는 것만으로 추가 환경 상호작용 없이 성능이 일관되게 오름. 이론적 근거도 있음. 목표 지향적 다중 스텝 과제에서 일반화하려면 에이전트가 환경의 전이 역학을 암묵적으로 모델링해야 한다는 게 UNREAL, SPR 등의 연구 결론인데, 기존 방법은 이걸 명시적으로 훈련하지 않았던 것.

![TAPO와 표준 agentic RL의 비교. 표준 RL은 보상 신호만 사용하고, TAPO는 전이 감독을 추가로 활용한다.](/images/2026-08-04-tapo-transition-aware-policy-optimization/fig-1-p2.png)

1. 방법이 소박해서 좋음. 롤아웃에서 얻은 각 스텝의 전이 (s_t, a_t) → s_{t+1}에 대해 다음 관측 토큰 시퀀스를 teacher-forcing(정답 토큰을 입력으로 주고 다음 토큰을 맞히게 하는 훈련 기법)으로 예측하는 조건부 로그 가능도 손실을 최대화함. 정책 최적화와 백본 파라미터를 공유해서 별도 모듈이 없음. 환경 상호작용 추가도, 전문가 데이터도, 추론 시간 오버헤드도 없음. 있는 데이터에 손실 하나를 추가로 태우는 구조임.

2. 교대 방식이 핵심 설계임. 정책 최적화 I회마다 전이 감독 1회를 수행함. I=4가 기본이고 2~5 범위에서 안정적임. 두 목적을 동시에 섞지 않고 번갈아 하는 이유는 그래디언트 간섭을 피하기 위해서로 보임. 하이퍼파라미터 민감도도 낮아서 튜닝 부담이 작음. 기존 파이프라인에 "4스텝마다 전이 손실 한 번"을 끼워 넣는 수준의 변경이라 도입 비용이 거의 없음.

![TAPO의 전체 구조. 에이전트가 환경과 상호작용한 뒤, 롤아웃 데이터로 정책 학습과 전이 감독을 번갈아 수행한다.](/images/2026-08-04-tapo-transition-aware-policy-optimization/fig-2-p6.png)

3. 결과가 모든 축에서 일관됨. WebShop(가상 쇼핑몰에서 요구에 맞는 상품을 검색해 구매하는 에이전트 벤치마크)에서 Qwen2.5-1.5B GRPO(같은 문제의 여러 롤아웃을 비교해 상대적으로 나은 행동을 강화하는 강화학습 알고리즘) 56.8% → TAPO-GRPO 66.2%, GiGPO(궤적 그룹 안에 스텝 그룹을 둬서 스텝별 크레딧을 주는 GRPO 변형) 67.4% → 71.7%. 7B도 66.1% → 73.7%, 75.2% → 77.9%로 오름. ALFWorld(텍스트로 조작하는 가상 가정집에서 일상 과제를 수행하는 에이전트 벤치마크)에서 7B TAPO-GiGPO가 93.6%로 Early Experience(82.8%), RWML(90.1%)을 넘음. 모델 스케일 두 개, RL 알고리즘 두 개, 환경 두 개에서 전부 향상. 특정 조합에서만 터지는 트릭이 아니라는 뜻임.

![WebShop과 ALFWorld에서의 메인 결과](/images/2026-08-04-tapo-transition-aware-policy-optimization/table-1-p6.png)

4. 왜 되는지도 측정으로 확인함. next-state perplexity(다음 상태를 예측할 때 모델의 확신 정도를 나타내는 값, 낮을수록 정확히 예측한다는 뜻)를 보면 GRPO만 훈련한 모델은 환경이 어떻게 바뀔지 예측을 못 하는데 TAPO는 행동 결과를 정확히 예측함. 성능 향상이 세계 모델링 능력 향상과 연결돼 있다는 것. 앞서 본 다크 룸 논문에서는 prediction reward를 보상 채널에 넣으면 붕괴했음. TAPO는 같은 예측 신호를 손실 채널로 넣어서 성과를 냄. "밀집 신호는 보상이 아니라 손실로"라는 원칙의 독립적 재확인이라서 신뢰가 더 감.

5. 근데 도메인 외 영향은 관찰해야 함. GSM8K(초등 수준 수학 문제 벤치마크)에서 base 59.1% → GRPO 57.9% → TAPO-GRPO 56.5%로 하락이 조금 커짐. 전이 감독이 특정 환경의 역학에 모델을 더 붙잡아두는 부작용 가능성. agentic RL 자체가 도메인 외 능력을 깎는 경향이 이미 알려져 있어서 TAPO만의 문제로 단정하긴 어렵지만 운영 시 수학·추론 벤치마크를 함께 추적할 가치가 있음.

6. 내 실무 결론은 이렇게임. 첫째, 에이전트 RL을 돌린다면 롤아웃의 전이 튜플로 TAPO식 교대 감독을 실험해볼 것. 구현 난이도 대비 기대 수익이 큼. 둘째, 밀집 예측 신호는 절대 보상에 넣지 말 것. 손실 채널로 보낼 것. 두 논문이 같은 결론을 독립적으로 냄. 셋째, 환경 두 개(WebShop, ALFWorld) 검증이라는 한계는 인지하고 자기 도메인에서 소규모 검증 후 도입할 것. 넷째, 교대 주기는 4로 시작하고 2~5에서 흔들어볼 것.
